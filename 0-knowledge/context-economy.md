# Context Economy

> 一句話：AI 的 Context 是有限且有成本的工作資源，應根據任務需要載入資訊，而不是把「知道更多」當成永遠更好。

## 核心原理

Context Economy（上下文經濟）不是單純追求「少讀文件」，而是在資訊完整度、理解準確度與 Context 成本之間取得合理平衡。

基本原則：

```text
任務需求
  ↓
判斷必要資訊
  ↓
先讀最相關內容
  ↓
發現缺口再擴大
  ↓
必要時完整稽核
```

「能讀全部」與「每次都應該讀全部」是兩個不同命題。

## 適用情境

- AI 接手大型或持續成長的 repository。
- 長期專案包含大量歷史對話與文件時。
- 同時存在核心規則、知識、專案資料與歷史資料時。
- 需要在完整理解與回應成本之間取捨時。

## 不適用情境

- 需要完整稽核、遷移或安全檢查時，不能為節省 Context 而省略必要文件。
- 文件量很小且完整閱讀本身成本很低時，不必為了節省 Context 建立複雜載入機制。

## 實務方法／注意事項

優先採取兩種模式：

**任務導向閱讀**：根據當前問題讀取相關文件，遇到證據不足再擴大。

**完整稽核閱讀**：需要確認 repository 全貌時，直接讀取全部相關文字文件。

不要建立複雜的多層 Context Loading 系統來處理尚未出現的規模問題。真正出現「找不到」「載入過慢」「重複閱讀造成明顯成本」等問題後，再尋找最小解法。

## 參考資料

- 使用者過往 AI 交接、知識庫與長期專案 Context 管理討論。

## 我的補充

Context 管理的目的不是讓 AI 永遠只看摘要，而是避免摘要本身變成新的資訊瓶頸。當完整文件可以直接取得時，應優先保留原始文件的可讀性，而不是為了 AI 建立大量中間索引層。
