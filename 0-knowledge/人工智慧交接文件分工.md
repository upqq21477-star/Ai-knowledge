# 人工智慧交接文件分工

> 一句話：長期人工智慧專案需要把「如何操作」「目前是什麼」「過去為什麼這樣決定」分開，避免新人工智慧把不同性質的資訊混成同一套規則。

## 核心原理

人工智慧交接不是單純摘要，而是讓下一個人工智慧快速恢復正確工作狀態的控制資訊。

不同文件回答不同問題：

```text
說明
→ 這個資料庫是什麼？從哪裡開始？

規則
→ 現在應該怎麼操作？

交接資料
→ 目前狀態是什麼？有哪些重要歷史決策與轉折？

正式內容
→ 真正保存了哪些知識、系統與應用？
```

文件分工的目的不是增加文件數量，而是避免一份文件同時承擔互相衝突的責任。

## 適用情境

多個人工智慧輪流接手同一個長期專案；專案歷史很長；架構曾經反覆修改；需要讓不同人工智慧依同一套現行規則工作時。

## 不適用情境

一次性短任務，不存在交接問題時；文件數量極少且沒有歷史決策與長期狀態時，不需要建立完整交接體系。

## 實務方法／注意事項

交接資料應保留會影響下一次決策的重要背景，例如當前狀態、已確立的架構邊界、重要設計轉折、已否決或暫緩方向及其原因、下一步真正應做的工作。

但交接資料不應複製整個知識庫，也不應取代正式規則。如果交接資料與正式操作規則衝突，應由規則文件取得操作優先權。

## 參考資料

- 使用者過往人工智慧交接文件、審核與知識庫設計討論。

## 我的補充

真正有效的交接文件不是把所有東西塞進去，而是防止下一個人工智慧在沒有前情時犯已經犯過的錯，同時讓它知道哪些內容必須回到正式文件確認。
