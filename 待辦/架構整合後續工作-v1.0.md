## 二、知識書原子化方向【已確認方向，待正式規格化】

原則：

> 知識書保持語義原子化、結構簡潔、低耦合與長期穩定；搜尋、分類、索引、關係、版本、狀態、遷移、驗證與 Context 管理等複雜性由上層系統承擔。

- [ ] 定義「知識書最小不可變核心」
- [ ] 確認知識內容與治理 Metadata 的邊界
- [ ] 確認哪些資訊不應直接寫入知識書
- [ ] 確認知識內容變更與系統格式變更的邊界
- [ ] 實際案例驗證知識書是否能跨系統版本保持穩定

注意：目前不提前制定完整 Schema，不提前細化大型 Metadata，不提前建立複雜索引。

## 三、圖書館式知識管理方案【候選，先定義範圍，不製作】

暫定定位：

> 以圖書館（Library）管理思想建立知識目錄、索引、集合與檢索管理能力，使大量原子知識能被有效定位、取用與組裝；知識書本身不承擔整個管理系統的複雜度。

暫定能力範圍：

- 知識目錄（Catalog）
- 知識分類與集合管理
- 知識索引（Index）
- 知識定位與檢索輔助
- Context 取用前的候選知識篩選
- 大量知識的分層管理
- 歷史／現行資料的區分
- 後續大型資料重製後的新索引建立

目前不做：

- 不建立完整實作
- 不制定詳細 Schema
- 不決定資料庫／向量資料庫／知識圖譜
- 不提前建立複雜搜尋演算法
- 不把圖書館管理能力獨立升格為第四個正式方案
- 不與既有搜尋研究方案重複定義

正式製作前置條件：

```text
新系統規格確認
↓
交接資訊確認
↓
共同資料語義確認
↓
共同版本模型確認
↓
資料格式唯一性確認
↓
跨方案接口確認
↓
實際案例驗證
↓
再製作圖書館式知識管理方案／系統能力
```

## 四、大型整體更新【新增正式待辦方向】

當共同版本模型成熟後，建立大型整體更新規則：

```text
建立新一代完整格式
↓
全量資料轉換／重製
↓
語義與完整性驗證
↓
新格式正式切換
↓
舊格式退出現行資料體系
↓
舊資料僅保留歷史／Migration Source／Regression Test用途
```

核心原則：

> 不追求永久保留多代現行格式；每一代現行資料應只有一套正式格式。

## 六、禁止提前做的事情

- 不因圖書館概念立即建立完整系統
- 不在共同版本模型完成前制定其專屬版本格式
- 不在共同資料格式確認前制定其專屬 Metadata
- 不在實際使用證明需要前導入資料庫、向量資料庫或知識圖譜
- 不讓新方案重複搜尋研究方案、AI 知識管理方案或資料演化方案的既有責任
- 不修改舊架構文件以配合尚未完成的新設計

## 七、判定原則

圖書館式知識管理能力只有在共同資料與版本規格穩定後才進入正式製作，原因是其 Catalog、Index、集合與檢索管理都依賴上層資料語義與版本契約。

先做它會造成：

```text
資料格式改變
→ Catalog 重做
→ Index 重做
→ 方案責任重做
→ 接口重做
```

因此目前只確認功能範圍與邊界，不進入精細設計。
