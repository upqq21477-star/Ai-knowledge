# 統御分支方案：架構與施工規劃 v1.1

日期：2026-09-17
狀態：【建立中；架構已調整；功能已收斂；待最終既有能力比對與實際驗證】

## 一、架構定位

統御分支不是中央執行引擎，而是橫向的「系統可發現性＋啟動保險」能力。

核心由兩個薄型系統構成：

```text
系統目錄／身份管理
+
啟動保險／觸發管理
```

## 二、正常路徑與保險路徑

```text
【正常路徑】
工作流程
↓
專責系統
↓
執行

【保險路徑】
工作流程／事件
↓
可能漏啟動
↓
Trigger Registry
↓
System ID
↓
檢查目前處理狀態
↓
未處理 → 補充啟動
已處理／執行中 → 不重啟
不確定 → 停止擴大並轉交判定
```

## 三、資料關係

```text
Trigger ID
   ↓
System ID
   ↓
System Catalog
   ├─ 系統名稱
   ├─ 位置
   ├─ 狀態
   ├─ 方案
   ├─ 功能
   └─ 關聯知識
```

Trigger Registry 不建立 System Catalog 的第二份正式資料來源。

## 四、啟動保險最小判斷

```text
事件
↓
匹配
↓
0 → 不啟動
1 → 查 System ID 狀態
>1 → 歧義，不自動全部啟動
↓
已處理／執行中 → 不重啟
未處理 → 補充啟動
不確定 → 轉交判定
```

## 五、安全機制

必須具備：

- Event ID／處理關聯。
- 防二次啟動。
- 基本冪等性。
- 基本循環觸發防護。
- 多重匹配歧義標記。
- 失效目標阻擋。

## 六、施工順序

```text
架構調整
↓
功能需求收斂
↓
既有 repository 能力逐項比對
↓
確認真正新增缺口
↓
外部方法再檢查
↓
知識書完成
↓
方案規則確認
↓
系統規則確認
↓
自然工作最小驗證
↓
實測結果回寫
```

## 七、停止條件

若發現既有系統已完整提供某項能力，不因本方案列出該功能就建立第二套系統。

若新需求需要完整事件匯流排、規則引擎或工作流引擎，必須重新進入問題解決與外部研究流程，不得在本方案內直接擴張。

## 八、規模策略

初期不按數量預先切割資料。

優先使用：

```text
單一 System Catalog
+
單一 Trigger Registry
+
搜尋／篩選
```

只有實際出現責任、生命週期、同步或維護成本分化，才考慮分流。

## 九、驗證

第一批自然案例優先確認：

1. 正常啟動不被保險層重複啟動。
2. 漏啟動可以被補充。
3. 重複事件不造成重複處理。
4. 多重匹配不造成無條件群體啟動。
5. 執行後狀態變更不造成循環。
