# 統御分支方案：功能需求分析 v1.1

日期：2026-09-17
狀態：【建立中；觸發功能已收斂；待既有能力最終比對與自然案例驗證】

## 一、調整原則

本版依「觸發系統只是第二層啟動保險」重新裁切功能。

因此不再把觸發能力視為中央事件處理、工作流編排或完整路由引擎。

## 四、降級或暫不建立的功能

以下功能不再列為第一版核心：

- 自動最佳候選選擇
- 複雜優先級計算
- 中央事件總線
- 完整 Rule Engine
- 完整 Workflow Engine
- 中央問題解決器
- 跨系統完整執行編排
- 大型事件歷史資料庫

原因：這些功能會把「啟動保險」重新膨脹成中央控制系統，與目前方案邊界衝突。

## 五、功能責任邊界

```text
System Catalog
→ 誰、在哪裡、屬於哪個方案、目前狀態

Trigger Registry
→ 哪個事件可能漏掉哪個系統

啟動保險
→ 這個系統是否已經在處理

方案／專責系統
→ 為什麼處理、如何處理、處理結果
```

## 六、最重要的安全條件

```text
Trigger 命中
↓
不是直接啟動
↓
查 System ID
↓
查目前處理狀態
↓
已處理／執行中 → 結束保險流程
未處理 → 補充啟動
不確定 → 停止擴大並轉交判定
```

## 七、與既有能力比對

目前確認本功能集合主要新增缺口不是「更多事件處理能力」，而是：

1. 統一 System ID 與 System Catalog。
2. 獨立的 Trigger Registry。
3. 啟動狀態確認與防二次啟動。
4. 事件／處理關聯，用於去重與循環防護。

問題解決、知識管理、資料演化與各專責系統仍維持原責任。
