## 五、觸發管理轉移規則

### 尚未歸屬

```text
小系統
→ 出現在本表「未歸屬小系統」
→ 顯示功能
→ 顯示觸發條件
→ 統御分支管理觸發
```

### 納入方案後

```text
小系統
→ 被正式方案納入
→ 移入該方案的系統分類
→ 統御表只保留系統／功能／狀態索引
→ 移除統御分支的觸發管理
```

### 尚未完全重疊

```text
只有部分觸發重疊
→ 不移交
→ 保留統御觸發
→ 等方案能力完整涵蓋後再移交
```

### 完全涵蓋

「完全涵蓋」必須確認觸發對象、情境、前置條件與所需結果均被方案能力承擔；不能只因兩邊文字相似就移交。

## 六、更新規則

每次發生以下事件之一，統御狀態表應重新檢查：

- 新系統建立。
- 系統狀態改變。
- 系統被納入方案。
- 小系統升格。
- 小系統整合進方案。
- 小系統廢止。
- 觸發管理權移交。

本表是狀態資料，不是歷史完整紀錄；重大變更仍應由對應系統／方案的變更記錄保存。
