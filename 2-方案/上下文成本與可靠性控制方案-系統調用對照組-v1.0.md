# 上下文成本與可靠性控制方案｜系統調用對照組

版本：v1.0
類型：方案對照組（Control Group）
目的：驗證「方案負責調動 System、System 負責調動 Knowledge」的分層寫法。

## 一、對照目標
本對照組不重新設計 C03／C04／C05，只改變責任分配與文件粒度：

- Solution：描述什麼情況調用哪個 System、System 之間如何串接、如何判定結果。
- System：描述本 System 調用哪些 Knowledge、呼叫哪些既有 System、輸入／輸出是什麼。
- Knowledge：保存原理、判定標準與研究結論。
- 不在 Solution 重複 System 的內部流程。
- 不在 System 重複 Knowledge 的完整內容。

## 二、方案核心
| 核心 | System | 主要調用時機 |
|---|---|---|
| C03 | 上下文預算與充分性測量系統 | 需要測定任務所需 Context 時 |
| C04 | 上下文可靠性測試系統 | 需要比較不同 Context 條件下可靠性時 |
| C05 | 上下文證據一致性與幻覺檢測系統 | 需要檢查輸出主張與證據一致性時 |

## 三、方案調度
需要「多少 Context」→ 調用 C03 System。
需要「Context 改變後是否仍可靠」→ 調用 C04 System。
需要「輸出是否有 unsupported／contradicted claims」→ 調用 C05 System。
需要完整 Context 可靠性閉環 → C03 → C04 → C05。
C05 結果必要時回饋 C03／C04 重新測試。

## 四、既有 System 調用
本方案直接調用：
- 研究問題、資料探索與搜尋系統：取得候選資料。
- AI知識與上下文交接系統：提供任務執行與 Context 組裝入口。
- 來源、證據與研究採用判斷系統：處理來源／證據採用判斷。
- 知識比較、更新與資料演化系統：處理結果造成的知識／狀態變更。
- 問題解決與新系統建立流程：處理失敗與必要的結構修正。

## 五、方案級輸入／輸出
輸入：任務、候選 Context、模型／測試條件、任務規則、可取得證據。
輸出：Context Profile、Reliability Profile、Claim／Evidence 判定、Context-induced Error 判定，以及是否需要調整 Context 並重新測試。

方案本身不重述上述 System 的內部測量方法。

## 六、方案驗證
只驗證：
1. 正確任務是否能調到正確 System。
2. 三個 System 是否能透過明確輸入／輸出形成閉環。
3. System 產出的結果是否能回到既有 Knowledge／System／方案演化流程。
