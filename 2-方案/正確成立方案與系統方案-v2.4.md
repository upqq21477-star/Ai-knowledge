# 正確成立方案與系統方案 v2.4

日期：2026-09-17
前版：`2-方案/正確成立方案與系統方案-v2.3.md`
狀態：【交接同步規則整合完成；待四情境失憶交接實測】

## 一、此次修正

v2.3 已定義「問題→功能→知識→知識書→研究→系統能力→方案」建立前鏈路。本版不改變該核心鏈路，只補上正式工程狀態與交接的生命週期接口。

核心原則：

> 交接只同步有意義的工程狀態轉換，不同步微步驟；施工中斷由工作檔案與 Git 恢復，不要求每次中斷都寫交接。

## 二、與工程運作方案的接口

```text
問題研究／討論
↓
正式結論
↓
建立規劃
↓
【交接更新：新工程基線】
↓
施工入口
↓
Preflight
↓
問題→功能→知識→研究→能力等建立前 Gate
↓
ALLOW
↓
正式建立／完善／驗收／實戰
↓
【重大狀態轉換 → 交接＋待辦同步】
↓
新基準
```

## 三、討論中斷與施工中斷必須分離

### 討論中斷

未形成正式結論：

```text
不形成工程狀態
→ 不更新正式交接
→ 回到前一階段
```

### 施工中斷

已產生實際工程變更：

```text
不視為不存在
→ 保留工作檔案
→ 保留 Git
→ 下一個 AI 從實際狀態恢復
```

## 四、規劃交接去重

建立規劃時一次同步：

- 規劃狀態
- 建立狀態
- 完善／驗證狀態
- 待辦
- 順序
- 依賴
- 下一個可執行工作
- 施工入口
- 交接基線

若規劃完成後立即施工，不重複寫一次相同交接；只有工程狀態產生新的重大轉換才再次同步。

## 五、正式建立前 Gate 不因交接規則而縮減

仍必須完整執行 v2.3 的：

```text
問題
→ 完整功能
→ 功能→知識
→ 知識書實查
→ 缺口
→ 外部研究／比較
→ 知識形成
→ 系統能力盤點
→ 系統／方案必要性
→ 建立規劃
→ Preflight
→ Gate
```

交接只是狀態恢復層，不取代任何建立前 Gate。

## 六、施工檔案作為第二層恢復證據

施工中主要工作檔案至少應具備：

```text
目前工作
目前階段
目前子步驟
已完成
未完成
阻塞
下一步
最後有效狀態
```

文件狀態是工程證據；交接是快速入口；Git 是變更證據。

三者不得互相取代。

## 七、失憶 AI 的恢復優先順序

```text
交接
↓
工程狀態快照
↓
目前工作檔案
↓
待辦
↓
Git
↓
必要歷史
```

若發現衝突：

```text
實際 Repository 狀態
＋
最新可確認工程紀錄
```

優先於可能過時的交接摘要。

## 八、四情境驗證要求

正式宣布本規則成立前，必須實測：

```text
A 討論中死亡
B 規劃完成後死亡
C 施工 50% 中死亡
D 施工完成但交接未同步時死亡
```

每個情境都必須確認新 AI 能：

1. 找到正確工作。
2. 判斷目前階段。
3. 不重做已完成工作。
4. 不把未完成工作誤判為完成。
5. 找到下一步。
6. 在必要時補交接，而不是製造重複交接。

## 九、LOCK / ALLOW

在四情境實測完成前：

`交接同步新規則：PENDING`

不得宣稱已完成正式驗收。

四情境均通過後才可：

`ALLOW → 建立新基準`
