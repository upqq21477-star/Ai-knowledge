# 語意壓縮與分層責任驗證方案

版本：v1.2
狀態：【候選方案；研究深化完成；待 A/B/C 實測】

## 一、方案目的

在不改變 Knowledge 與核心能力的前提下，建立 Knowledge、System、Solution 的最小充分語意，降低 Context 成本，同時維持：
- 可交接
- 可執行
- 可驗收
- 可追溯
- Evidence Grounding

## 二、標準建立流程

本方案禁止直接從問題跳到 Solution。

固定流程：

問題
→ 問題拆分
→ 功能清單
→ 功能逐項研究
→ 外部方法／工具／研究比較
→ 證據與適用性判斷
→ 建立 Knowledge
→ Knowledge 整合
→ 建立 System
→ System 最小實測
→ 建立 Solution
→ A/B/C 驗證
→ 回寫 Knowledge
→ 必要時 System／Solution 演化

## 三、層級契約

Knowledge：
原理、規則、事實、證據、判定依據。

System：
身份、功能、必要依賴、固定結果契約。

Solution：
目的、路由、邊界、組合、驗收。

核心：
> 同一語意只在真正需要它的層保存一次。

## 四、壓縮標準

### 必須保留
影響：
身份、路由、功能、依賴、結果解讀、驗收、證據追溯
的語意。

### 可移交
屬於其他層責任的語意，必須移交並明確落位。

### 可合併
可由短契約、代碼、固定結構表達。

### 可刪
不影響決策、執行、結果解讀、驗收與證據追溯的冗餘。

## 五、Evidence 優先原則

證據、來源、主張、限定條件、例外、分類邊界屬高敏感語意。

不得因追求 Token 壓縮而優先刪除。

原因：近期研究顯示答案品質可能維持，但 grounding 顯著下降，因此答案正確不能代替證據驗收。citeturn0search8turn0search0

## 六、實驗設計

### A｜完整組
完整 Solution + 完整 System + 相同 Knowledge。

### B｜分層壓縮組
壓縮 Solution + 壓縮 System + 相同 Knowledge。

### C｜過度壓縮組
刻意移除一部分不可替代語意，用於建立失真基線。

三組使用相同任務與盡量一致的測試條件。

## 七、測量項目

每組至少測：

1. Token／Context 成本
2. 路由正確
3. System 身份正確
4. 功能完成
5. 依賴正確
6. 語意失真
7. 最終答案正確
8. Grounding
9. Evidence Mapping
10. 驗收正確
11. Context-induced Error
12. 整體成功

## 八、既有實驗參考

50 次結構化模擬：

初始壓縮：
- 路由錯誤 3/50
- 語意失真 4/50
- 幻覺 1/50
- 功能完成 48/50
- 整體成功 46/50

加入 Solution 路由邊界：
- 路由 0/50
- 語意失真 1/50
- 幻覺 0/50
- 功能 49/50
- 整體 49/50

加入 Solution 驗收：
- 路由 0/50
- 語意失真 0/50
- 幻覺 0/50
- 功能 50/50
- 整體 50/50

Token 結構化估算：
完整組約 28,201／50 次；
初始壓縮約 9,177／50 次；
Solution 邊界後約 9,500／50 次。

以上僅為內部結構化模擬。

## 九、目前最優解候選

目前不採用「所有文件極限壓縮」。

採用：

> 分層壓縮 + 語意契約 + Evidence 優先保留 + 結果驗收 + A/B/C 驗證。

目標不是最高 compression ratio，而是找到：
> Minimum Sufficient Semantics。

## 十、錯誤修正

錯誤發生時：

發現
→ 定位缺失語意
→ 判定責任層
→ 補最小語意
→ 重測

禁止直接恢復完整原文。

## 十一、成功條件

1. Knowledge 仍完整提供判定依據。
2. System 仍具備核心能力。
3. Solution 仍具備正確路由與驗收。
4. 無跨層責任污染。
5. Context 成本下降。
6. 任務表現維持。
7. Grounding 與 Evidence Mapping 維持。
8. 語意失真可定位。
9. 錯誤可用最小語意修復。
10. 壓縮結果可交接。

## 十二、研究依據

Prompt Compression 研究指出長 Prompt 會增加記憶／推理成本，壓縮方法需在成本與任務效能間取得平衡。citeturn0search1

資訊保存研究進一步指出，compression ratio 之外必須評估 downstream performance、grounding 與 information preservation。citeturn0search0

Evidence-aware RAG 的 2026 研究顯示，答案正確率與 grounding 可能在壓縮後出現明顯分離，因此本方案將 Evidence Mapping 列為獨立驗收軸。citeturn0search8

Context Engineering 研究亦指出，Context 不只包含 Prompt，而包括檢索資料、歷史與工具輸出等，因此本方案將 Context 結構與來源納入驗證。citeturn0search3

## 十三、下一步

執行真正的 A/B/C 實驗：

A 完整組
B 分層壓縮組
C 過度壓縮組

每組至少 50 次。

目標不是只確認 B 比 A 短，而是找出：
- B 是否維持能力。
- B 是否維持 Evidence Grounding。
- C 從哪一個語意缺失開始產生錯誤。
- 哪些語意是 Minimum Sufficient Semantics。
