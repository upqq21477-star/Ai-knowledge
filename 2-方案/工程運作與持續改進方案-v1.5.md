# 工程運作與持續改進方案 v1.5

日期：2026-09-18  
前版：`2-方案/工程運作與持續改進方案-v1.4.md`  
問題來源：GitHub Issue #1  
狀態：【問題修正完成；模擬驗收待執行】

## 一、本次問題

v1.4 已正確取消 FIELD 作為後續工程的硬性阻塞，但仍不足以明確處理以下情況：

> 某項能力需要真實工程運作才能取得證據，但在方案完成當下沒有自然案例可以執行。

若只寫 `FIELD-PENDING`，後續容易出現三個問題：

1. 不知道什麼時候應該記錄。
2. 不知道正常使用後如何結束 pending。
3. 發生異常時不容易直接追溯到問題解決流程。

## 二、正式修正

新增「實際驗證觀察與待觸發機制」：

```text
SIMULATION-PASSED
↓
正常工程運作
↓
FIELD-PENDING
↓
等待自然觸發
↓
Observation Event
├─ NORMAL
│   → 清除 pending 標記，保留歷史
├─ ABNORMAL
│   → 保留／重新開啟 pending + 問題解決事件
└─ INCONCLUSIVE
    → 保留 pending
```

完整操作規則見：
`2-方案/完善/實際驗證觀察與待觸發機制-v1.0.md`

## 三、FIELD 的正式工程位置

FIELD 仍然不是硬 Gate。

```text
SIMULATION-PASSED
＋
FIELD-PENDING
=
可以正常工程運作
```

`FIELD-PENDING` 的意思改為更精確的：

> 尚未由自然工程使用取得足夠實際觀察證據。

它不是「尚未完成」或「禁止使用」。

## 四、自然觸發原則

只有正常工程本身需要使用該能力時，才觸發實際觀察。

禁止：

```text
沒有自然案例
↓
人工創造案例
↓
只為關閉 FIELD-PENDING
```

這種做法會把「驗證」變成形式作業，降低證據價值。

## 五、Observation Event

自然觸發後建立最小觀察記錄：

```text
Observation ID
Target Identity
Target Version
Current State
Trigger / Task
Input / Context
Operation
Expected Result
Actual Result
Evidence
Outcome
Timestamp
Related Problem / Improvement Case
```

事件中的 `FIELD-OBSERVING` 只是處理中的事件標記，不建立第二套長期生命週期。

## 六、正常結果

正常結果的工程處理：

```text
Observation
↓
NORMAL
↓
確認沒有未解決異常
↓
移除 pending 標記
↓
保留 Observation History / Traceability
↓
正常工程繼續
```

「移除 pending」不等於「永久證明」。

後續若發現新異常，仍可建立新的觀察與問題事件。

## 七、異常結果

```text
Observation
↓
ABNORMAL
↓
保留／重新開啟 pending
↓
建立 Real-World Validation / Improvement Case
↓
進入問題解決系統
↓
責任判定
↓
必要時 Scheme 3 / Scheme 4
↓
最小修正
↓
模擬回歸
↓
恢復正常工程
```

單一 FIELD 異常不自動等於方案失敗，也不自動觸發 Scheme 4。

## 八、無法判定

```text
INCONCLUSIVE
↓
保留 FIELD-PENDING
```

不可將證據不足轉換成 NORMAL。

## 九、與四方案的關係

此機制不改變四方案正式功能清單：

- 方案一：A1～A12
- 方案二：B1～B16
- 方案三：C1～C18
- 方案四：D1～D20

它是工程運作層的共同觀察機制。

## 十、目前工程狀態

四方案目前均已有模擬工程層面的驗收與回歸成果；FIELD 不應被人工製造成下一個必做批次。

目前需要做的是：

```text
盤點哪些能力確實需要自然工程使用才能取得證據
↓
建立 FIELD-PENDING 標記
↓
正常工程繼續
↓
等待自然觸發
```

如果某項能力尚未有合理的實際觸發條件，不建立虛假的 Observation。

## 十一、工程停止條件修正

工程進入正常運作的必要條件仍是：

1. 責任完整。
2. 模擬驗收通過。
3. 模擬回歸通過。
4. 沒有已確認的阻塞性結構缺口。
5. 已建立必要工程狀態與交接資料。

新增明確規則：

> 是否已經發生 FIELD 實際使用，不是進入正常工程的必要條件。

## 十二、本版結論

```text
問題已被轉化為明確的工程機制
↓
研究與外部方法比較完成
↓
採用最小解法
↓
建立待觸發觀察機制
↓
進入模擬驗收
```

本版不修改 v1.0～v1.4 歷史文件。
