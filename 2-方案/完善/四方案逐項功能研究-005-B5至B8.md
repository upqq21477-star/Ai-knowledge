## 三、外部研究總結

本批對照 W3C PROV、NIST AI Risk Management Framework、NIST《On the Evaluation of Machine-Generated Reports》、NIST 2026 Agentic AI evaluation work，以及 Anthropic 的 Contextual Retrieval、Effective Context Engineering。

共同結論是：研究型 AI 系統不能只記錄「找到什麼」，還必須區分來源、證據、主張、適用條件與實際使用上下文；Context 也不能單純追求最大資料量，而要根據任務選擇足以完成工作的高訊號資料。

整體責任鏈可表達為：

```text
B5 外部研究
↓
取得外部方法／案例／證據
↓
B6 來源／證據判斷
↓
判斷資料到底支持什麼
↓
B7 適用性判斷
↓
判斷能否用在目前任務與條件
↓
B8 最小充分上下文選擇
↓
只把目前任務真正需要的資料送入工作 Context
```

## 四、B5 外部研究 External Research

### 4.1 功能問題

當 Repository 內部資料不足以回答研究問題、比較方法或確認外部現況時，向外取得成熟方法、工具、案例、標準、論文與其他可驗證資料。

B5 的核心不是「上網搜尋」，而是「為目前任務取得 Repository 外部的必要研究證據」。

### 4.2 必要性

【必要；系統化能力】

新技術、外部工具、業界方法、標準、最新版本與外部案例都可能超出 Repository 現有知識，因此需要明確的外部研究入口。

### 4.3 邊界

```text
B3 知識搜尋
= Repository 內找已存在資料

B4 資料探索
= 在既有資料空間擴展探索

B5 外部研究
= Repository 不足時取得外部研究資料
```

既有問題解決流程已經包含「外部方法／工具／案例比較」，所以 B5 不建立第二套問題解決系統。

```text
B5
負責取得與整理外部研究資料

問題解決系統
負責確認問題、比較候選解法、最小實測與處置決定
```

### 4.4 最小模型

```text
Research Question
↓
Information Gap
↓
Search / Research Strategy
↓
External Candidates
↓
Source / Evidence Check
↓
Applicability Check
↓
Research Result
↓
Limitations / Uncertainty
↓
Decision Input
```

### 4.5 停止條件

至少考慮：關鍵資訊缺口是否覆蓋、關鍵主張是否有足夠證據、重大來源衝突、時間／版本／條件、追加搜尋的預期資訊價值，以及是否已足以交給下一責任層。

### 4.6 模擬案例

任務：判斷 Repository 現有搜尋方案是否需要增加語意搜尋。

B5 應先確認既有能力與不足，再研究外部成熟方法、案例與限制，最後把研究結果交給候選解法比較，而不是直接宣布「應該增加語意搜尋」。

【模擬結果：通過】

### 4.7 失敗案例

AI 看到某公司使用向量搜尋，就直接把向量搜尋列為本系統應採用方案。

判定：B5 失敗。取得外部案例不等於證明本系統適用，更不等於採用決策。

## 五、B6 來源／證據判斷 Source / Evidence Judgment

### 5.1 功能問題

判斷搜尋／研究取得的內容在知識鏈中的角色，以及它能支持什麼主張。

至少區分：

```text
Source
Evidence
Claim
Observation
Inference
Decision
```

### 5.2 外部研究

W3C PROV 將 provenance 用於描述產生、交付或影響資料的實體、活動與人員，支援來源理解、可信度判斷、流程驗證與重現。

NIST《On the Evaluation of Machine-Generated Reports》指出複雜報告除了完整與正確，也需要可驗證性，並要求將報告中的 claims 與 supporting source documents 建立關聯。

NIST 2026 Agentic AI evaluation work 進一步採用 structured audit trail，將 Agent 決策與支持文件連接，並分別檢查 faithfulness、completeness、sufficiency。

### 5.3 必要性

【必要；共同核心能力】

B6 是方案一 A3、A4、A10 在 AI 工作流程中的使用入口之一。因此不應重新建立另一套 provenance 語義，而應使用方案一共同語義。

### 5.4 最小模型

```text
Retrieved Item
├─ Identity
├─ Source
├─ Version / Time
├─ Claim(s)
├─ Evidence Role
├─ Direct / Indirect Support
├─ Limitations
└─ Traceability
```

### 5.5 關鍵邊界

```text
Source Quality
≠
Claim Support
≠
Applicability
≠
Decision Correctness
```

「來源可靠」不能直接推出「支持目前主張」；「證據存在」也不能直接推出「證據足夠」。

### 5.6 模擬案例

研究結果聲稱「方法 X 可以降低搜尋失敗率」。B6 至少要確認來源、原始測試內容、測試資料與條件，以及研究結果究竟支持哪個具體主張。

【模擬結果：通過】

### 5.7 失敗案例

只保存「官方文章」並把文章全部內容視為本系統已證明的事實。

判定：B6 失敗。Source 身份被錯誤等同 Evidence Sufficiency。

## 六、B7 適用性判斷 Applicability Judgment

### 6.1 功能問題

確認某份資料、證據、方法或知識是否可以用於「目前這個任務、目前這個條件」。

B7 把「它是真的／它存在」與「它現在能不能用」分開。

### 6.2 外部研究

NIST AI RMF 對 validity / reliability 強調，驗證必須針對特定 intended use 或 application；不同資料、設定與使用情境不能直接假設表現相同。NIST 也指出 context 會影響評估方式與結果。

NIST Information Quality Standards 將資訊品質與 intended use、time sensitivity、permanence、context 及成本限制連結，並要求考慮第三方資料的 limitations、assumptions、collection methods 與 uncertainties。

因此適用性不能縮減成單一「可信度分數」。

### 6.3 必要性

【必要；共同判斷能力】

若只有 B6 而沒有 B7，容易出現：

```text
來源可信
＋
證據真實
↓
錯誤地推論
↓
所以適用於現在
```

### 6.4 最小模型

```text
Candidate Knowledge
↓
Task Match
├─ Scope
├─ Time
├─ Version
├─ Environment
├─ Conditions
├─ Population / Data Context
├─ Intended Use
└─ Known Limitations
↓
Applicability Result
├─ Applicable
├─ Conditionally Applicable
├─ Reference Only
├─ Not Applicable
└─ Unknown
```

### 6.5 與 B6、B12 的邊界

```text
B6：它是什麼？它支持什麼？
B7：它能不能用在現在這個問題？
B12：產生結果後，結果是否符合要求？
```

B7 是使用前判斷；B12 是結果產生後驗證。

### 6.6 模擬案例

外部文章測試某檢索方法，但資料集與本 Repository 完全不同。

正確判斷：可以作為方法存在與可能效果的研究證據，但不能直接當成本 Repository 的實測證明；若要採用，仍需要本系統最小實測。

【模擬結果：通過】

### 6.7 失敗案例

「這是 2026 年的官方研究，所以一定適用本系統。」

判定：B7 失敗。時間新鮮度被錯誤當成任務適用性。

## 七、B8 最小充分上下文選擇 Minimum Sufficient Context Selection

### 7.1 功能問題

從已取得且判斷可用的資料中，選出完成目前任務所需的最小充分資訊集合。

不是「越少越好」，而是：

```text
足以完成任務
＋
足以避免關鍵誤判
＋
不加入大量低訊號資料
```

### 7.2 外部研究

Anthropic Contextual Retrieval 指出，增加檢索內容可能提高找到相關資料的機會，但過多資訊也可能造成干擾；chunk 數量、上下文與 reranking 應透過 eval 找到適合任務的平衡。

Anthropic Effective Context Engineering 進一步把 Context 視為有限資源，主張高訊號、精簡的 context，並使用 just-in-time retrieval、progressive disclosure、compaction 與結構化筆記管理長期任務。

因此「最小」不是固定 token 數，而是任務條件下的充分性。

### 7.3 必要性

【必要；系統化能力】

沒有 B8，搜尋／研究結果容易全部進入 Context，造成無關資訊、舊版本、不同條件證據互相干擾，以及 Context 成本增加。

### 7.4 最小模型

```text
Task
↓
Required Information
↓
Applicable Candidates
↓
Select
├─ Must Include
├─ Useful Context
├─ Optional
└─ Exclude
↓
Sufficiency Check
↓
Working Context
```

### 7.5 選擇條件

至少考慮：任務直接必要性、對關鍵決策的證據作用、前後文依賴、版本／時間一致性、衝突資料、限制與反例、更精確資料是否可取代大段資料，以及增加 Context 是否真的提高任務完成能力。

### 7.6 動態而非固定

B8 不應建立「每個任務固定 10 份文件」之類死規則。

```text
初始 Context
↓
執行／推理
↓
發現資訊缺口
↓
追加最必要資料
↓
繼續工作
```

這與 just-in-time retrieval 與 progressive disclosure 的方向一致。

### 7.7 模擬案例

任務：只判斷「A13～A16 是否存在於目前正式功能清單」。

最小充分 Context 只需要目前正式功能清單與必要批次驗證規則；若出現衝突，再載入相關研究／交接文件。

把整個 Repository 全部載入雖然可能得到答案，但不是最小充分 Context。

【模擬結果：通過】

### 7.8 失敗案例

為了回答小問題，把所有歷史文件、舊版本、所有方案與研究資料全部送入 Context。

判定：B8 失敗。資料量最大化取代了任務充分性。

↓

↓

↓
B5 外部研究
↓
外部候選
↓

↓

↓

## 九、與既有系統的處置結論

### B5

不建立新的「外部研究系統」。沿用既有搜尋研究方案與問題解決流程，補足 B5 的責任接口、研究深度與輸出契約。

### B6

不建立第二套來源／證據語義。沿用方案一的 Source、Evidence、Claim、Observation、Inference、Decision 與 Traceability，共同語義負責定義，B6 負責在 AI 任務流程中使用。

### B7

這是本批較需要補強的一項。現有來源／證據能力已有基礎，但「能否用於目前任務」涉及時間、版本、條件、範圍、環境與 intended use 的組合判斷，需要形成明確責任與輸出狀態。

### B8

沿用 AI 上下文與交接系統，不建立新的 Context 系統。需要把「最小充分」從原則提升為可操作的選擇條件與充分性檢查。

## 十、模擬驗收總結

| 功能 | 必要性 | 邊界 | 最小模型 | 典型失敗 | 模擬結果 |
|---|---|---|---|---|---|
| B5 外部研究 | 必要 | 不取代問題解決 | 研究問題→候選→證據→適用性→結果 | 外部案例直接當採用答案 | 通過 |
| B6 來源／證據判斷 | 必要／共同核心 | 不等同適用性 | Source→Claim→Evidence→Support | Source＝充分證據 | 通過 |
| B7 適用性判斷 | 必要 | 不取代結果驗證 | Task→Scope/Time/Version/Condition→Applicability | 新／權威＝必然適用 | 通過 |
| B8 最小充分上下文 | 必要 | 不取代搜尋／組裝 | Required Info→Candidates→Select→Sufficiency | 全庫載入 | 通過 |

## 十一、本批研究結論

1. B5～B8 均為必要能力。
2. 四者不應各自建立大型獨立系統。
3. B5 應嵌入既有搜尋研究與問題解決接口。
4. B6 應使用方案一共同語義，不重新定義 Source／Evidence。
5. B7 是目前最需要補足責任與條件模型的能力；「可信」與「適用」必須嚴格分離。
6. B8 應將「最小充分 Context」落實成選擇與充分性檢查，而不是固定文件數量或 token 數量。
7. B5～B8 應形成「取得 → 判斷 → 適用 → 篩選」鏈，之後才進入 B9 Context Assembly。
8. 本批模擬驗收通過，不代表長期真實運作已驗證。

## 十二、外部研究來源

- W3C PROV Model Primer / PROV Overview：provenance、來源、活動、實體與可追溯性。
- NIST《On the Evaluation of Machine-Generated Reports》：完整性、正確性與可驗證性，以及 claim-to-source 映射。
- NIST Building Evaluation Probes into Agentic AI：structured audit trail、faithfulness、completeness、sufficiency。
- NIST AI Risk Management Framework：validity、reliability 與 intended use / context。
- NIST Information Quality Standards：accuracy、reliability、context、time sensitivity、intended use 與第三方資料限制。
- Anthropic Contextual Retrieval：contextual retrieval、hybrid retrieval、reranking 與 context 數量取捨。
- Anthropic Effective Context Engineering for AI Agents：context curation、just-in-time retrieval、progressive disclosure、context as a finite resource。
