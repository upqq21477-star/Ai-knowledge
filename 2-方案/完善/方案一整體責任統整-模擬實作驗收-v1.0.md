# 方案一整體責任統整：模擬實作驗收 v1.0

日期：2026-09-18
狀態：【SIMULATION-PASSED；待模擬回歸驗證】
研究／驗收範圍：方案一「整體資料治理」A1～A12
前置條件：A1～A12 逐項研究完成；A1～A12 正式責任整合完成。

## 一、驗收目的

本文件驗證 A1～A12 經正式責任整合後，是否能形成一套可連續運作的整體治理責任鏈。

本輪只進行模擬實作驗收，不宣稱 FIELD-PASSED，也不以實際 Repository 全量改造作為本輪必要條件。

驗收核心：

```text
Identity
→ Metadata
→ Source / Evidence / Claim
→ State / Version
→ Relationship
→ Lifecycle / History
→ Traceability / Impact
→ Cross-Scheme Semantics
```

## 二、驗收規則

1. 正式功能清單只接受 A1～A12。
2. 不建立 A13 以上不存在的正式功能。
3. Identity、Version、State、Lifecycle、History 不互相混同。
4. Source 不等於 Evidence；Evidence 不等於 Claim；Inference 不得偽裝成 Fact。
5. Path、Filename、Git SHA 均不得直接取代 Logical Identity。
6. Relationship 必須具有語義與方向；一般 related_to 不得成為所有關係的替代物。
7. Impact 代表可能受影響範圍，不代表必然結果。
8. History 可追溯但不得自動重新成為 Current。
9. Cross-Scheme Semantics 只保留必要共同語義，不把所有內部流程強制統一。
10. 模擬通過只能產生 SIMULATION-PASSED，不得宣稱 FIELD-PASSED。

## 三、核心情境驗收

### Case A：身份、改名與搬移

```text
Object A
→ filename change
→ path change
→ Object A'
```

結果：PASS

驗證：邏輯身份保持一致；名稱與儲存位置可變；版本與狀態可獨立表達。

### Case B：版本演化

```text
Identity A
→ Version 1
→ Version 2
→ Version 3
```

結果：PASS

驗證：Identity 不因版本變更而改變；可回溯版本關係；Git commit 可作為實作證據但不取代邏輯版本。

### Case C：來源、證據、主張、推論

```text
Source A
→ Evidence A
→ Claim A
→ Inference A
```

結果：PASS

驗證：四者可分離；推論不會因存在來源而自動升格為已驗證事實。

### Case D：狀態與生命週期

```text
draft
→ review
→ verified
→ active
→ superseded
→ archived
```

結果：PASS

驗證：State、Lifecycle、Version、History 可分開表示；退出目前結構的資料仍可追溯。

### Case E：多類型關係

```text
A --derived_from--> B
A --depends_on--> C
A --supported_by--> D
A --supersedes--> E
```

結果：PASS

驗證：關係具有類型、方向與對象；不同語義不得被單一 related_to 取代。

### Case F：追溯鏈

```text
Result
→ derived_from
→ Claim
→ supported_by
→ Evidence
→ located_in
→ Source
→ represented_as
→ Version / Snapshot
```

結果：PASS

驗證：可以由結果向下追溯至主張、證據、來源及其版本／快照。

### Case G：變更影響

```text
Object A changed
→ identify relationships
→ identify dependent objects
→ identify potentially affected validation / usage
```

結果：PASS

驗證：A11 能產生可能受影響範圍；不把可能影響直接宣稱為實際影響。

### Case H：歷史資料隔離

```text
Current A
→ replaced by B
→ A retained as historical
```

結果：PASS

驗證：A 可追溯但不重新成為目前可用對象。

### Case I：跨方案共同語義

結果：PASS

驗證：Identity、State、Version、Relationship、Evidence、History、Traceability、Impact 等必要共同概念可供其他方案使用；方案內部流程仍由各方案自行負責。
