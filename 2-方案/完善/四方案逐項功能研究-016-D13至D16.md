## 三、D13 影響分析

### 3.1 責任

D13 將 D12 已比較的候選處置，轉換成具體影響範圍：

- 受影響的 Stable Identity
- 直接受影響能力
- 間接受影響能力
- 資料／知識影響
- 系統／方案影響
- 使用者與實際工作影響
- 關係／依賴傳播路徑
- 可能的成本、風險與回退影響
- 未知影響區域

### 3.2 核心原則

Impact 是「可能受影響的範圍與關係」，不是「已經發生的結果」。

D13 不得把 Impact Analysis 當成 D16 驗證；也不得因為某物被列入影響範圍，就直接判定它必須修改。

## 四、D14 遷移條件分析

### 4.1 責任

D14 不負責執行重構，而是回答：在什麼條件下，新舊能力可以安全共存、切換、替換或退出。

### 4.2 必要條件

至少需要確認：

- 新能力可用條件
- 舊能力停止使用條件
- 新舊能力並存期間的責任邊界
- 資料／引用／依賴轉移條件
- 相容性條件
- 驗證通過條件
- 回退條件
- 失敗停止條件
- 歷史資料保存條件
- 實際工作切換條件

### 4.3 邊界

D14 ≠ D11 候選產生。  
D14 ≠ D15 重構執行。  
D14 ≠ D16 驗證結果。  

D14 的輸出是「可執行的遷移條件」，不是「已經遷移完成」。

## 五、D15 重構執行

### 5.1 責任

D15 執行已經通過前置分析與條件確認的最小重構。

執行可以包含：

- 建立新能力
- 調整責任邊界
- 更新關係／依賴
- 遷移引用或資料
- 替換既有能力
- 讓舊能力進入退出流程
- 必要的最小文件／索引更新

### 5.2 核心原則

D15 不自行決定「應該 Merge／Delete／Retire」。

D15 的輸入必須包含：候選處置、影響分析、遷移條件、執行範圍、成功條件、回退條件。

任何無法確認範圍、條件或回退方式的重構，不得被包裝成已完成的最小重構。

### 5.3 與 Git 的關係

Git commit 是工程執行證據之一，不等於能力的 Logical Identity、Version 或 Current State 本身。

## 六、D16 重構後驗證

### 6.1 責任

D16 驗證重構後實際狀態是否符合 D15 前已定義的成功條件、遷移條件與影響控制要求。

### 6.2 驗證維度

至少檢查：

- 新能力是否存在且可使用
- 舊能力是否按照預期處理
- 關係／依賴是否正確
- 資料／引用是否完整
- 責任邊界是否符合設計
- 預期功能是否仍然成立
- 非目標範圍是否沒有被意外修改
- 回退條件是否仍可識別
- 歷史／追溯資訊是否仍完整
- 實際工作是否符合預期

### 6.3 結果

D16 最少輸出：

```text
PASS
PARTIAL
FAIL
UNKNOWN
```

UNKNOWN 不得升格為 PASS。

### 6.4 邊界

D16 是方案四重構結果的驗證，不等於方案二 B12 的一般任務結果驗證，也不等於方案三 C13 的變更實際驗證。三者可以共用驗證語義，但驗證對象不同。

## 八、禁止越權

1. D13 不直接決定採用哪個候選。
2. D14 不直接執行重構。
3. D15 不自行產生無分析依據的刪除／合併決策。
4. D16 不把未驗證結果寫成成功狀態。
5. D16 不提前建立 D17 新基準。
6. 任何實際工程異常應進入既有問題解決／持續改進流程，而不是在 D15 階段私自擴張方案四。
