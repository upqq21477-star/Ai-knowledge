# 語意壓縮與分層責任驗證｜研究深化與最優解確認

版本：v1.1
狀態：【研究完成第一輪；待實測最優解】

## 一、研究深化目的

上一輪已建立：
問題 → 功能 → Knowledge → System → Solution。

本輪不重新發明架構，而是驗證：
1. 既有分層原則是否與外部研究一致。
2. 哪些評估指標不可省略。
3. 是否存在比「單純 Token 壓縮」更合理的最優解。
4. 如何把外部研究轉成可執行的知識庫規則。

## 二、研究結果

### R01｜壓縮率不是唯一目標

2025 NAACL Survey 將 Prompt Compression 分為 hard／soft compression，核心目的都是降低長 Prompt 帶來的記憶與推理成本；因此成本下降是重要目標，但不是唯一目標。citeturn0search1

### R02｜資訊保存必須獨立測量

2025 EMNLP Findings 提出更完整的評估框架，除 compression ratio 外，至少同時觀察：
- downstream task performance
- grounding
- information preservation

研究發現部分壓縮方法會遺失原 Prompt 的關鍵細節，導致複雜任務效能受限。citeturn0search0

這直接支持本方案的「最小充分語意」而不是「最短文字」。

### R03｜答案正確不代表證據正確

2026 CustomNLP4U 研究在 evidence-aware RAG 中發現，隨壓縮增加，答案正確率下降幅度可能只有 2～4%，但 grounding 下降可達 40～50%；因此只驗收答案正確會高估壓縮系統可靠性。研究提出應依驗證需求保留 evidence-bearing spans。citeturn0search8

這與本專案先前發現的「結果語意不能只剩名稱」高度一致。

### R04｜Context 不只是 Prompt

Context Engineering 的實務定義將 system prompt、使用者問題、檢索資料、歷史、工具輸出等都視為模型推理時可見 Context，並強調選擇、結構化、壓縮、排序與工具／記憶整合。citeturn0search3

因此本方案不能只壓縮單一 Markdown 文件，還必須關注壓縮後 Context 的組成與順序。

## 三、對既有 50 次資料的重新解讀

既有結果：
- 初始壓縮：路由錯誤 3/50、語意失真 4/50、幻覺 1/50。
- Solution 邊界修正後：路由錯誤 0/50、語意失真 1/50、幻覺 0/50。
- Solution 驗收定義後：路由錯誤 0/50、語意失真 0/50、幻覺 0/50。

由此形成一個目前仍屬「內部模擬證據」的工程假設：

> 壓縮失真主要不是由字數本身造成，而是由不可替代語意被刪除或移交到錯誤層造成。

此假設仍需真實模型重複實驗驗證。

## 四、最優解候選

目前最優解不是：
「所有文件一起極限壓縮」。

而是：

> 「分層壓縮 + 語意契約 + 結果驗收 + A/B 驗證」。

具體為：

Knowledge：
保留原理、規則、證據、判定依據。

System：
只保留跨方案穩定成立的能力契約。

Solution：
保存本次任務的目的、路由、邊界、組合與驗收。

Context：
依任務選取必要層級，不把整庫全部送入模型。

## 五、最小充分語意判定

任何語意只有在同時滿足以下條件時才能刪除：

1. 不影響身份。
2. 不影響路由。
3. 不影響功能。
4. 不影響依賴。
5. 不影響結果解讀。
6. 不影響驗收。
7. 不需要作為證據追溯依據。

若不滿足，必須：
- 保留原層；
- 或明確移交到正確層。

## 六、研究新增的關鍵原則

### 原則 A｜Grounding 是獨立驗收軸

不能用「答案正確」取代「證據一致」。

### 原則 B｜Evidence-bearing semantics 優先保留

涉及：
- 證據
- 來源
- 主張
- 限定條件
- 例外
- 分類邊界

的語意，壓縮優先級最低。

### 原則 C｜Layer ownership 優先於字數

先判斷「誰負責這個語意」，再判斷能不能壓縮。

### 原則 D｜壓縮粒度必須可回退

每次壓縮都要能指出：
原語意 → 壓縮語意 → 責任層 → 驗收結果。

## 七、下一階段實驗

不再只測「完整 vs 壓縮」。

增加三組：

A｜完整組
B｜分層壓縮組
C｜過度壓縮組

比較：
- Token
- 路由
- 功能
- 語意失真
- Grounding
- Evidence Mapping
- 驗收
- Context-induced Error

目的是找出真正的「最小充分點」，而不是只證明壓縮有效。

## 八、研究結論

目前研究支持：

> 最優解不是最大壓縮率，而是在成本、能力、資訊保存與可驗證性之間取得最小充分平衡。

本專案的分層架構因此應繼續採用：
Knowledge → System → Solution，
但壓縮必須遵守語意所有權與證據保存原則。
