版本：v1.0

日期：2026-09-17

## 一、目的

將方案二「AI知識管理」的 B1～B16 功能逐項對照 Repository 已存在的系統、流程與知識，避免功能增加就直接建立新系統。

判定規則：

```text
已完整承擔 → 沿用
部分承擔 → 擴充／重新分責
跨系統共同 → 共用能力，不新增重複系統
流程性能力 → 優先維持流程，不強制系統化
真正缺口 → 才進入新系統建立 Gate
```

## 三、逐項判定

### B1 任務理解

AI知識管理系統 v2.0 已直接將問題／任務理解列為核心能力，因此不建立「任務理解系統」。

### B2 任務拆解

目前 AI知識管理系統提供任務理解；問題解決系統則已經有問題澄清、研究問題與候選解法流程。B2 尚不能直接宣告有完整統一能力，應先驗證一般複合任務與「已確認問題」是否需要不同拆解方式。

結論：部分承擔，不新增系統。

### B3～B4 搜尋與探索

Repository 已存在資料探索與搜尋系統，其責任包含搜尋意圖、範圍選擇、查詢拆分、候選取得、篩選、排序、停止與搜尋失敗診斷；AI知識管理系統負責把這項能力放入 AI 任務流程。因此不建立新的「AI搜尋系統」。

### B5 外部研究

外部研究已被問題解決系統定義為既有研究流程的一部分；AI知識管理系統也將外部研究與證據使用列為能力。應由既有搜尋／研究能力被調用，而不是再建立一個研究系統。

### B6 來源／證據判斷

Repository 已有來源與證據分析系統，明確區分 Source、Claim、Evidence、Knowledge，並檢查時間、版本、條件與適用範圍。因此直接沿用。

### B7 適用性判斷

B7 比 B6 更接近「目前任務是否適用」。目前相關條件檢查分散在來源／證據、版本、狀態、相容性等知識中，尚未證明需要獨立系統。先形成跨時間、版本、條件的實際案例。

### B8～B9 Context

AI上下文與交接系統已明確負責最小充分上下文、分層讀取、停止條件、交接與資訊不足後擴大搜尋；AI知識管理系統則負責把 Context 放入完整任務流程。因此不新增 Context 系統。

### B10 記憶／目前狀態辨識

目前已有上下文系統區分長期背景、目前狀態、歷史狀態與單次任務資訊；共同資料治理知識又要求 State、Version、History 分離。但目前尚缺一個充分的跨案例驗證，因此暫列部分承擔。

### B11 任務執行

這不是一個需要另立「執行系統」的理由。AI知識管理系統負責 AI 任務流程，AI知識庫基本運作系統負責將既有能力組合成實際工作循環。任務執行本身保持工作層能力。

### B12 結果驗證

目前存在三層能力：AI知識管理系統的結果驗證、實測結果回寫檢查小系統、後續工作觸發式驗證系統。這裡真正需要的是共同語義與責任接口，而不是第四個驗證系統。

### B13 不確定性保存

來源／證據分析系統已有「證據不足、尚未確認、部分支持」等結果；共同資料狀態模型又可保存目前狀態。因此已有基礎，但需要真實案例確認 AI 是否會正確保存而不是把未確認內容升格為知識。

### B14 結果保存

AI知識管理系統已負責結果保存；AI知識庫基本運作系統又要求形成可重建的最小運作收據。因此不新增結果保存系統。

### B15 知識回饋

AI知識庫基本運作系統已將 Observation、Evidence、Claim、Knowledge、Decision、Current State、Memory 分開；知識迭代與資料演化方案負責後續變更。B15 應驗證兩者接口，不新增「知識回饋系統」。

### B16 失敗診斷

AI知識管理系統已有失敗類型；基本運作系統負責異常、嚴重程度與路由；問題解決系統負責確認後的問題處理。因此目前是跨系統能力，不建立獨立失敗診斷系統。

## 四、目前真正未完成的地方

第一輪映射後，未發現足以直接觸發新正式系統 Gate 的明確缺口。

目前較值得驗證的是四個接口問題：

```text
1. B2 任務拆解
   一般複合任務 vs 已確認問題的拆解責任

2. B7 適用性判斷
   時間／版本／條件／範圍是否能被可靠組合判斷

3. B10 記憶／目前狀態辨識
   是否會把歷史、記憶、目前狀態混淆

4. B15～B16
   結果／失敗是否能正確回到演化與問題解決流程
```

這些都應優先用真實工作驗證，而不是再建立文件型系統。

## 五、與既有系統的責任關係

```text
AI知識管理系統
→ 任務流程總體協調

資料探索與搜尋系統
→ 搜尋／探索

來源與證據分析系統
→ Source / Claim / Evidence 判斷

AI上下文與交接系統
→ Context 選擇／組裝／交接

問題解決系統
→ 已確認問題的研究、候選解法與實測

AI知識庫基本運作系統
→ 實際工作循環、狀態檢查、異常與結果回饋

後續工作觸發式驗證系統
→ 待驗證能力在自然工作中的驗證

實測結果回寫檢查小系統
→ 檢查「已實測」是否具備最低證據

知識迭代與資料演化系統
→ 接收真正的演化訊號
```

## 六、結論

方案二目前沒有理由新增 B1～B16 對應的獨立系統。

下一步不應是「再建立搜尋系統／Context 系統／驗證系統」，而應進入：

```text
B2／B7／B10／B15／B16
↓
選擇真實工作案例
↓
最小實作驗收方法
↓
自然工作驗證
↓
觀察是否出現真正能力缺口
↓
只有缺口成立才進入新系統建立 Gate
```

本文件不修改任何既有系統，也不宣告任何舊系統退役。
