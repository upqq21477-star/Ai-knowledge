# 問題處理－無記憶交接測試發現現行入口引用漂移－研究與候選解法 v1.0

日期：2026-09-18
對應問題：GitHub Issue #2「無記憶交接測試發現現行入口引用漂移」
狀態：【問題確認完成；研究與候選解法完成；待最小修正】

## 一、問題定義

本次無記憶 AI 交接測試已證明核心入口可以恢復目前工程，但全庫一致性檢查失敗。

真正問題不是「沒有目前狀態」，而是：

> 現行權威入口已經前進到「交接資料-v2.7 + 快照-003」，但仍有現行文件保留舊入口與舊狀態語義。

因此新 AI 若只沿 README 的明確入口可以成功；若依規則進行衝突檢查，會發現多個互相競爭的舊引用。

## 二、問題分解

### P1：目前工程狀態來源漂移

目前狀態.md 仍指向快照-001，且內容仍描述舊 Gate 4～6。

### P2：入口鏈漂移

說明.md、規則.md、1-系統/AI上下文與交接系統.md仍保存舊入口鏈。

### P3：歷史引用與現行引用沒有語義分層

舊交接資料、舊快照、舊驗證文件必須保留，但不能讓「保留歷史」等於「仍是目前入口」。

### P4：缺少「現行文件引用驗證」這一層

本次問題是交接文件建立後發現的，因此現有檔案索引只能驗證檔案存在與位置，還不足以保證現行入口引用沒有漂移。

## 三、外部研究

研究得到的共同原則：

1. AI 的 priming/context 文件應是 repository 中的一等工程資產，並且必須保持最新；過時文件可能直接把 AI 引向舊做法。Martin Fowler 的 Knowledge Priming 建議將這類文件放在 repository、像程式碼一樣維護，並在重大重構時重新檢查。 
2. Context Anchoring 的做法是把目前決策與狀態外化為可持續、權威的文件，而不是依賴對話記憶；不同層級文件應各自承擔不同責任。
3. GitHub 的文件工程也使用自動檢查 broken links、由變更觸發文件更新等方式降低文件漂移。
4. 軟體重建工作中，當文件可能過時時，應明確指定較可靠的 source of truth，而不是讓 AI 自行猜測哪份文件較新。

外部研究支持本問題的核心判斷：需要「明確權威來源＋受影響引用同步＋驗證」，而不是繼續增加另一份交接摘要。

## 四、候選解法

### A：只修目前狀態.md

優點：成本最低。
缺點：說明.md、規則.md、上下文系統仍會提供舊入口，問題不完整解決。
判定：不採用。

### B：建立第五份「總入口文件」

優點：可以把所有入口集中。
缺點：會增加新的同步來源，違反目前單一工程狀態入口設計。
判定：拒絕。

### C：維持現有入口分層，修正現行文件引用，歷史文件保持不動

目標鏈：
README → 說明 → 交接-v2.7 → 快照-003 → 目前狀態（高階總覽）→ 規則 → 待辦 → 工程運作方案 → 任務相關文件

其中：
- 快照-003是目前工程執行游標。
- 目前狀態是高階架構總覽，不再保存舊工程游標。
- v2.7是目前交接背景。
- 舊快照、舊交接、舊驗證文件保留為歷史，不作目前入口。

判定：採用。

### D：建立自動化引用檢查系統

可進一步掃描所有 Markdown 的舊入口引用。
優點：長期可降低再次漂移。
缺點：目前問題可用低成本文件修正解決；立即增加軟體／CI 系統會擴大範圍。
判定：本輪不建立。若後續自然工程再次發生同類漂移，再進入問題處理。

## 五、採用方案

採用 C。

最小修正範圍：

1. 目前狀態.md：移除舊工程游標與 Gate 4～6；明確定義為高階專案／架構總覽；指向快照-003取得目前工程位置。
2. 說明.md：將入口順序切換到 v2.7／快照-003；移除「目前狀態是第一判斷入口」語義。
3. 規則.md：明確區分快照=目前工程狀態、目前狀態=高階總覽、v2.7=交接背景、規則本身=操作規則；更新舊交接檔名引用。
4. 1-系統/AI上下文與交接系統.md：更新分層讀取與交接入口，避免系統文件本身教導 AI 使用舊入口。
5. 不修改舊快照-001/002、舊交接 v2.x、已完成驗收／問題處理歷史。

## 六、最小變更原則

本次不重新設計交接系統，只做「現行權威鏈同步」。

不做：新增狀態層、新增第五方案、建立自動化工具、重做四方案驗收、批量改寫所有歷史文件。

## 七、驗收條件

### 靜態一致性驗證
- 搜尋舊快照-001/002在現行文件中的引用。
- 搜尋「交接資料.md」在現行文件中的引用。
- 確認這些引用只存在於歷史說明／歷史紀錄，或明確標示為歷史。
- 確認現行入口全部指向 v2.7／快照-003。

### 無記憶交接驗證
重新模擬：只提供 Repository 首頁 → README → 現行入口 → 恢復目前工程 → 判斷下一步。

必須能直接得到：
正常工程運作；FIELD 待自然觸發；無需人工 FIELD 測試；無需重做四方案總驗收。

### 回歸
原有四方案模擬／回歸紀錄不得被修改；只驗證交接鏈沒有破壞原有責任邊界。
