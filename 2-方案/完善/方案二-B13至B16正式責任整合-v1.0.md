## 一、整合目的

將 B13～B16 的研究結果正式接入方案二「AI知識管理」責任鏈，不新增四個獨立大型系統，不覆蓋既有問題解決流程與方案三／方案四責任。

本文件是責任整合文件，不代表方案二整體完成或 FIELD-PASSED。

---

# 二、B13 不確定性保存

### 正式責任

B13 負責保存任務過程與結果中的：

- Unknown
- Unverified
- Insufficient Evidence
- Conflicting Evidence
- Conditional
- Time-sensitive / Outdated
- Applicability Unknown

並保存其原因、證據缺口、適用條件、版本／時間、影響與下一步驗證方向。

### 不負責

- 不替 B6 判斷證據品質
- 不替 B7 判斷適用性
- 不替 B12 判斷任務是否成功
- 不把模型 confidence 直接當成事實
- 不自行消滅歷史不確定性

---

# 三、B14 結果保存

### 正式責任

保存可重建一次任務結果所需的最小充分資訊：

```text
Task / Goal
Result
Status
Verification
Sources / Evidence
Context / Version
Decisions
Uncertainty
Unresolved Issues
Reusable Candidate
Traceability
```

### 不負責

B14 不將所有結果自動升格為正式知識；正式知識形成仍需適當的驗證與演化流程。

---

# 四、B15 知識回饋

### 正式責任

從實際任務結果中識別值得保存與後續處理的回饋訊號，並將其分流為：

- 保存即可
- 問題候選
- 研究候選
- 知識變更候選
- 方案三演化候選
- 方案四蒸餾候選

### 正式 Gate

```text
工作結果
↓
Observation / Evidence
↓
Feedback Signal
↓
重複性／範圍／證據判斷
↓
Candidate
↓
適當責任層
```

不得：

```text
工作結果 → 直接改正式知識
```

---

# 五、B16 失敗診斷

### 正式責任

B16 接收 B12 FAIL 或其他已確認異常，定位失敗階段與責任層，建立診斷資料：

```text
Original Task
Expected Result
Actual Result
Failure Point
Failure Type
Evidence
Contributing Conditions
Existing Capability Checked
Root Cause Candidate
Uncertainty
Responsible Layer
Next Action
Revalidation Target
```

### 正式路由

```text
B12 FAIL
↓
B16
↓
問題確認
↓
問題解決系統
↓
候選解法／最小修正
↓
B12 重新驗證
```

若診斷結果涉及正式知識／資料演化，轉方案三；若涉及長期能力重疊、責任混亂或系統重構，建立方案四候選。

B16 不直接重構正式系統。
