## 一、回歸目的

本輪不是重新證明 A1～A12 是否存在，而是驗證在以下變化、錯誤、重複與跨方案操作後，既有整體責任仍能保持一致：

- Identity 穩定性
- Version / State / Lifecycle 分離
- Source / Evidence / Claim 邊界
- Relationship 語義
- History 不污染 Current
- Traceability 可恢復
- Impact 不被誤判為實際結果
- Cross-Scheme Semantics 不越權
- Formal List 不被錯誤擴張

## 二、回歸規則

任何案例若造成以下任一情況，即視為 FAIL：

1. 同一 Logical Identity 因路徑或檔名變更而被錯認為新對象。
2. 新 Version 自動覆蓋或消滅舊 Version 的可追溯性。
3. State 變更被錯誤當成 Version 變更。
4. History 資料重新被當成 Current。
5. Source、Evidence、Claim、Inference 的語義邊界消失。
6. Typed Relationship 被退化成無語義關聯。
7. Traceability 中斷且無法定位原因。
8. Impact 被直接解讀成已發生結果。
9. 跨方案共同語義侵入方案內部責任。
10. 系統自行產生 A13 以上正式功能。

## 三、回歸案例

### R01：檔名變更

Identity 保持；Name 更新；Version 不因單純名稱變更而被錯誤重建。

結果：PASS

### R02：路徑搬移

Current Path 改變；Logical Identity 不變；Traceability 保持。

結果：PASS

### R03：內容新版本

建立新 Version；舊 Version 保留 History；Current 指向依治理規則更新。

結果：PASS

### R04：僅 State 改變

State 改變不產生不必要的 Identity 重建。

結果：PASS

### R05：來源新增但證據不足

新增 Source 不會自動產生 Verified Claim。

結果：PASS

### R06：Evidence 與 Claim 不一致

衝突被保留為問題／不確定性，不自動消除其中一方。

結果：PASS

### R07：Inference 回寫

Inference 可保存並標示其推導性質，不升格為原始 Evidence。

結果：PASS

### R08：舊資料封存

Archived / Historical 對象仍可追溯，但不自動回到 Current。

結果：PASS

### R09：關係變更

新增或移除 Typed Relationship 不改變被關聯對象本身的 Identity。

結果：PASS

### R10：依賴變更

依賴關係更新後，可重新判定可能受影響範圍；不直接宣稱實際結果。

結果：PASS

### R11：追溯鏈回復

由 Result 向 Claim、Evidence、Source、Version／Snapshot 回溯仍可成立。

結果：PASS

### R12：跨方案回寫

方案二／三／四產生的治理資料可回寫；方案一不接管其內部執行責任。

結果：PASS

### R13：重複寫入

同一 Logical Identity 的重複事件不產生多個錯誤身份。

結果：PASS

### R14：歷史版本誤用

舊 Version 被引用時可以識別其歷史狀態，不會無聲地偽裝成 Current Version。

結果：PASS

### R15：Impact 過度推論

「可能受影響」不得被轉換為「已受影響」。

結果：PASS

### R16：Formal List 邊界

重新掃描正式功能清單後，仍確認最高正式功能為 A12；不存在 A13～A16。

結果：PASS
