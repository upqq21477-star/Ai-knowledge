## 一、為什麼重新重建

本輪重新檢查發現：Repository 其實早已有建立方案前的完整規則與 v1.0 流程，但 AI 仍曾跳過流程直接施工。

已確認：

```text

≠
規則被執行
```

因此本次不是補一句提醒，而是把流程改成真正的行動前 Preflight／LOCK／ALLOW 機制。

## 二、研究與比對

已完成 Repository 內部交叉比對與外部方法研究。

外部參考：

- Microsoft Azure Well-Architected ADR
- AWS Prescriptive Guidance ADR
- GitLab Engineering Communication
- GitLab Weekly Async Updates

主要吸收：

- 重大決策才建立正式決策紀錄。
- 決策保留背景、選項、取捨、狀態與後果。
- 非同步狀態以階段／週期摘要為主，不逐步廣播。
- 使用者不需要知道每個內部操作。
- 文件應簡潔並保持單一真實來源。
