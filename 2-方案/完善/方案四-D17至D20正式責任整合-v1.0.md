# 方案四-D17至D20正式責任整合-v1.0

版本：v1.0  
狀態：【正式責任整合完成；SIMULATION-PASSED】

## 一、正式責任鏈

`D16 重構後驗證 → D17 新基準建立 → D18 歷史／舊能力保存 → D19 蒸餾結果回寫 → D20 再次蒸餾觸發`

完成 D20 後不直接執行下一次蒸餾，而是建立新的蒸餾入口並回到 D1。

## 二、D17

責任：將 D16 已驗證通過的新結構建立為新的 Current Baseline。

必要條件：D16 PASS、Stable Identity、Version、Current State、生效範圍、來源案件、Evidence、Traceability。

禁止：把 PARTIAL、FAIL、UNKNOWN 當成已通過的 Current Baseline。

## 三、D18

責任：保存退出 Current 的舊能力、舊版本與歷史關係。

語義：Historical/Archived/Retired 不等於 Current。

禁止：保存後未標示 Lifecycle/State，導致 AI 將舊能力重新當作目前能力。

## 四、D19

責任：保存本次蒸餾的決策脈絡、候選、實際變更、驗證、未解決問題與不確定性。

禁止：D19 自行修改其他方案內部知識；不得把 UNKNOWN、候選或推論寫成確認事實。

## 五、D20

責任：在正常工程運作中確認是否再次形成符合蒸餾條件的結構性問題，若成立則建立新的 Distillation Case 入口。

D20 不是重構執行器，也不是 D1 的替代品。

新案件必須重新執行：

`D1 → D2 → D3 → D4 → D5 ...`

## 六、與其他責任層的關係

- Scheme 1：提供 Identity、State、Version、Lifecycle、History、Evidence、Traceability 等共同語義。
- Scheme 3：C17 是蒸餾候選轉交入口；不能跳過 D1～D4。
- 問題解決系統：負責問題確認與候選解法流程，不被 D20 取代。
- 工程運作與持續改進：提供 D20 的長期實際工作觀察來源。

## 七、狀態

```text
D16-PASS
↓
BASELINE-CREATED
↓
HISTORICAL-PRESERVED
↓
DISTILLATION-RECORDED
↓
NORMAL-OPERATION
↓
DISTILLATION-TRIGGER-CHECK
├─ NO → 繼續正常工程運作
└─ YES → NEW-DISTILLATION-CASE → D1
```

D17～D20 已完成研究、模擬實作驗收與正式責任整合。

目前狀態為 `SIMULATION-PASSED`，不宣稱 `FIELD-PASSED`。
