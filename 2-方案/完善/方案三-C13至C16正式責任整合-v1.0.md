# 方案三-C13至C16正式責任整合 v1.0

版本：v1.0  
狀態：【責任整合完成；模擬回歸待驗證】  
日期：2026-09-17

## 一、正式責任鏈

```text
C12 最小變更執行
↓
C13 實際驗證
↓
C14 採用／暫緩／退回
├─ ADOPT → C15 目前狀態更新 → C16 歷史保存
├─ DEFER → C16 歷史保存 → 後續條件追蹤
└─ RETURN → C16 歷史保存 → 問題解決／重新候選
```

## 二、責任定義

### C13 實際驗證

負責以實際工作／環境結果檢查 Change Objective、Success Criteria、Applied Version 與實際證據。

輸出：PASS、PARTIAL、FAIL、UNKNOWN。

不得因模擬通過、文字合理或 C12 執行成功而自動宣告 PASS。

### C14 採用／暫緩／退回

負責根據 C13 與既定條件形成 ADOPT、DEFER、RETURN。

不得自行修改正式內容，也不得取代 C13 驗證。

### C15 目前狀態更新

只在具備可採用決策依據時更新 Current State，並建立新的 Version／Effective State 關聯。

不得把 DEFER、FAIL、UNKNOWN 當作目前成功狀態。

### C16 歷史保存

保存 Change Case、舊／新版本、驗證、決策、證據、限制與 Traceability。

不得讓歷史資料重新被當成 Current。

## 四、跨方案接口

方案二 B12：驗證單次任務結果。  
方案三 C13：驗證演化變更的實際效果。

二者可以互相提供證據，但責任不可合併。

C14 RETURN 可轉入既有問題解決流程；若問題超出單次變更範圍，可轉方案四。
