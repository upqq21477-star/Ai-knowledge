狀態：【功能→知識盤點完成；知識書已建立；既有系統能力重新盤點完成；暫不建立新系統；待自然案例驗證】

## 一、本輪實際處理的問題

問題不是「缺少一份建立方案規則」，而是：

> 新內容進入工程後，AI 沒有先將其問題化，也沒有先完整列出功能、逐項確認功能所需知識、檢查既有知識書與整理知識缺口，就直接進入方案／系統建立。

前一輪已經發現「建立入口 Gate」缺口，但只補上了 Problem Intake 與建立流程文件；實際檢查後確認仍少了一個更重要的施工依賴：

```text
問題
→ 完整功能
→ 功能需要的知識
→ 既有知識書檢查
→ 知識缺口
→ 外部研究／比較
→ 建立／更新知識
→ 重新盤點系統能力
→ 才能判斷是否需要系統／方案
```

因此本輪沒有直接建立新系統，而是先完成上述知識層。

## 四、外部研究與比較

### AWS ADR

AWS 將重大架構決策放入具有狀態與生命週期的 ADR，至少記錄背景、決策與後果；決策改變時建立新記錄並取代舊記錄。這證明重大決策需要持久、可追溯的理由，但 ADR 本身不是完整的功能→知識盤點機制。citeturn0search0turn0search6

### Microsoft Azure ADR

Microsoft 的 ADR 建議記錄問題背景、考慮過的選項、決策、取捨、狀態與理由，並把 ADR 視為系統目前結構如何形成的累積記錄。這支持本專案的決策追溯，但仍不能替代前置的功能與知識盤點。citeturn0search5turn0search9

### Atlassian Product Discovery / PRD

Atlassian 的產品發現先處理問題、價值、可用性、可行性與策略，再進入交付；PRD 則要求目的、功能、行為、假設、問題、範圍外事項與待研究問題保持可追蹤。這支持「先問題、再功能／需求、再研究與交付」的方向。citeturn1search0turn1search6

### IEEE Software Requirements

IEEE 將需求工程定義為識別、文件化與管理系統必須滿足的條件與能力，並將其視為後續設計、實作與驗證的基礎。這支持先識別能力，再決定實作方式。citeturn1search12

### 綜合比較

外部成熟做法共同支持：

1. 先定義問題與需求。
2. 明確列出需要的能力／功能。
3. 研究與比較候選做法。
4. 記錄決策、取捨與限制。
5. 再進入實作與驗證。
6. 持續回饋與修正。

本專案增加的特殊要求是：

> 在「功能 → 實作」之前增加「功能 → 知識 → 既有知識書 → 知識缺口 → 研究 → 知識形成」。

原因是本專案的核心產物本身就是 AI 可重用知識，而不是一般單次軟體產品。

本輪在知識建立後重新檢查既有系統，而不是因為發現缺口就直接建新系統。

### 2. 搜尋研究相關系統／知識

已有問題理解、資訊需求、查詢策略、搜尋拆分與比較相關知識，因此沒有理由為本次問題再建立另一套搜尋系統。

### 3. 小系統建立能力

已有「小系統建立原則」要求問題／需求 → 現有能力 → 外部搜尋 → 方法／工具／案例比較 → 候選 → 知識書 → 最小規格 → 實測 → 判定。fileciteturn277file1L17-L23

### 4. 觸發管理

已有「觸發條件管理系統」，且其明確不是問題解決系統，不應把問題解決本身塞進觸發系統。fileciteturn282file3L49-L57

### 5. 實際失效證據

既有紀錄已證明：問題解決系統可能存在，但新內容進入時 AI 不一定會實際啟動它。也就是「能力存在」與「正確觸發」是兩個不同問題。fileciteturn282file1L18-L25

## 六、本輪判定：不是建立新系統

重新盤點後，沒有足夠證據支持建立另一個「新內容問題化系統」或「功能→知識系統」。

原因：

1. 問題理解已有知識。
2. 問題解決已有系統。
3. 搜尋與外部比較已有能力。
4. 知識建立已有流程與目錄。
5. 系統建立已有正式流程。
6. 真正缺口是這些既有能力沒有在正確入口形成強制依賴鏈。

因此目前最小正確處理不是：

```text
再建立一個系統
```

而是：

```text
補足知識層
+
把「功能→知識書盤點」設為建立方案／系統前的必要入口
+
讓問題解決系統在新內容構成問題時被正確觸發
```

## 九、禁止誤判

- 知識資料夾存在 ≠ 本問題的知識已建立。
- 有相關知識書 ≠ 每項功能的知識需求都已覆蓋。
- 有問題解決系統 ≠ 新內容一定會觸發問題解決系統。
- 有建立流程 ≠ AI 已經實際遵守建立流程。
- 建立知識書 ≠ 系統成立。
- 建立系統文件 ≠ 系統驗證完成。
- 完成一次自然案例 ≠ 整套流程永久正確。
