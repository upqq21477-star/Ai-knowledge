版本：v1.0

## 一、核心問題
目前已有「上下文成本」與「上下文管理原理」，但它們主要回答「應如何管理 Context」，尚未形成可重複測量：
- 一個任務需要多少 Context。
- Context 增加後可靠性如何變化。
- Context 不足／過量是否造成失真。
- Unsupported Claims 如何被追溯與分類。

因此本次不是重新建立一般 Context 管理，而是把三項能力作為核心：
- C03 Context Budget。
- C04 Context Reliability Test。
- C05 Hallucination Detection。

## 二、第一階段：問題拆分
### 問題 A：Context 沒有任務級預算
現有原理要求「最小充分 Context」，但缺乏測量流程。

需要功能：
1. Context 梯度。
2. 任務級性能測量。
3. 最小可靠 Context。
4. 飽和／下降點。
5. Context Profile。

### 問題 B：Context 改變後可靠性未知
長 Context 不等於有效 Context。

需要功能：
1. Context 長度控制。
2. 關鍵資訊位置控制。
3. 無關資料比例控制。
4. 規則／記憶／理解一致性測試。
5. 重複測試與失真分類。

### 問題 C：錯誤是否由 Context 造成無法判定
一般「答案錯誤」不足以說明原因。

需要功能：
1. Atomic Claim。
2. Evidence Mapping。
3. Supported／Contradicted／Unsupported／Uncertain。
4. Context 梯度對照。
5. Context-induced Error 判定。

## 三、第二階段：外部研究與比較
### 1. 長 Context 評估
RULER 提供比 Needle-in-a-Haystack 更廣的長 Context 評估，加入多 needle、multi-hop tracing、aggregation 等任務；其實驗顯示多數模型在長度增加及任務複雜度提高時會出現性能下降。

2025 年研究進一步報告，即使相關證據已被完美取得，單純增加輸入長度仍可能使多種任務性能下降，說明 Context Budget 不能只等同「檢索是否成功」。

### 2. Factuality／Grounding
FActScore 將長輸出拆成 atomic facts，逐項檢查是否有可靠來源支持，適合吸收為 C05 的 claim-level grounding 原則。

SelfCheckGPT 顯示，在沒有外部資料庫的黑箱情況下，多次採樣的一致性可作為 hallucination detection 的輔助訊號，但一致性不能直接等同真實性。

### 3. 外部研究結論
外部方法共同支持三個方向：
- 不以宣稱 Context Window 代替實際能力測試。
- 不以單一 Needle retrieval 代替完整 Context reliability。
- 不以整體「答案對／錯」代替 claim-level evidence grounding。

## 五、候選方案的必要性
目前既有能力能：
- 管理 Context。
- 搜尋資料。
- 判斷證據。
- 執行任務。

但不能形成一條已定義、可重複執行的「Context size → reliability → claim grounding → context-induced error」測試鏈。

因此目前可提出候選方案，但「需要正式方案」仍應由最小實測確認。
