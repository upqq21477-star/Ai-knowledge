# 方案二 B9至B12 正式責任整合 v1.0

版本：v1.0
狀態：【責任整合完成；模擬回歸待驗證】
日期：2026-09-17

## 一、整合目的

將 B9～B12 的逐項研究結果轉為方案二正式責任鏈，同時保留既有系統的專業責任，不建立重複大型系統。

## 二、正式責任

### B9 上下文組裝

負責將 B8 選出的最小充分資料依任務組合成 Working Context。

不負責：重新無限制搜尋、重新判斷所有資料適用性、建立第二套 Context 系統。

### B10 記憶／目前狀態辨識

負責辨識 Knowledge、Memory、Current State、History，並在 Context 中避免歷史或記憶污染目前狀態。

不負責建立第二套 State / Version / Lifecycle 語義；使用方案一共同語義。

### B11 任務執行

負責利用已確認的 Context、工具與既有能力完成任務。

不負責：自行改寫正式規則、取代問題解決系統、以執行完成推論任務成功。

### B12 結果驗證

負責依 Goal、Requirements、Evidence、Applicability、Output、Success Criteria 驗證實際結果。

結果可為 PASS、PARTIAL、FAIL、UNKNOWN。

不負責：只檢查來源可信度、只檢查資料適用性、或自行吞掉失敗修正。

## 三、正式接口

```text
B8
↓
B9 Context Assembly
↓
B10 State / Memory Recognition
↓
B11 Task Execution
↓
B12 Result Validation
├─ PASS → B14/B15
├─ PARTIAL → 補做／保留缺口
├─ UNKNOWN → 補研究／補證據
└─ FAIL → B16 → 問題解決 → 修正 → B12
```

B9/B10 在實際工作中可反覆互動，不要求絕對線性。

## 四、共同語義依賴

B9～B12 使用方案一共同語義：

```text
Identity
Version
State
Lifecycle
History
Source
Evidence
Traceability
```

不另建同名第二套定義。

## 五、與既有系統處置

- AI上下文與交接系統：承擔 B9 主要 Context 能力。
- AI知識管理系統：承擔 B9、B11、B12 的方案流程接口。
- AI知識庫基本運作系統：承擔 B11／結果保存等基礎運作。
- 方案一共同語義：承擔 B10 所需 State / Version / History 等語義。
- 問題解決系統：承擔 B12 FAIL 後的候選解法與修正流程。

```text
選擇 → 組裝 → 狀態辨識 → 執行 → 驗證
```
