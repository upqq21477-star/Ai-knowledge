# 方案分層分類清冊 v1.0

日期：2026-09-19
狀態：【施工中；第一輪分類基線】
目的：處理目前「2-方案」文件角色混雜問題；先分類，再搬遷。

## 1. 正式責任層
- 00-CURRENT：目前唯一工程游標與目前正式方案狀態入口。
- 01-施工：正在建立、修改、整合、等待驗證的方案施工材料。
- 02-研究驗證：研究、比較、模擬、實測、驗收、問題處理與驗證材料。
- 03-歷史：已被新版本／新基準取代，或只保留歷史追溯價值的材料。

既有 完善/ 是歷史施工形成的混合區，不能直接視為單一層。

## 2. 明確 CURRENT
唯一：完善/CURRENT Baseline-v1.0.md
不得因其他文件名稱含「最新」「狀態」「完整」而自動取得 CURRENT 權威。

## 4. 明確施工類候選
以下類型優先進 01-施工：
- *施工規劃*
- *施工總規劃*
- *施工順序*
- *建立規劃*
- *完善草案*
- *閉環補強規格*
- 尚未完成、仍是目前施工主線的方案規劃。

但「規劃」本身不等於施工中；仍以 CURRENT 與工程狀態為準。

## 5. 明確歷史類候選
以下材料若已被 CURRENT／新版正式方案取代，優先進 03-歷史：
- 舊版本方案中已被後版取代者。
- 目前工程狀態快照中已被 CURRENT Baseline 明確降級者。
- 已完成、且不再作為目前入口的舊交接／舊方案。
- 只具有追溯用途的舊研究與舊施工紀錄。

注意：版本較舊不等於自動歷史；必須確認是否已被新權威取代。

## 6. 第一輪不搬遷區
完善/ 內的以下類型暫不直接搬：
- 方案一/二/三/四 責任整合與模擬驗證混合文件。
- 工程運作* 系列。
- 目前工程狀態* 系列。
- 問題處理* / 問題解決* 系列。
- 實際驗證* 系列。

原因：這些文件互相引用且部分承擔目前工程證據鏈；必須先做引用掃描與 Authority 判定。

## 7. 特別注意

方案與 Evidence 不是同一層。
方案文件回答：要解決什麼、選什麼方法、怎麼施工與驗證。
驗證文件回答：實際／模擬結果如何。
系統文件回答：系統本身怎麼運作。
Skill 文件回答：AI 何時、以何種責任執行工作。
不能因某方案文件描述了一個系統，就直接把它當成 System Source of Truth。
