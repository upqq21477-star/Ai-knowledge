# 語意壓縮與分層責任驗證方案

版本：v1.1
狀態：【候選方案；已完成研究→Knowledge→System→方案組裝】

## 一、目的

在不改變核心能力與 Knowledge 的前提下，找出 Knowledge、System、Solution 的最小充分語意，降低 Context 成本，同時維持可交接、可執行、可驗收。

## 二、執行鏈

研究問題
→ 問題拆分
→ 功能清單
→ 功能逐項研究
→ 外部方法／工具／研究比較
→ 證據與適用性判斷
→ 建立 Knowledge
→ Knowledge 整合
→ 建立 System
→ System 最小實測
→ 組裝 Solution
→ A/B 驗證
→ 必要時回退並補最小語意

## 三、核心路由

需要判定語意歸屬／壓縮
→ 語意壓縮與分層責任驗證系統

需要外部證據
→ 既有研究／搜尋相關 System

需要更新 Knowledge
→ 知識比較、更新與資料演化相關能力

## 四、層級契約

### Knowledge
保存：
原理、規則、證據、判定依據。

### System
保存：
身份、功能、必要依賴、結果。

### Solution
保存：
目的、路由、邊界、依賴、驗收。

原則：
> 同一語意只在真正需要它的層保存一次。

## 五、壓縮規則

1. 可由 Knowledge 取得的原理，不在 System 重複。
2. 可由 System 固定身份取得的資訊，不在 Solution 重複。
3. 方案專屬目的、路由、邊界、驗收保留在 Solution。
4. 影響 System 身份、功能、依賴或固定結果解讀的語意不得刪。
5. 背景、重複敘述、不影響決策與執行的資訊優先刪除。
6. 發現錯誤只補最小缺失語意，不恢復完整原文。

## 六、實驗設計

### A｜正式組
正式 Solution + 正式 System + 相同 Knowledge。

### B｜壓縮組
壓縮 Solution + 壓縮 System + 相同 Knowledge。

控制：
Knowledge 不變；任務相同；測試條件盡量相同。

## 七、驗收

至少檢查：
- 路由正確
- System 身份正確
- 功能完成
- 依賴正確
- 結果正確解讀
- 驗收分類正確
- Grounding 正確
- 無新增不可解釋失真
- Context／Token 成本下降

若錯誤：
定位缺失語意 → 判定責任層 → 最小修正 → 重測。

## 八、既有實驗參考

內部 50 次結構化模擬：
- 初始壓縮：路由 3/50、語意失真 4/50、幻覺 1/50。
- 加入 Solution 路由邊界後：路由 0/50、語意失真 1/50、幻覺 0/50。
- 加入 Solution 驗收定義後：路由 0/50、語意失真 0/50、幻覺 0/50、功能 50/50、整體成功 50/50。

Token 結構化估算：
正式組約 28,201／50 次；
初始壓縮約 9,177／50 次；
Solution 邊界修正後約 9,500／50 次。

以上為內部模擬，不是獨立 API benchmark。

## 九、成功條件

1. Knowledge 不因壓縮而失去判定依據。
2. System 不因壓縮而失去核心能力。
3. Solution 不因壓縮而失去路由與驗收。
4. 三層責任不互相污染。
5. 壓縮後 Context 成本下降。
6. 任務成功與結果解讀維持。
7. 錯誤可以定位到具體缺失語意。
8. 修正可以以最小語意增量完成。

## 十、停止／回退

若壓縮失敗：
- 先定位缺失語意。
- 回退到對應層。
- 不直接恢復整份長文件。

若通過：
- 保留壓縮版本。
- 累積實驗資料。
- 將可泛化規則回寫 Knowledge。
- 再決定是否擴展至其他 System／Solution。

## 十一、研究依據

Prompt Compression 研究指出，壓縮需同時考慮成本與下游任務效能；近期研究進一步強調資訊保存與 grounding，不能只以壓縮比例判定成功。

參考：
- Li et al., Prompt Compression for Large Language Models: A Survey, NAACL 2025.
- Łajewska et al., Understanding and Improving Information Preservation in Prompt Compression for LLMs, Findings of EMNLP 2025.
