# 正確成立方案與系統方案 v2.1

日期：2026-09-17
前版：`2-方案/正確成立方案與系統方案-v2.0.md`
狀態：【正式流程補強；已納入「規劃 → 建立」連續生命週期】

> v2.1 不取代 v2.0 的 F01～F30 功能與建立前研究／Gate；本版補強一個先前仍存在的入口缺口：**方案規劃本身必須被納入工程運作，而且規劃完成時必須留下明確的「未建立／未完善」施工控制標記。**

## 一、完整生命週期

```text
構想／需求
↓
建立規劃
↓
【規劃完成／未建立／未完善】
↓
同步建立待辦／順序／依賴
↓
等待施工
↓
下一次開始施工
↓
讀取施工入口標記
↓
Preflight
↓
問題／目標
↓
完整功能
↓
既有能力盤點
↓
外部研究／工具／產品／案例比較
↓
限制／漏洞／失效模式
↓
反方案檢查
↓
候選架構／責任邊界
↓
討論／修正
↓
方案確認 Gate
↓
LOCK / ALLOW
↓
只有 ALLOW 才能正式建立
↓
建立／完善／驗收／實戰
↓
新基準
```

## 二、規劃不是正式方案

規劃文件只代表：

```text
「這個東西被認為值得規劃／研究／安排施工」
```

不得代表：

```text
「這個方案已經正式成立」
```

因此所有尚未正式建立的規劃，必須明確標記：

```text
方案建立狀態：【未建立】
方案完善狀態：【未完善】
施工入口：【必須重新執行本流程】
```

## 三、規劃完成時必須同步產生

規劃階段不得只建立一份說明文件。

至少同步形成：

1. 規劃文件
2. 工程狀態
3. 待辦／工作池
4. 前置條件／依賴
5. 目前順序
6. 下一個可執行工作
7. 施工入口標記

其中「待辦」不記錄微步驟，而記錄工程階段。

## 四、施工入口強制規則

下一次 AI 開始建立該方案時，看到：

```text
【未建立】
或
【未完善】
```

不得直接建立核心方案／核心系統。

必須先確認：

```text
規劃文件
↓
目前工程狀態
↓
待辦／依賴
↓
正確成立方案與系統方案流程
↓
Preflight
```

若任一核心 Gate 未完成：

```text
LOCK
```

只有完整通過才：

```text
ALLOW
```

## 五、規劃狀態、建立狀態、完善狀態分離

不得用單一「完成」表示全部完成。

```text
規劃狀態：未規劃／規劃中／規劃完成
建立狀態：未建立／建立中／已建立
完善狀態：未完善／完善中／已完善待驗收／已驗證
```

推薦顯示：

```text
【規劃完成／未建立／未完善】
```

正式建立後才可轉換：

```text
【規劃完成／建立中／未完善】
→
【規劃完成／已建立／未完善】
→
【規劃完成／已建立／已完善待驗收】
→
【規劃完成／已建立／已驗證】
```

## 六、與工程運作方案的接口

`2-方案/工程運作與持續改進方案-v1.1.md` 負責：

```text
規劃項目在哪裡
↓
目前狀態
↓
待辦
↓
順序
↓
依賴
↓
何時進入施工
```

本方案負責：

```text
開始施工時
↓
正式建立前必須做什麼
↓
哪些 Gate 必須通過
↓
何時 LOCK / ALLOW
```

兩者不可互相取代。

## 七、狀態與回傳成本

規劃成立時一次建立：

```text
狀態＋待辦＋依賴＋順序＋施工入口
```

之後只在工程意義發生變化時更新。

```text
微步驟 → 不記錄／不回傳
工作批次 → 必要時摘要
Gate → Checkpoint
重大狀態／新基準 → 完整同步
```

## 八、禁止事項

- 不得把規劃完成視為方案建立完成。
- 不得刪除「未建立／未完善」標記來讓文件看起來已完成。
- 不得從規劃文件直接跳過建立方案流程。
- 不得因規劃內容完整而跳過外部研究／比較／反方案檢查／Gate。
- 不得因微步驟更新狀態或回傳使用者。
