# 觸發條件管理系統 v1.1

日期：2026-09-17
狀態：【建立中；定位已調整；待實際運作驗證】

## 一、定位

本系統是 Trigger Registry（觸發索引／啟動保險層）。

唯一核心任務：

> 在正常工作流程可能漏掉應啟動系統時，提供第二層保險；確認目標系統尚未處理後，才補充啟動。

本系統不是主要工作流程的第一啟動源，不是問題解決系統，也不執行目標系統工作。

核心原則：**命中 Trigger ≠ 立即啟動。先確認狀態，再決定是否補充啟動。**

## 二、工作流程

```text
事件／問題／需求
↓
Trigger 匹配
↓
0 個 → 不啟動
1 個 → 取得 System ID
多個 → 保留候選並標記歧義，不自動全部啟動
↓
查詢目標系統狀態
↓
已啟動／執行中／已處理？
├─ 是 → 不再次啟動
└─ 否 → 再確認保險條件
          ↓
       補充啟動
          ↓
       記錄 Event ID／Trigger ID／System ID／結果
```

## 三、核心安全規則

### 1. 防二次啟動
同一事件、同一目標系統已有有效處理時，不得再次建立相同處理。

### 2. 觸發冪等性（Idempotency）
同一 Event ID 重複觀察或匹配，不得因此產生重複執行。

```text
Event ID → Trigger ID → System ID → 啟動／處理狀態
```

### 3. 防循環觸發
系統執行造成的狀態變更不得無限制重新觸發同一處理。若屬同一處理鏈，視為既有事件生命週期的一部分。

### 4. 多重匹配不等於多重啟動
>1 個候選時，預設標記歧義；除非已有明確、已驗證的多系統協作規則，不得全部啟動。

### 5. 不確定時不擴大啟動
無法確認是否已處理或是否仍需處理時，預設不重複啟動，轉交統御／問題解決流程判定。

## 四、最小資料

| 欄位 | 用途 |
|---|---|
| Trigger ID | 觸發條件身份 |
| 觸發條件 | 第一級匹配 |
| 目標 System ID | 正式目標 |
| 狀態 | 啟用／停用／待驗證／待更新 |
| Event ID／事件關聯 | 防重複與循環 |
| 啟動／處理狀態 | 判斷是否需要補啟動 |

系統名稱、位置、方案歸屬由 System Catalog 以 System ID 查詢，不在 Trigger Registry 建立第二份正式來源。

## 五、責任邊界

負責：觸發索引、第一級匹配、System ID 對應、啟動狀態確認、防二次啟動、基本循環防護、觸發關係記錄、失效標記。

不負責：完整問題判定、方案策略、目標系統內部流程、問題解決、中央事件總線、完整規則引擎、自動選擇多重候選最佳方案。

## 六、異常

至少辨識：無候選、過多候選、條件衝突、目標不存在、目標停用、已執行卻再次命中、同一事件反覆觸發、Trigger 過時或與系統狀態不一致。

## 七、驗證

自然工作案例至少驗證：

1. 正常流程已啟動 → Trigger 命中時不二次啟動。
2. 正常流程漏啟動 → Trigger 能補充啟動。
3. 同一事件重複出現 → 不產生重複執行。
4. 多重匹配 → 不自動全部啟動。
5. 執行後狀態變更 → 不形成無限循環。

未取得實際啟動與結果，不判定系統完成驗證。
