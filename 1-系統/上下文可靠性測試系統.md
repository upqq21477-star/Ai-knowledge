# 上下文可靠性測試系統

版本：v1.0
所屬方案：上下文成本與可靠性控制方案（候選）
核心能力：C04｜Context Reliability Test
狀態：【候選系統；待最小實測】

## 一、定位
測試 Context 大小與組成變化是否造成 AI 在理解、記憶、規則遵守與結論上的非預期漂移。

## 二、標準流程
~~~text
建立任務與預期規則
↓
建立 Context 基準
↓
控制單一變因
↓
執行多個 Context 梯度
↓
重複測試
↓
比較理解／Recall／規則／輸出
↓
分類合理變化與失真變化
↓
形成 Reliability Profile
~~~

## 三、控制變因
至少包括：
- Context 長度。
- 關鍵資訊位置。
- 無關資料比例。
- 重複資料。
- 規則位置。
- 歷史與目前狀態混合。
- 衝突資料。

## 四、測試結果
結果至少分：
- PASS：關鍵行為穩定。
- CONDITIONAL：特定 Context 條件下才可靠。
- FAIL：出現無法由證據／任務變化解釋的漂移。

不得用單次回答直接宣稱可靠。

## 五、接口
C03 提供 Context 梯度；C04 判斷可靠性；C05 分析輸出是否出現 Unsupported／Contradicted Claims。

## 六、最小驗證
以一個有明確規則與已知答案的任務測試：
短 Context、基準 Context、長 Context、過量 Context。

若無法形成可重現的差異分類，暫不升格。
