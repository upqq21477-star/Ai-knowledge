# 後續工作觸發式順便驗證系統 v2.0

狀態：**【新建立；候選小系統；待最小實測】**

## 1. 系統定位

本系統是一個獨立運作、規模很小的驗證能力單元，用於管理「未完成驗證但未來正常工作可能自然用到」的驗證標記。

它不是正式方案，也不是核心系統；其存在目的只有一個：**讓未完成驗證不被遺忘，並在正常施工自然遇到適用場景時順便完成驗證。**

本系統依照「小系統建立原則」建立：需求確認 → 現有能力盤點 → 外部方法／工具／案例比對 → 建立知識書 → 建立最小規格 → 最小實測 → 判定。

## 2. 核心問題

目前存在一類低成本但容易遺忘的驗證工作：某個系統、規則或能力現在知道需要驗證，但沒有必要立即專門安排測試；未來其他正常工作卻可能自然經過相同條件。

如果沒有標記，可能遺忘；如果每次都專門測試，又會製造不必要的工作。

因此需要一個最小機制，把「待驗證事項」掛在後續正常施工上。

## 3. 最小資料

每一個標記至少包含：

```text
ID
名稱
待驗證對象
驗證目的
觸發條件
預期可觀察結果
目前狀態
建立時間／來源
相關依賴
```

驗證完成後追加：

```text
實際觸發工作
實際操作
實際結果
差異
判定
驗證記錄
後續處理
```

## 4. 最小運作流程

```text
建立驗證標記
↓
正常進行其他工作
↓
讀取目前狀態／待辦／驗證標記
↓
分析本次工作是否可能自然觸發
├─ 無關 → 不觸發
└─ 可能觸發
    ↓
    檢查觸發條件與 Gate
    ├─ 不成立 → 保留標記，正常施工
    └─ 成立
        ↓
        同步完成最小驗證
        ↓
        比較 Expected / Actual
        ↓
        記錄結果
        ↓
        PASS / PARTIAL / FAIL
        ↓
        結束標記或建立後續處理
```

## 5. 「分析待辦清單」不是強制觸發

後續工作開始前，可以分析待辦清單與目前施工內容，尋找「本次工作是否可能順便驗證某個標記」。

但分析結果只是一個候選觸發判斷，不代表一定執行。

必須先確認：

- 本次工作本來就需要做。
- 驗證對象確實會被使用或自然經過。
- 驗證不會改變原工作目的。
- 不會違反施工 Gate。
- 能取得足夠結果判定資料。

## 6. 嚴禁事項

### 6.1 不得為了驗證而製造工作

如果近期沒有自然觸發條件，保持標記，不得強行安排一個無必要的任務。

### 6.2 不得把「使用」視為「PASS」

使用只代表可能觸發。只有記錄預期結果與實際結果並完成判定，才算完成驗證。

### 6.3 不得越過施工順序

驗證工作不能成為跳過 Gate 的理由。

### 6.4 不得因為標記存在而干擾主要任務

主要施工目的優先；順便驗證必須是附加成本很低的自然行為。

### 6.5 發現問題必須回到問題解決流程

如果驗證結果 FAIL，或發現新的結構性問題，本系統只負責記錄與轉送，不自行膨脹成問題解決系統。

## 7. 最小狀態機

```text
MARKED
  ↓
NOT TRIGGERED
  ↓
TRIGGERED
  ↓
PASS / PARTIAL / FAIL
```

允許：

- `MARKED → NOT TRIGGERED`
- `NOT TRIGGERED → TRIGGERED`
- `TRIGGERED → PASS`
- `TRIGGERED → PARTIAL`
- `TRIGGERED → FAIL`

`PARTIAL` 或 `FAIL` 不應直接被標成完成；應保留後續處理狀態。

## 8. 與其他系統的介面

### 輸入

- 目前狀態
- 待辦清單
- 施工階段與 Gate
- 驗證標記
- 目前工作內容

### 輸出

- 是否自然觸發
- 驗證執行記錄
- Expected / Actual 差異
- 驗證判定
- 後續處理建議

### 問題轉送

若發現問題：

`驗證結果 → 問題描述 → 問題解決系統`

不得在本系統內自行建立另一套問題解決流程。

## 9. 外部方法比對採用原則

外部方法顯示，成熟的 AI／系統管理框架普遍強調生命週期中的持續監控、測試、評估、驗證、記錄與改進。NIST AI RMF 明確要求持續進行風險管理、測量與管理，並記錄 TEVV 結果；NIST RMF 亦要求分析監控輸出並據此回應。citeturn0search4turn0search7

ISO/IEC 42001 則採用建立、實施、維護與持續改進的管理系統思路。citeturn0search0turn0search3

本小系統只抽取「持續觀察＋驗證＋記錄＋改進」的最小能力，不引入大型管理框架、固定資料庫、複雜排程或自動測試平台。

## 10. 第一個標記

```text
ID：SS-001-V-001
名稱：AI知識庫基本運作系統真實問題閉環測試
狀態：MARKED
觸發方式：後續正常系統更新／其他施工工作自然遇到適用條件時
要求：若本次工作自然可以完成閉環測試，直接同步執行並記錄；不得為此製造額外工作
```

## 11. 最小實測要求

本系統本身尚未因「文件建立完成」而視為成立。

第一次最小實測必須來自真實後續工作，至少觀察：

1. AI 是否會讀取待辦與標記。
2. AI 是否能判斷本次工作是否自然觸發。
3. 未觸發時是否保持標記而不製造工作。
4. 觸發時是否能在正常工作中同步驗證。
5. 是否記錄 Expected / Actual。
6. 是否能形成 PASS / PARTIAL / FAIL。
7. FAIL 時是否正確轉送問題解決流程。

在上述閉環完成前，本系統維持「候選小系統；待最小實測」狀態。
