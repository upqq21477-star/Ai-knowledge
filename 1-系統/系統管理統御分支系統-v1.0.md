# 系統管理統御分支系統 v1.0

日期：2026-09-17
狀態：【建立中；規則已建立；待最小實測】

## 一、系統目的

維護 Ai-knowledge 中所有現行／候選系統的最小身份、位置、狀態、方案歸屬、知識關係與功能摘要，讓其他能力可以快速定位與路由。

## 二、系統邊界

本系統負責：

- 系統身份。
- 系統目錄。
- 系統位置。
- 系統狀態。
- 方案歸屬。
- 關聯知識書。
- 功能摘要。
- 基本生命週期資訊。
- 依 System ID 接收觸發管理系統的轉交。
- 將系統路由至所屬方案。

本系統不負責：

- 專責系統的執行流程。
- 觸發條件本身的集中匹配邏輯。
- 問題解決方法。
- 方案內部協作細節。
- 全庫即時狀態控制。

## 三、核心資料

```text
System ID
系統名稱
文件位置
狀態
方案歸屬
功能摘要
關聯知識書
版本／生命週期
```

## 四、身份規則

System ID 是唯一正式系統身份。

系統名稱可以修改；位置可以移動；方案歸屬可以改變；這些變更不應自動建立新的 System ID。

只有實際代表另一個獨立系統時才建立新的 System ID。

## 五、基本操作

### 查詢

輸入 System ID、名稱、功能或方案條件，取得系統 metadata。

### 路由

```text
收到 System ID
↓
確認系統存在
↓
確認狀態
↓
取得方案歸屬
↓
交給方案
```

### 狀態檢查

如果系統為停用、暫停或廢棄，不得直接當作可執行能力；應回傳狀態並進入替代能力／問題解決流程。

## 六、觸發系統交接

```text
Trigger Registry
↓
System ID
↓
本系統
↓
方案歸屬
↓
方案
```

本系統不重新判斷「事件是否符合觸發條件」，只處理已取得的 System ID。

## 七、資料來源原則

本目錄是索引與 metadata 層，不是所有系統內容的唯一真實來源。

系統詳細規則仍以各系統文件為準；本系統只保存最小必要摘要與定位資料。

## 八、異常

以下情況應標記異常，不靜默修正：

- System ID 找不到。
- 文件位置不存在。
- 系統文件與目錄狀態不一致。
- 系統沒有明確方案歸屬且被要求直接路由。
- 方案已廢棄但目錄仍標示可執行。
- 同一 System ID 出現互相衝突的身份資料。

必要時交給問題解決系統。

## 十、第一版禁止

- 不建立大型 CMDB。
- 不建立完整依賴圖譜。
- 不把所有系統內容複製進目錄。
- 不自行執行專責系統。
- 不自行決定未知問題的解法。
- 不建立複雜自動優先級。

## 十一、驗證要求

目前只代表文件與規則建立完成。

尚需至少驗證：

1. 新增系統能否登錄。
2. 查詢能否快速定位。
3. System ID 能否穩定引用。
4. 系統移動後目錄能否更新。
5. 觸發系統交付 System ID 後能否正確路由到方案。
6. 無效／廢棄系統能否阻止錯誤路由。
