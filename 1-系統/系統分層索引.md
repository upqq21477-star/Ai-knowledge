# 系統分層索引

日期：2026-09-19
狀態：【CURRENT】

## 正式分層

| 層 | 責任 | Runtime 地位 |
|---|---|---|
| 00-核心入口 | 核心入口與最小控制契約 | 是 |
| 01-Skill | 可觸發、可執行的行為單元 | 是 |
| 02-System | 被 Skill 調用的系統能力與治理 | 間接 |
| 03-Spec | 規格、契約、介面、定義 | 依據 |
| 04-Evidence | 驗收、FIELD、Simulation、Audit | 按需查證 |
| 05-Research | 外部研究與候選材料 | 按需研究 |

## 本輪策略

先建立邏輯分層，不直接搬移既有 80 份文件。既有文件存在大量互相引用；未完成引用掃描就搬移會造成入口斷裂。

因此目前「原位置」仍是正式文件；新資料夾先作為責任邊界。完成引用掃描、Authority 核對與回歸驗證後，再進行實體搬遷。

## 判斷規則

- Skill：內容定義可觸發、可執行能力。
- System：長期可被調用的系統能力與治理。
- Spec：規格／契約／介面／定義。
- Evidence：FIELD／Simulation／Acceptance／Audit／Pressure Test。
- Research：外部比對與研究材料。

## Runtime 原則

Task → Skill Selection → 必要 System / Spec → 必要 Knowledge / Plan → Execution → Verification。
Evidence / Research 僅在需要查證、研究或回溯時載入。
