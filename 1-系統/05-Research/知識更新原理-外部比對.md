# 知識更新原理－外部比對

## 一、基本資料

- 知識名稱：知識更新原理
- 原文件：`0-知識/知識/知識更新原理.md`
- 比對日期：2026-09-16
- 狀態：`【已比對；待實測】`

## 二、問題定義

### 要解決的實際問題

新資訊、新證據、新觀察或條件變化出現時，如何判斷既有知識應維持、補充、修正、限縮、擴張、取代、新增或暫不採用。

### 為什麼現有做法不足

原文件方向正確，但偏重「不要直接覆蓋」與更新類型，對「更新前需要哪些判斷」、「最新不等於取代」、「更新後如何檢查依賴與系統影響」的界線仍可補強。

## 三、外部研究

### ISO 30401:2018／ISO/DIS 30401

- 類型：`國際標準`
- 主要觀察：知識管理系統不只建立內容，也包含實施、維護、審查與持續改善。
- 對本系統的意義：知識更新應被視為持續管理閉環，而不是一次性的文件覆蓋機制。
- 限制：ISO 標準針對組織知識管理系統，不能直接等同於個人 Markdown 知識庫的具體實作。

### Notion 官方文件：版本歷史

- 類型：`官方產品文件`
- 主要觀察：頁面提供版本歷史、過去版本檢視與還原機制；不同方案有不同歷史保留範圍。
- 對本系統的意義：內容維護需要可回溯能力；目前 GitHub 提交歷史已能提供基本回溯，因此不需要預先建立獨立版本資料庫。
- 限制：Notion 的產品機制不能直接作為 Ai-knowledge 的資料模型。

## 四、比較

| 項目 | 原有做法 | 外部共通做法 | 判定 |
|---|---|---|---|
| 更新觸發 | 新資訊出現 | 新資訊、審查、實際使用與變更都可能觸發 | 補充 |
| 更新判斷 | 比較來源、條件與差異 | 先確認內容與適用條件，再決定維護方式 | 保留並細化 |
| 最新資料 | 未明確說明不能直接取代 | 版本歷史與持續維護並不等於所有新內容自動取代舊內容 | 補強 |
| 更新類型 | 修正、補充、擴張、限縮、取代、新增、待確認 | 不同系統採不同維護機制，但共同存在版本／變更管理 | 保留 |
| 歷史 | 必要時保留 | 成熟工具通常提供歷史與還原 | 保留 |
| 影響檢查 | 原文件已有基本概念 | 知識管理強調持續維護與審查 | 補強 |
| 自動化 | 暫不建立 | 工具可提供自動版本保存，但不代表自動判斷知識語義 | 暫不採用 |

## 五、分析結果

### 共通原理

1. 知識維護是持續循環，而不是一次性建立。
2. 變更保存與內容判斷是兩個不同問題。
3. 新資料需要經過判斷後才能成為目前採用內容。
4. 歷史與目前版本可以同時具有價值。
5. 實際使用結果可以反向觸發知識審查與更新。

### 重要差異與適用條件

組織型知識管理框架關注治理、審查與持續改善；Ai-knowledge 目前主要需要的是低成本、可追溯的個人知識更新流程。因此只採用其共通管理原理，不建立組織治理層級。

### 原文件遺漏

- 「最新」不能單獨作為取代依據。
- 更新後應檢查受影響的知識與 `1-系統`。
- GitHub 現有提交歷史已能承擔基本版本保存，不必立即建立新版本資料庫。

### 原文件過度簡化

原文件把更新主要描述成「新資訊 → 更新判斷」，需要進一步明確區分來源、主張、證據、條件與狀態。

### 過度工程化風險

若現在建立完整知識版本資料庫、自動依賴分析或自動級聯更新，會在尚未證明實際成本前增加維護成本，因此暫不採用。

## 六、設計決定

- 決定：`修改並保留核心原理`

### 決定內容

將更新原理改成「比較與判斷 → 更新 → 影響檢查 → 實際驗證」的閉環；明確區分文件變更、知識變更與狀態變更；保留 GitHub 提交歷史作為目前基本版本能力。

### 不採用其他方案的理由

目前沒有證據證明需要獨立版本資料庫、完整自動依賴分析或自動級聯更新。

## 七、知識整合影響

本知識與以下知識直接相關：

- `來源與證據` → 支撐更新前的可信判斷。
- `知識比較原理` → 提供新舊內容差異判斷。
- `知識衝突判定` → 判斷差異是否真正不能同時成立。
- `資料狀態模型` → 區分內容與目前採用狀態。
- `知識整合系統` → 更新後檢查依賴、約束與受影響系統。

## 八、實際驗證

### 目前結果

已使用 Ai-knowledge 現有文件維護流程檢查：

- 文件修改與知識更新確實可以分開。
- 外部比對完成後仍可維持「待實際驗證」狀態。
- GitHub 提交歷史可以提供基本回溯。

### 尚未驗證

- 所有實際更新案例是否都能落入目前八種更新類型。
- 重大更新與小型修改的界線。
- 長期使用後是否需要結構化更新索引。

## 九、結論

目前原理可以保留，但需要以「持續維護閉環」取代單純「覆蓋舊知識」的理解。

最小閉環為：

```text
新資訊／新證據／新觀察
↓
來源與內容確認
↓
比較
↓
差異／衝突判定
↓
更新決定
↓
目前知識更新
↓
影響檢查
↓
實際驗證
↓
必要時再次更新
```
