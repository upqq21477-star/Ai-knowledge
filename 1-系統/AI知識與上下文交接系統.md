# AI知識與上下文交接系統

版本：v2.0
所屬方案：方案二｜AI知識管理
狀態：【融合後單一入口；待真實工作驗證】

## 一、定位
整合「AI知識管理」「AI上下文與交接」以及與其高度重疊的基本運作／自然驗證／實測回寫能力，形成 AI 從接收任務到完成、驗證、交接與回寫的單一工作入口。

核心原則：大記憶，小 Context；完整歷史，乾淨 CURRENT；先完成工作，再留下可重建結果。

## 二、核心流程
```
任務
↓
理解問題／目標／限制
↓
確認目前狀態、Gate、待辦
↓
判定需要的知識／狀態／記憶／能力
↓
搜尋／研究
↓
來源與證據判斷
↓
組裝最小充分 Context
↓
執行
↓
Expected vs Actual
├─ 正常 → 判定結果 → 回寫
└─ 異常 → 分類／嚴重度／影響 → 問題解決流程
↓
重新驗證
↓
更新 CURRENT／交接資料／必要記錄
```

## 三、交接
無歷史記憶的 AI 必須能依 Repository 恢復：
- 目前階段與目標。
- CURRENT 與歷史邊界。
- 允許／禁止事項。
- 已有能力與可用系統。
- 下一個合法工作。
- 必要的上下文，而非整庫全文。

讀取原則：
```
先讀交接入口
→ 目前狀態
→ 規則／Gate
→ 任務相關資料
→ 不足才擴大
→ 足夠即停止
```

## 四、工作守門
開始工作前檢查：
目前階段、目標、前置條件、Gate、禁止事項、依賴。
不得因使用者要求「繼續」就越過 Gate。

## 五、驗證與自然觸發
未完成驗證可建立最小驗證標記；正常工作若自然遇到適用條件，可同步完成驗證，但不得為驗證製造額外工作。

「使用到」不等於 PASS。必須有：
問題／條件／預期／實際觸發／實際執行／結果／差異／判定／後續處理。

實測宣稱至少分：
- PASS：核心證據完整。
- INCOMPLETE：有執行但證據不足。
- NOT-A-TEST：只有規劃、研究或模擬。

## 六、異常處理
異常不得靜默吞掉。至少記錄：
問題、Expected/Actual 差異、影響、嚴重度、處理決策。
L2/L3 或結構性問題轉入「問題解決、方案與新系統建立流程」。

## 七、最小工作收據
```
任務／問題
→ 使用條件
→ 使用知識／來源
→ 執行
→ 預期
→ 實際
→ 差異／異常
→ 判定
→ 後續處理
→ 最終狀態
```

## 八、責任邊界
本系統負責「AI 如何接手並完成一輪工作」。
不取代：
- 整體資料治理。
- 研究／搜尋。
- 來源與證據判斷。
- 長期知識演化。
- 問題解決內部研究流程。

## 九、驗收目標
1. 無記憶 AI 可恢復狀態。
2. 可取得最小充分 Context。
3. 可自主完成一個完整工作單位。
4. 正確區分正常／異常。
5. 異常能正確路由。
6. 實測證據可重建。
7. 結果能回寫 CURRENT。
8. 不因驗證機制增加不必要工作。

## 十、禁止
不因文件存在宣告驗證完成；不把搜尋結果當知識；不把使用當 PASS；不為驗證製造工作；不越過 Gate；不因單次異常自動建立大型系統。
