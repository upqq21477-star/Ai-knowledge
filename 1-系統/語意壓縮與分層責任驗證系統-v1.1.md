# 語意壓縮與分層責任驗證系統

版本：v1.1
核心能力：Semantic Compression & Layer Validation
狀態：【候選 System；研究深化後版本】

## 功能

將 Knowledge／System／Solution 原始版本與候選壓縮版本進行分層語意分析，找出最小充分語意，並驗證壓縮是否破壞身份、路由、功能、依賴、結果解讀、驗收或證據追溯。

## 輸入

- 原始文件
- 壓縮候選
- 所屬層級
- 任務／方案目的
- 驗收條件
- 測試 Context

## Knowledge

使用：
0-知識/語意壓縮與分層責任原理-v1.1.md

## 執行

1. 建立 Semantic Map。
2. 為每段語意指定責任層。
3. 分類不可刪／可移交／可合併／冗餘。
4. 建立壓縮版本。
5. 對照原版檢查身份、路由、功能、依賴、結果、驗收、證據。
6. 對 evidence-bearing semantics 提高保留優先級。
7. 定位任何缺失語意。
8. 只補最小必要語意。
9. 重測。

## 輸出

- Semantic Map
- Layer Assignment
- Compression Result
- Missing Semantic
- Evidence Preservation Result
- Validation Result
- Token／Context Difference
- Error Classification

## 固定失敗條件

以下任一改變即視為壓縮失敗：
- System／Solution 身份
- 路由
- 核心功能
- 必要依賴
- 結果解讀
- 驗收分類
- 重要證據追溯

## Evidence 驗證

不能只驗收最終答案。
需要檢查重要主張是否仍能正確映射至 Evidence。

## 邊界

本 System 不決定特定方案目的。
不自行制定方案驗收。
不取代 Knowledge。
不自行選擇正式組／對照組。

## 驗證模式

至少比較：
A 完整組
B 分層壓縮組
C 過度壓縮組

相同 Knowledge、相同任務、盡量相同測試條件。

測量：
Token、路由、功能、語意失真、Grounding、Evidence Mapping、驗收、Context-induced Error。

## 原則

> 先判定語意所有權，再進行語意壓縮。

> 先保留會影響證據與結果解讀的語意，再壓縮背景與冗餘。

## 注意

任何內部模擬結果不得直接宣稱為真實模型可靠率。
