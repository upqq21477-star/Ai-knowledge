# 系統與小系統統御管理系統

版本：v1.0
所屬方案：方案四｜能力蒸餾與系統重構
狀態：【融合後候選統御系統；待實際施工驗證】

## 一、定位
融合原「系統管理統御分支」「系統管理統御分支系統」「統御方案系統」「統御小系統協調管理系統」的共同責任。

本系統只處理：
- 系統／小系統身份與最小目錄。
- 系統位置、狀態、方案歸屬與主要關係。
- System ID 路由。
- 未歸屬小系統的最小觸發／協調。
- 小系統納入方案後的觸發權移交。
- 統御層的最小狀態檢查。

不執行專責系統的業務邏輯，也不建立大型中央治理引擎。

## 二、核心流程
```
事件／工作
↓
確認相關 System ID／Small System
↓
查詢身份、位置、狀態、方案
↓
判斷責任歸屬
├─ 已歸屬方案 → 路由至方案
└─ 未歸屬小系統 → 檢查自然觸發條件
                         ↓
                     成立才交由小系統執行
↓
取得結果
↓
必要時更新目錄／狀態／歸屬
```

## 三、最小目錄
每個系統原則上維持一個穩定 System ID：
- System ID
- 正式名稱
- 文件位置
- 狀態
- 方案歸屬
- 功能摘要
- 主要知識／關係入口
- 版本／生命週期參考

詳細內容仍以系統本體文件為準。

## 四、身份規則
名稱、路徑、版本或方案歸屬變更，不應自動產生新 System ID。
只有真正代表另一個獨立系統時才建立新 ID。

同名但不同 Identity／Kind 的對象必須可以區分。

## 五、路由規則
```
Trigger／事件
→ System ID
→ 本系統查詢
→ 方案／系統
```

本系統不重新發明 Trigger Registry；已知觸發條件由其專責機制提供。

已歸屬方案的系統，由所屬方案承擔其正常工作；本系統只維持索引。

## 六、未歸屬小系統
對尚未納入正式方案的小系統，只保留最小協調責任：
- 是否存在待驗證標記。
- 本次正常工作是否自然符合條件。
- 是否允許交給小系統執行。
- 結果與後續狀態。

不得為驗證製造工作，不得因小系統存在強制升格。

## 七、方案歸屬移交
小系統正式納入方案後：
```
確認方案已有完整承接
↓
比較原觸發與方案觸發
↓
完整涵蓋 → 移交
部分涵蓋 → 保留必要原責任並明確邊界
↓
統御索引只保留身份／狀態／歸屬
```

## 八、異常
以下情況不得靜默修正：
- System ID 找不到。
- 文件位置不存在。
- 目錄與系統本體狀態不一致。
- 無方案歸屬卻被要求直接當正式能力使用。
- 已停用／廢棄系統仍被路由。
- 同一 Identity 出現衝突資料。
必要時轉入問題解決流程。

## 九、與共同對象與關係目錄的邊界
共同對象與關係目錄負責跨方案通用的 Object Identity / Relationship 語義。
本系統只管理「系統／小系統作為工程對象」的最小目錄與路由。

兩者不建立第二份全庫 Identity 真相。

## 十、驗收
至少驗證：
1. 新系統可登錄並定位。
2. 改名／搬移仍維持同一 Identity。
3. 可查詢方案歸屬與狀態。
4. Trigger 交付 System ID 後可正確路由。
5. 無效／廢棄系統不會被錯誤路由。
6. 未歸屬小系統可在自然工作中正確觸發。
7. 小系統納入方案後不產生雙重觸發。
8. 目錄與系統本體不一致時能發出異常。

## 十一、禁止
不建立大型 CMDB／知識圖譜；不複製所有系統內容；不取代方案；不執行專責系統；不把 Trigger、問題解決、治理或全庫即時狀態全部集中到本系統。

## 十二、成立條件
文件存在不等於系統成立。至少取得真實施工案例後，才能判定是否保留為獨立系統、降級為共用能力或再次融合。
