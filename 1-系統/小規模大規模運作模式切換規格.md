# 小規模／大規模運作模式切換規格 v1.0

版本：v1.0
日期：2026-09-19
狀態：【正式創建；Small Mode 啟用；Large Mode 介面預留】

## 1. 定位

本文件定義本系統的「運作模式（Operating Mode）」。

核心原則：

> 小規模現在採輕量模式；架構介面先預留；大規模時切換運作模式，而不是重新設計整套系統。

因此 Small Mode 與 Large Mode 不是兩套系統，而是同一套 Skill 架構的兩種運作方式。

## 2. 不變的核心

無論 Small Mode 或 Large Mode，以下內容不得因模式切換而改變：

- Problem 定義
- Responsibility
- Skill 定義
- Skill ID
- Trigger
- Input / Output
- Mode
- Dependency
- Verification
- Failure Pattern
- Lifecycle
- Provider / Tool 邊界

模式只改變「如何找到、選擇、組合與載入 Skill」，不改變 Skill 本身代表什麼。

## 3. Small Mode：目前正式運作

目前使用 Small Mode。

流程：

Task
→ Task Understanding
→ Problem Triage
→ Context Selection
→ Agent 直接 Skill Selection
→ Skill / Mode Execution
→ Verification
→ Replan（必要時）

### Small Mode 特性

- Agent 直接選 Skill。
- 使用既有 Markdown Skill Definition。
- 以檔案索引與明確路由條件輔助檢索。
- 不建立獨立 Skill Registry Runtime。
- 不建立 Embedding / Vector Database。
- 不建立自動 Ranking Engine。
- 不建立動態 Composition Engine。
- 不建立常駐 Runtime。
- 優先降低 Context 與維護成本。

## 4. Large Mode：只預留介面

Large Mode 不在目前建立完整 Runtime。

預留流程：

Task
→ Task Understanding
→ Problem Triage
→ Problem Decomposition
→ Capability Retrieval
→ Skill Candidate Retrieval
→ Skill Ranking
→ Skill Composition
→ Context Retrieval
→ Execution
→ Verification
→ Telemetry
→ Replan

目前只固定上述介面與資料契約，不提前實作大型基礎設施。

## 5. 模式介面

### Input

兩種模式均接受：

- Task
- Context
- Candidate Skills（若已知）
- Provider / Tool constraints
- Verification requirements

### Output

兩種模式均輸出：

- Selected Skill / Skills
- Selected Mode
- Execution Result
- Verification Result
- Failure Classification（若失敗）
- Replan Requirement（若需要）

### 差異

Small Mode：

Agent → 直接選擇

Large Mode：

Problem → Capability → Candidate Skills → Ranking → Composition → 選擇

因此 Large Mode 是增加「選擇基礎設施」，不是重新定義 Skill。

## 6. Large Mode 擴展介面

預留以下模組：

G01 Skill Registry
G02 Capability Registry
G03 Candidate Retrieval
G04 Skill Ranking
G05 Skill Composition
G06 Dependency Resolution
G07 Routing Telemetry
G08 Automated Candidate Filtering

目前狀態：

- 介面：保留
- 資料契約：保留
- Runtime：未建立
- 自動化：未建立

## 7. 切換觸發

不得使用單一 Skill 數量作為自動切換門檻。

進入 Large Mode 評估的依據：

### Routing

- Skill Selection 錯誤反覆發生。
- Skill Overlap 開始造成大量衝突。
- 人工選擇已成為主要成本。

### Context

- 為選 Skill 必須載入大量無關文件。
- Context Cost 開始成為主要瓶頸。

### Composition

- 單一任務經常需要多個 Skill。
- Skill 組合順序開始無法由固定 Workflow 穩定處理。

### Maintenance

- Skill Mapping 維護成本明顯上升。
- Dependency / Lifecycle 無法靠目前索引管理。

只有實際使用資料支持時才切換。

## 8. 切換流程

Small Mode
→ 收集 Usage / Failure / Cost
→ Evidence / Verification
→ 判斷瓶頸
→ Research D3（若屬結構性變更）
→ 確認 Large Mode 必要性
→ 建立所需 Infrastructure
→ 驗證
→ 切換

禁止：

直接因「未來可能變大」而提前建立大型 Runtime。

## 9. 相容性要求

切換到 Large Mode 時：

1. 讀取既有 Skill Definition。
2. 保留既有 Responsibility。
3. 保留既有 Trigger。
4. 保留既有 Input / Output。
5. 保留既有 Verification。
6. 只增加 Retrieval / Ranking / Composition 等基礎設施。
7. 若必須改變 Skill 語義，先進入 Skill Classification → Evolution → Execution → Verification。

不得以 Large Mode 為理由直接重寫既有 Skill。

## 10. 失敗處理

Small / Large 均使用同一 Failure Classification：

- Data
- Context
- Research
- Routing
- Skill
- Provider
- Execution
- Verification

失敗後：

Failure
→ Classification
→ Diagnosis
→ Replan
→ 必要時重新選 Skill / Mode
→ Verification

如果 Large Mode 的失敗主要來自其自身成本或複雜度，允許退回 Small Mode。

## 11. 驗證指標

模式切換前後至少比較：

- Context Cost
- Routing Cost
- Execution Cost
- Verification Cost
- Maintenance Cost
- Failure Rate
- Replanning Frequency

Large Mode 只有在實際降低主要瓶頸時才保留。

## 12. 與 Skill 建立流程的關係

建立新 Skill 不等於切換 Large Mode。

新 Skill：

Research D3
→ Skill Classification
→ NEW / MERGE / UPDATE / REPLACE / DEFER
→ Evolution
→ Execution
→ Verification
→ Feedback

Small Mode 仍可建立正式 Skill。

Large Mode 只是未來改變 Skill 的「檢索與組合方式」。
