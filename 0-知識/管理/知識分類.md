# 知識分類

## 定義

知識庫的分類是將資料依主要使用目的與功能組織，使資料容易理解、探索、搜尋、維護與重用。

分類是邏輯結構；資料夾是目前在 Ai-knowledge 中採用的實體實作。

## 目前 Ai-knowledge 的分類原則

`0-知識/` 不再把「知識」本身當成一個多餘的中間資料夾。第二層資料夾直接表示目前已經實際需要的功能分類。

```text
0-知識/
├─ 分類/
├─ 管理/
├─ 搜尋/
├─ 證據/
├─ 比較/
├─ 更新/
├─ 系統/
└─ 上下文/
```

上述新分類中，只有已經有實際資料且能明確對應既有功能需求者才建立；不預先建立空資料夾。

## 舊結構

目前 repository 曾存在：

```text
0-知識/知識/
```

其中混合了搜尋、上下文、知識定義、來源證據、比較、更新、系統等不同功能。

這是過渡結構，不應繼續作為長期分類。

## 整理原則

1. 不依主題熱度建立分類。
2. 不混用功能、狀態、領域與資料性質作為同一層目錄。
3. 同一功能的原理放在同一功能分類。
4. 一份文件若跨多個功能，依主要使用目的歸類，其他關係由文件內容與引用表達。
5. 不因工具支援標籤、屬性或關係就預先建立這些機制。
6. 不建立沒有實際文件的分類。
7. 若現有分類無法合理容納文件，先記錄案例，再判斷是否需要新分類。
