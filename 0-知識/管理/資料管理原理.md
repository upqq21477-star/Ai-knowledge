# 資料管理原理

狀態：**【已完成外部比對；待實際資料驗證】**

## 一、目的

資料管理的目的，是讓資料能被保存、找到、理解、更新與持續使用，而不是單純增加文件數量。

## 二、管理對象

資料管理需要處理至少以下問題：

- 資料放在哪裡
- 資料屬於什麼性質
- 資料如何分類
- 如何找到資料
- 如何判斷資料目前狀態
- 如何更新資料
- 如何避免新舊資料互相覆蓋或產生誤解

這些是不同功能，不能全部視為同一個分類問題。

## 三、功能導向

`0-知識` 的知識文件是建立後續系統功能的基礎原理。

因此管理、分類、搜尋等功能應分別建立所需原理，再由 `1-系統` 將這些原理組合成可運作的系統。

```text
基礎原理
↓
功能
↓
系統
↓
軟體
```

## 四、管理與分類的關係

分類是管理的一部分，但管理不等於分類。

```text
資料管理
├─ 分類
├─ 探索
├─ 搜尋
├─ 狀態管理
├─ 更新
└─ 其他實際需要的功能
```

因此不能把所有管理相關知識全部放入「分類」，也不能把所有知識都視為「管理」。

## 五、管理與結構化描述

資料管理可以利用多種機制完成，包括目錄、文件內容、結構化屬性、標籤、關係與查詢。

這些機制不是互相取代的關係，而是依需求分工。

目前 Ai-knowledge 以 Markdown 與目錄為主要承載方式；只有當實際使用證明純文字與目錄不足以降低管理成本時，才增加結構化機制。

## 六、最小化原則

目前只建立已經有實際需求的管理原理。

不預先建立：

- 複雜資料庫
- 知識圖譜
- 自動分類引擎
- 全自動資料治理
- 複雜版本管理

只有當實際使用產生明確成本時，才新增相應機制。

## 七、與其他知識的關係

資料管理位於多個管理能力的上位層，但不取代這些能力：

```text
資料管理原理
├─ 分類原理
│  └─ 分類與目錄
├─ 資料探索
├─ 搜尋原理
├─ 資料狀態模型
└─ 知識更新原理
```

它們共同支撐 `1-系統/知識整合系統.md` 與後續其他系統。

## 八、外部比對結果

外部成熟工具支持將內容、型別、屬性、標籤、關係與動態查詢分開處理。這支持本文件把資料管理視為「確保資料可持續使用的上位工作」，而不是單一分類機制。
