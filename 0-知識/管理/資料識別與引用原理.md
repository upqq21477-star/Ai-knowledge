# 資料識別與引用原理

狀態：**【初版建立；待三方案實際建立後驗證】**

## 一、目的

當知識、記憶、來源、證據、系統與方案數量增加後，AI 必須能知道「正在談的是哪一份資料」，也必須能從一份資料追到相關資料。

因此需要區分：

```text
資料內容
資料識別
資料引用
資料關係
```

## 二、識別的目的

識別不是單純替檔案取名字，而是讓一項資料能在不同文件、版本與流程中被穩定指認。

理想狀態：

```text
同一資料
↓
不同文件引用
↓
仍能判斷是同一對象
```

## 三、檔名不是唯一識別

檔名屬於承載形式。

例如：

```text
知識 A
├─ 檔名：知識A.md
├─ 版本：v1.0
└─ 內容識別：同一知識對象
```

檔名可能因目錄整理而改變，但資料對象不一定因此改變。

反過來，同一檔名也可能在不同版本代表不同內容。

## 四、引用的最低語義

引用至少應讓使用者或 AI 知道：

1. 引用了哪一個資料對象。
2. 引用的是目前版本還是特定歷史版本。
3. 引用的目的或上下文（若有必要）。

不要求所有引用都建立複雜資料庫。

## 五、引用與複製不同

```text
引用
＝指向既有資料

複製
＝建立另一份內容
```

若兩份資料只是引用關係，不應因複製文字就誤判成兩個獨立知識來源。

## 六、引用與關係不同

引用表示「這裡需要使用另一份資料」。

關係表示「兩個資料對象之間具有某種語義連結」。

例如：

```text
方案文件引用知識 A
```

不代表方案與知識 A 一定具有某一特定關係；具體關係仍需另外判定。

## 七、識別穩定性的原則

識別方式應優先滿足：

- 穩定
- 可追溯
- 不依賴單純顯示名稱
- 能與版本區分
- 能被其他資料引用

但目前不固定 UUID、資料庫 ID 或其他技術方案。

## 八、與版本的關係

資料識別與版本識別必須能區分：

```text
資料對象 A
├─ v1.0
├─ v1.1
└─ v2.0
```

如果引用的是「A」而不是特定版本，使用時需要依目前有效狀態判定應採用哪一版。

如果引用的是特定版本，則不應因目前版本更新而自動改變引用語義。

## 九、與三方案的關係

治理負責共同識別與引用原則。

AI 知識管理方案負責在搜尋、上下文與交接中使用引用。

知識迭代與資料演化方案負責處理識別對象在版本演化、拆分、融合或遷移時的追蹤問題。

## 十、目前不建立的內容

暫不固定：

- UUID 規格
- 資料庫主鍵
- 全域引用 API
- 自動引用修復
- 自動引用重寫
- 完整知識圖譜

待實際方案建立後，只有當真實案例證明需要，才進一步正式化。
