# 資料生命週期與有效性最小原則

版本：v1.0  
狀態：【候選知識；已完成外部方法比對；待實際案例驗證】  
日期：2026-09-17

## 一、目的

定義共同資料模型中「生命週期（Lifecycle）」與「有效性（Validity）」的最小語義，避免把生命週期、目前狀態、版本、歷史保存混成同一個欄位。

本原則服務於四方案共同資料層，不建立獨立生命週期管理系統。

## 二、核心區分

```text
Identity   = 這是哪一個對象
Version    = 同一對象的哪一次演化
State      = 目前處於什麼工作狀態
Lifecycle   = 這個對象在其生命週期中的階段
Validity   = 目前是否可以被某項工作合法／有效地使用
History    = 過去發生過什麼
```

以上概念可以互相關聯，但不可互相取代。

例如：

- `deprecated` 是生命週期訊號，不代表資料不存在。
- 歷史版本可以仍然可追溯，但不代表它仍是目前工作資料。
- 一個對象可以仍存在，但對某一任務已經無效。
- `active` 不應直接等同於「任何情況都可以使用」。

## 三、最小生命週期模型

不預設所有資料都必須使用完全相同的生命週期狀態。共同層只要求能表達以下語義：

```text
candidate
→ active
→ deprecated / superseded
→ retired
→ archived
```

其中：

- `candidate`：尚未成為穩定工作對象。
- `active`：目前可作為正常工作對象。
- `deprecated`：仍可追溯，但已明確不鼓勵新使用。
- `superseded`：已有新的對象／版本取代其工作角色。
- `retired`：退出正常工作流程。
- `archived`：為歷史、稽核或追溯目的保存。

這些不是強制所有物件都依序經過的固定狀態機；不同物件可採用不同子集合，但任何自訂狀態都必須有明確語義。

## 四、Validity 不等於 Lifecycle

有效性應至少考慮：

```text
對象身份
+ 版本
+ 目前狀態
+ 使用條件
+ 時間
+ 依賴／關係
+ 任務情境
```

因此「這份資料目前存在」不足以回答「這次任務能不能用」。

共同資料層應保存必要條件，而不是建立一個巨大中央規則引擎替所有方案裁決適用性。

## 五、外部方法比對

Backstage Software Catalog 將 lifecycle 作為獨立語義，並以 `experimental / production / deprecated` 等狀態描述生命週期；其 Catalog 同時保留實體、關係與來源處理流程。這支持「生命週期是對象語義之一，而不是直接拿檔案存在與否代表生命週期」的方向。

Kubernetes／Backstage 所採用的物件語義也將 metadata、狀態與版本／更新語義分開處理，因此不宜把 Identity、Version、State、Lifecycle 壓成單一欄位。

參考：
- Backstage Software Catalog： https://backstage.io/docs/features/software-catalog/
- Backstage Descriptor Format： https://backstage.io/docs/features/software-catalog/descriptor-format/
- Backstage Life of an Entity： https://backstage.io/docs/features/software-catalog/life-of-an-entity/

## 六、不可直接推出的結論

不能因為成熟工具存在 lifecycle，就直接建立一套全域 Lifecycle Engine。

目前只建立共同語義，先以實際案例驗證：

1. 系統停用後，Trigger 是否能判斷目標已不可正常啟動。
2. 舊知識被新知識取代後，搜尋是否仍能找到歷史資料但避免誤當目前資料。
3. `deprecated` 與 `archived` 是否在實際工作中需要不同處理。
4. 同一對象在不同方案中的 lifecycle 是否真的需要不同表示。
5. lifecycle 與 State、Version 混用是否會造成實際錯誤。

## 七、最小驗證方法

選取至少一個真實系統與一個真實知識案例，記錄：

```text
Identity
Version
State
Lifecycle
Validity
History
實際使用結果
是否發生誤用／誤判
```

若沒有實際工作觸發，不製造獨立測試；依「後續工作觸發式順便驗證」原則等待自然案例。

## 八、禁止事項

- 不以檔案存在／不存在直接代表生命週期。
- 不以單一 `status` 欄位同時承擔 State、Lifecycle、Validity。
- 不因生命週期概念存在就建立中央生命週期引擎。
- 不自動刪除 retired / archived 對象。
- 不把 deprecated 等同於錯誤或無價值。
- 不在沒有實際案例前固定所有物件的完整狀態機。
