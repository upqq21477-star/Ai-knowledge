# 知識與系統的證據閉環原則

日期：2026-09-17
狀態：【候選知識；已完成問題分析；待實際施工驗證】

## 一、核心原則

知識與系統不是同一層級，也不是同一種變化速度。

### 知識 Knowledge

知識是可跨問題重複使用的相對穩定原理、規律、定義、方法與適用條件。

其特徵：

- 穩定性通常高於系統。
- 可以被修正、限制、取代或淘汰，但不能因單一新案例就任意修改。
- 外部研究只能提供候選內容與證據，不能直接把外部資料視為本 repository 的正式知識。
- 實際使用與驗證可提高或降低其可信度，並形成後續修正依據。

### 系統 System

系統是將知識、規則、資料、流程與判斷組合成可實際執行能力的結構。

其特徵：

- 可以隨需求、實測結果與架構演進增加、減少、重組或淘汰。
- 系統文件存在不代表系統能力成立。
- 必須確認正確觸發、實際執行、結果產生與結果驗證。

## 二、外部研究的正確位置

外部研究是建立候選知識、候選方法與候選系統設計的輸入，不是問題解決的終點。

正確流程：

```text
問題
↓
外部研究／比較
↓
形成候選知識與候選方法
↓
建立或整理必要知識
↓
建立系統
↓
實際使用
↓
產生本專案自己的觀察／數據
↓
驗證結果
↓
修正系統
↓
必要時重新檢驗知識
```

外部資料與本專案實測資料不得混為同一證據層級。

## 三、禁止的程序替代

以下均不得視為完整問題解決：

```text
外部研究完成 ≠ 問題已解決
外部案例存在 ≠ 本系統已驗證
知識書建立 ≠ 系統已成立
系統規劃完成 ≠ 系統已執行
系統曾執行 ≠ 結果正確
文件 PASS ≠ 真實工作 PASS
```

## 四、最小證據閉環

對需要建立新系統的問題，至少要形成：

```text
問題
→ 候選知識／方法
→ 系統
→ 正確觸發
→ 實際執行
→ 結果／數據
→ 驗證
→ 系統修正或採用
```

只有完成這個閉環，才能宣稱該解法已取得本專案自己的實證資料。

## 五、適用範圍

本原則適用於方案建立、系統建立、小系統建立、問題解決、搜尋研究、知識建立與方案整體驗證。

本文件目前是候選知識；必須在後續真實施工中驗證其可重複性與邊界。
