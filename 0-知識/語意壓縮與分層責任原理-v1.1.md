# 語意壓縮與分層責任 Knowledge

版本：v1.1
狀態：【候選 Knowledge；研究深化完成】

## 1. 分層責任原理

Knowledge：原理、規則、事實、證據、判定依據。
System：可重複能力、固定依賴、固定結果契約。
Solution：特定任務目的、路由、組合、邊界、驗收。

核心：
> 同一語意只在真正需要它的層保存一次。

## 2. 最小充分語意

壓縮目標不是最短文字，而是最小仍能保持：
身份、決策、執行、結果解讀、驗收、證據追溯。

## 3. 語意分類

A 不可刪：刪除會改變身份、路由、功能、依賴、結果解讀、驗收或證據追溯。

B 可移交：本層不必保存，但必須在正確責任層明確保存。

C 可合併：可由短契約、代碼、固定結構表示。

D 冗餘：刪除不影響上述能力。

## 4. System 最小契約

身份、功能、必要依賴、結果。

其中固定成立的結果解讀契約屬 System；僅屬特定方案的驗收分類可由 Solution 保存。

## 5. Solution 最小契約

目的、路由、邊界、依賴、驗收。

正式組／對照組等身份差異必須明確，不得要求模型自行推測。

## 6. Knowledge 最小契約

原理、規則、證據、判定依據。

## 7. 結果語意

結果名稱不等於結果語意。

若結果分類會影響結論，最低必要判定語意必須存在於可可靠取得的位置。

例如：
Unsupported 不等於 Hallucination。

## 8. Evidence-bearing Semantics

涉及以下內容的語意壓縮優先級最低：
- 證據
- 來源
- 主張
- 限定條件
- 例外
- 分類邊界

理由：2025 EMNLP 研究指出資訊保存與 grounding 必須獨立於 compression ratio 評估；2026 evidence-aware RAG 研究更顯示答案品質可維持而 grounding 大幅下降，因此答案正確不能取代證據驗收。citeturn0search0turn0search8

## 9. Context 不等於單一文件

模型可見 Context 包含 system prompt、問題、檢索資料、歷史、工具輸出等；因此壓縮必須考慮內容選擇、結構、順序與工具／記憶整合，而非只刪 Markdown 字數。citeturn0search3

## 10. 壓縮判定

依序檢查：
1. 身份
2. 路由
3. 功能
4. 依賴
5. 結果解讀
6. 驗收
7. 證據追溯

若受影響：
- 固定能力契約 → System 保留。
- 方案情境 → Solution 保留。
- 原理／事實／證據 → Knowledge 保留。

## 11. 最小修正

錯誤 → 定位缺失語意 → 判定責任層 → 補最小語意 → 重測。

禁止因單次錯誤恢復完整原文。

## 12. 評估軸

不能只測 compression ratio。
至少測：
Token／Context 成本、任務成功、路由、功能、語意失真、Grounding、Evidence Mapping、驗收、Context-induced Error。

外部研究同樣支持同時衡量成本、下游表現、grounding 與資訊保存。citeturn0search1turn0search0

## 13. 目前內部證據

50 次結構化模擬：
- 初始壓縮：路由 3/50、語意失真 4/50、幻覺 1/50。
- 加入 Solution 邊界：路由 0/50、語意失真 1/50、幻覺 0/50。
- 加入 Solution 驗收：路由 0/50、語意失真 0/50、幻覺 0/50、功能 50/50、整體成功 50/50。

以上是內部模擬，不是獨立 API benchmark。

## 14. 最優解假設

目前最佳候選不是單純極限壓縮，而是：
> 分層壓縮 + 語意契約 + 證據優先保留 + 結果驗收 + A/B 驗證。

此結論仍需後續實測確認。
