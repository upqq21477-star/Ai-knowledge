# 資訊需求建立

## 狀態
【建立中；已完成外部方法比對；待實際任務驗證】

## 定義

資訊需求（Information Need）是為了回答目前研究問題，而必須取得的資訊內容、條件、證據或資料範圍。

```text
研究問題
↓
資訊需求
↓
查詢策略
↓
搜尋
```

資訊需求不是搜尋詞，也不是搜尋結果。

## 為什麼需要獨立建立資訊需求

直接從問題跳到搜尋詞，容易出現：

- 問題太寬，搜尋大量無法使用的資料。
- 問題被錯誤縮窄，查詢看似精確卻漏掉真正需要的資料。

因此需要先回答：

> 為了完成這個問題，我究竟需要取得哪些資訊？

## 基本結構

| 項目 | 要確認的內容 |
|---|---|
| 需求內容 | 要取得什麼資訊？ |
| 用途 | 支援研究問題的哪一部分？ |
| 對象／概念 | 涉及哪些人、事物、系統或概念？ |
| 條件 | 有哪些必要條件？ |
| 時間／狀態 | 需要目前、歷史、特定期間或特定版本？ |
| 範圍 | 單一案例、某類資料、整體領域或跨領域？ |
| 資料角色 | 定義、事實、案例、比較、來源、證據等？ |
| 完成判定 | 取得到什麼程度才足以支援下一步？ |

不要求每項需求都填滿所有欄位；欄位是防止重要條件遺漏的檢查工具。

## 常見資訊需求類型

- 定義需求：確認概念是什麼。
- 事實需求：取得特定事實或數據。
- 狀態需求：知道目前狀態、版本或最新情況。
- 歷史需求：知道演變、舊版本或形成背景。
- 比較需求：取得多個對象的可比較資訊。
- 解釋需求：理解原因、機制或關係。
- 案例需求：取得實際案例。
- 證據需求：取得支持或反駁主張的資料。
- 方法需求：知道可行方法、流程或工具。

同一研究問題可以同時包含多種需求。

## 與問題拆分的關係

```text
問題拆分
→ 把複合問題拆成可分別處理的子問題

資訊需求建立
→ 確認回答這些問題需要取得哪些資訊
```

兩者可以交替進行；不是絕對的先後階段。

## 與搜尋詞的區分

資訊需求不能直接等同於關鍵字。

例如：

```text
資訊需求：確認某產品目前是否支援某功能
```

可能需要不同查詢：

```text
產品名稱 + 功能名稱
產品名稱 + 官方文件
產品名稱 + 版本
產品名稱 + release notes
```

因此：

> 資訊需求決定「要找到什麼」，查詢策略才決定「怎麼找」。

## 需求完整度

不以需求數量判定完整，而應檢查：

1. 是否覆蓋研究問題真正需要回答的部分。
2. 是否包含會改變結論的重要條件。
3. 是否區分目前狀態與歷史背景。
4. 是否需要不同來源或不同資料角色。
5. 是否存在尚未處理的重要不確定性。

需求過多也會增加搜尋與上下文成本，因此採用「最小充分資訊需求」原則。

## 需求與搜尋範圍

```text
目前版本功能
→ 最新官方資料／版本資訊

歷史演進
→ 歷史版本與舊資料

方案比較
→ 多個對象的同類資訊

主張驗證
→ 支持／反駁該主張的證據來源
```

搜尋範圍應由資訊需求與漏失成本共同決定，而不是固定由資料庫大小決定。

## 需求完成與停止

「找到資料」不等於「需求已滿足」。

應判斷：

```text
是否已取得足以回答該需求的資料？
↓
是否仍有會改變結論的重要缺口？
↓
是否需要其他來源／角度驗證？
```

當核心需求已充分支援、剩餘缺口不會合理改變結論，且繼續搜尋的預期收益低於成本，可以考慮停止。

高風險、高影響或要求高度完整性的研究，停止標準應提高。

## 需求的迭代

初步搜尋可能揭露原本不知道的需求：

```text
原需求
↓
搜尋
↓
發現關鍵版本差異
↓
新增「版本差異」需求
↓
再次搜尋
```

因此資訊需求是研究中的工作結果，可以隨理解進展更新。

## 外部方法比對後採用的原則

外部研究搜尋方法普遍先從研究問題辨識核心概念，再由概念形成搜尋策略。問題框架可以協助界定範圍與搜尋概念，但研究問題中的每個概念不一定都適合直接成為搜尋限制。

PubMed User Guide（2026-05-07 更新）也將辨識核心概念列為基本搜尋步驟，並提供查詢詞、布林運算、欄位、同義詞映射與結果聚焦／擴展等機制。

因此 Ai-knowledge 採用：

1. 先建立「要取得什麼資訊」，再建立查詢。
2. 資訊需求應與研究問題直接對應。
3. 包含會影響答案的必要條件，但不任意增加限制。
4. 不把搜尋詞、搜尋結果或來源直接當成資訊需求。
5. 資訊需求可以依搜尋結果重新修正。
6. 以最小充分資訊需求控制搜尋與上下文成本。
7. 高風險問題提高需求覆蓋與驗證標準。

## 待驗證

- 實際研究問題是否需要增加更細的資訊需求分類。
- 「最小充分資訊需求」是否能穩定降低搜尋與上下文成本。
- 資訊需求是否需要固定格式，或維持自然語言即可。
