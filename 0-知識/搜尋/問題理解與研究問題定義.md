# 問題理解與研究問題定義

## 狀態
【建立中；已完成外部方法比對；待實際任務驗證】

## 定義

問題理解（Problem Understanding）是把使用者提出的原始問題、需求或模糊描述，轉換成目前真正需要回答、判斷或查明的研究問題（Research Question）。

研究問題不是把原句換一種說法，而是要確認：

- 真正要解決的是什麼。
- 最終需要得到什麼結果。
- 問題涉及哪些核心概念。
- 有哪些必要條件、範圍、時間或對象限制。
- 哪些內容只是背景，不是搜尋必要條件。
- 哪些部分需要事實、比較、解釋、驗證或目前狀態判定。

## 為什麼需要先理解問題

搜尋策略應由問題決定，而不是由搜尋工具的功能反過來決定。

Cochrane 的研究方法指出，良好形成的研究問題會影響後續的納入／排除條件、搜尋、資料蒐集、結果整合與呈現。citehttps://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-02

因此：

```text
原始問題
↓
理解真正目的
↓
界定問題範圍與條件
↓
形成可回答的研究問題
↓
辨識核心概念
↓
建立資訊需求
↓
建立查詢策略
```

如果問題理解錯誤，即使後續搜尋技術正確，也可能得到大量「相關但沒有回答真正問題」的資料。

## 問題理解的最低結構

不要求所有問題都套用固定問句框架，但至少應檢查：

| 項目 | 要確認的內容 |
|---|---|
| 目的 | 為什麼要研究／搜尋？ |
| 核心問題 | 最終真正要回答什麼？ |
| 對象 | 涉及誰、什麼資料、什麼系統或什麼事物？ |
| 核心概念 | 問題中的主要概念有哪些？ |
| 關係 | 要知道因果、差異、狀態、定義、效果、方法或其他關係？ |
| 條件 | 有哪些必要條件或限制？ |
| 時間 | 需要目前狀態、特定期間、歷史演進，還是不限時間？ |
| 範圍 | 需要單一案例、特定領域，還是跨領域比較？ |
| 輸出 | 最終需要事實、比較、判斷、解釋、建議依據或其他結果？ |

不是每個問題都需要所有欄位；欄位的作用是避免重要條件被忽略。

## 問題框架不是固定模板

外部研究方法常使用 PICO、PCC、PEO、SPIDER、SPICE 等問題框架來幫助界定研究問題。這些框架有助於辨識概念、範圍與條件，但不同研究問題適用的框架不同，不能把 PICO 當成所有搜尋問題的通用格式。citehttps://bib.kuleuven.be/english/research/information-retrieval/research-question/question-frameworks

因此 Ai-knowledge 採用較上位的原則：

> 問題框架是協助理解問題的工具，不是問題理解本身。

如果現有框架不適合，可以直接使用概念拆解、概念圖（Concept Mapping）或自然語言重新表述問題。citehttps://bib.kuleuven.be/english/research/information-retrieval/research-question/question-frameworks

## 問題與搜尋問題的區分

研究問題與搜尋查詢（Query）不是同一件事。

```text
研究問題
→ 我要知道什麼？

資訊需求
→ 為了回答它，我需要取得哪些資訊？

搜尋查詢
→ 我要用什麼詞與條件找到這些資訊？
```

因此不能直接把原始問題整句丟給搜尋工具，就視為完成問題理解。

## 從問題找出搜尋概念

研究問題中的每個詞不一定都應成為搜尋詞。

外部圖書館研究方法指出，應先辨識主要概念，再決定哪些概念適合作為搜尋概念；有些概念可能對全文判讀重要，但因不會穩定出現在標題、摘要或關鍵字中，不適合作為嚴格的搜尋限制。citehttps://bib.kuleuven.be/english/research/information-retrieval/research-question/research-to-searchable-question

因此：

```text
問題概念
≠
必然搜尋詞
```

這是避免過度限制搜尋的重要原則。

## 問題範圍

問題應有足夠明確的範圍，但不應為了搜尋方便而過度縮窄。

需要在：

```text
太寬 → 無法有效搜尋／判斷
太窄 → 漏掉重要資料
```

之間取得平衡。

如果問題過於寬泛，優先考慮：

- 明確主要目的。
- 指定必要對象。
- 指定必要時間。
- 指定必要條件。
- 拆成多個真正不同的子問題。

而不是任意加入限制條件。

## 問題理解的迭代性

問題理解不是一次完成後永遠不變。

初步搜尋可能發現：

- 使用者使用的名稱不是領域常用名稱。
- 原問題缺少必要條件。
- 問題其實包含多個不同問題。
- 現有資料顯示需要增加或刪除某個範圍。
- 原本認為重要的概念其實不是搜尋必要條件。

因此可以：

```text
問題理解
↓
初步搜尋／探索
↓
發現新資訊
↓
重新理解問題
↓
修正資訊需求與查詢
```

重新理解不是搜尋失敗，而是研究過程的一部分。

## AI 協助問題理解

AI 可以協助：

- 重述問題。
- 找出隱含條件。
- 提出可能的子問題。
- 提出不同問題框架。
- 指出原問題可能存在的歧義。

但 AI 的重述與拆解只是候選理解，不應自動視為使用者真正需求。

需要檢查：

- 是否改變原始目的。
- 是否加入使用者沒有要求的限制。
- 是否漏掉核心條件。
- 是否把推測當成使用者已確認的需求。

## 最小充分問題定義

本方案不要求每個研究問題都建立完整研究計畫。

對一般搜尋研究而言，至少應能回答：

```text
我要知道什麼？
為什麼需要知道？
需要哪些核心概念？
有哪些必要條件？
需要什麼時間／狀態範圍？
最後要產生什麼結果？
```

能回答這些問題，才進入資訊需求與查詢策略階段。

## 外部方法比對後的設計決定

目前採用：

1. 研究問題需要先於查詢策略明確化。
2. 問題框架可協助界定範圍，但不強制使用單一框架。
3. 研究問題中的概念與搜尋詞需要分開判斷。
4. 問題理解可以在搜尋後迭代修正。
5. AI 產生的問題重述、拆分與框架化結果都屬候選，不直接視為已確認需求。
