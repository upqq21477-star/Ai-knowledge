# 上下文成本

> 一句話：人工智慧的上下文是有限且有成本的工作資源，應根據任務需要載入資訊。

## 核心原理
上下文管理是在資訊完整度、理解準確度與使用成本之間取得平衡。

```text
任務需求 → 判斷必要資訊 → 先讀相關內容 → 發現缺口再擴大 → 必要時完整稽核
```

能讀全部與每次都應讀全部，是兩個不同命題。

## 適用情境
大型或持續成長的資料庫、長期專案、大量歷史資料，以及需要在完整理解與回應成本之間取捨時。

## 不適用情境
完整稽核、遷移或安全檢查不能為節省上下文而省略必要文件。文件很少時也不必建立複雜載入機制。

## 實務方法／注意事項
優先採取任務導向閱讀；證據不足再擴大。需要確認全貌時直接完整閱讀。真正出現找不到、載入過慢或重複閱讀成本後，再尋找最小解法。

## 我的補充
上下文管理不是永遠只看摘要，而是避免摘要成為新的資訊瓶頸。
