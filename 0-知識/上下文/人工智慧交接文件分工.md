# 人工智慧交接文件分工

> 一句話：長期人工智慧專案需要把「如何操作」「目前是什麼」「過去為什麼這樣決定」分開。

## 核心原理
不同文件回答不同問題：

```text
說明 → 這個資料庫是什麼？
規則 → 現在應該怎麼操作？
交接資料 → 目前狀態與重要歷史是什麼？
正式內容 → 真正保存了哪些知識、系統與應用？
```

文件分工的目的不是增加數量，而是避免一份文件同時承擔互相衝突的責任。

## 適用情境
多個人工智慧輪流接手長期專案、專案歷史很長、架構反覆修改時。

## 不適用情境
一次性短任務或沒有長期狀態的小型文件。

## 實務方法／注意事項
交接資料保留會影響下一次決策的重要背景，但不複製整個知識庫，也不取代正式規則。衝突時以規則文件為準。

## 我的補充
有效交接的重點是避免下一個人工智慧重犯已經犯過的錯，同時知道哪些內容必須回到正式文件確認。
