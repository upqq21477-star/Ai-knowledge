# 實測結果回寫最小原則

日期：2026-09-17
狀態：【候選知識；已完成外部比對；待實際小系統驗證】

## 一、目的

定義系統實際執行後，如何把觀察結果、實測資料與判定回寫到正確工作層級。

本文件是可重用的最小原則，不是某一個系統的完整操作流程。

## 二、核心原則

系統文件中的「預期結果」不能取代實際結果。

至少必須區分：

```text
預期狀態／預期輸出
↓
實際觸發
↓
實際執行
↓
實際結果／觀察
↓
比較
↓
判定
↓
回寫
```

沒有實際執行，就不能產生本專案自己的實測證據。

## 三、最小回寫資料

一次實測至少保留：

- 問題／需求
- 使用條件
- 預期結果
- 實際觸發情況
- 實際執行情況
- 實際結果
- 與預期的差異
- 判定
- 後續處理

## 四、回寫層級

```text
一次性工作觀察 → 應用／工作記錄
可重複的穩定原理 → 知識
可重複的方法結構 → 系統
多系統固定目的組合 → 方案
```

一次異常不得直接被提升成穩定知識；需要足夠證據與適用條件。

## 五、外部研究與實測的關係

外部研究可以提供候選方法、比較基準與已知限制，但不等於本專案的實測結果。

因此：

```text
外部證據 ≠ 本專案實測數據
規格預期 ≠ 實際結果
文件存在 ≠ 能力成立
```

## 七、限制

本原則不規定完整資料庫、固定 JSON Schema、完整統計模型或自動化測量平台。

目前只要求能留下足以重建一次實測的最小證據。
