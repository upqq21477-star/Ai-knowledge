# 後續工作觸發式順便驗證原則 v2.0

狀態：**【新建立；候選知識；已完成外部方法比對；待實際案例驗證】**

## 1. 定義

後續工作觸發式順便驗證（Follow-up Work Triggered Validation）是一種低干擾驗證方法：對已知但尚未完成驗證的系統、能力或規則建立「待觸發驗證標記」，之後正常進行其他工作時，檢查該工作是否自然提供驗證條件；若條件成立，則在不額外製造工作的前提下，同時完成驗證並記錄結果。

核心原則：**標記待驗證，不主動製造測試；自然遇到適用場景時順便驗證。**

## 2. 為什麼需要

部分能力不需要立即安排獨立測試。若未來正常施工必然會使用或自然經過其適用條件，可以把驗證工作綁定到正常施工，降低重複操作與人工成本。

但「被使用」不等於「已驗證」。只有實際觀察到可判定的輸入、執行、結果與條件，才可以結束驗證標記。

## 3. 最小運作循環

```text
建立待驗證標記
↓
正常進行後續工作
↓
讀取目前狀態／待辦／相關標記
↓
判斷本次工作是否自然符合驗證條件
├─ 否 → 不觸發，正常施工
└─ 是
    ↓
    在正常工作中同步執行驗證
    ↓
    記錄條件、操作、觀察、結果
    ↓
    判定 PASS / PARTIAL / FAIL / NOT TRIGGERED
    ↓
    更新驗證標記狀態
```

## 4. 觸發判定

只有同時符合以下條件，才應觸發：

1. 本次工作本來就會進行，不是為了測試而臨時製造。
2. 本次工作實際會使用或經過被標記能力的適用範圍。
3. 所需前置條件已成立。
4. 驗證不會破壞目前施工順序、Gate 或既有工作目的。
5. 能取得足以判定結果的觀察資料。

任一條件不成立，保持 `NOT TRIGGERED`，不得為了消除待辦而硬測。

## 5. 驗證記錄最小內容

每次實際觸發至少記錄：

- 驗證標記 ID
- 觸發的正常工作
- 觸發條件
- 實際使用／操作
- 預期結果
- 實際結果
- 差異
- 驗證判定
- 適用條件與限制
- 後續處理

## 6. 狀態

```text
MARKED
↓
NOT TRIGGERED（尚未遇到自然條件）
↓
TRIGGERED
↓
PASS / PARTIAL / FAIL
```

`MARKED` 表示已要求後續自然觸發；`NOT TRIGGERED` 表示尚未遇到合適工作；`TRIGGERED` 表示已開始實際觀察；三種結果必須有實際證據才能成立。

## 7. 與其他能力的邊界

- 不是獨立問題解決流程；若驗證中發現問題，應轉入既有問題解決流程。
- 不是待辦清單的替代品；標記只表達「未來自然遇到時順便驗證」。
- 不是自動測試系統；不代表會自行製造測試環境。
- 不是驗證結果本身；標記存在不代表 PASS。
- 不得越過施工 Gate 來完成驗證。

本專案不直接複製上述大型管理框架，而是取其可移植的原則：**持續觀察、自然觸發、記錄結果、持續改進**。本原則進一步加入本專案特有的限制：不得為了驗證而製造工作、不得把使用等同於驗證完成、不得破壞施工 Gate。

## 9. 驗證狀態

本知識已完成外部方法比對，但尚未由真實後續工作完成閉環驗證。第一次自然觸發案例應驗證：

`標記 → 讀取待辦 → 判斷是否自然觸發 → 同步實測 → 記錄 → 判定 → 結束／保留標記`。
