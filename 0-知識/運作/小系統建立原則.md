# 小系統建立原則

日期：2026-09-17
狀態：【候選知識；已完成外部方法比對；待實測驗證】

## 核心知識

小系統是「具有獨立運作邊界，但規模不足以列入正式方案等級」的能力單元。

它不應只是功能名稱或待辦項目，而應至少具備目的、觸發條件、輸入、輸出、依賴、邊界、運作方式與驗證狀態。

## 建立程序

```text
問題／需求
→ 現有能力盤點
→ 外部搜尋
→ 方法／工具／案例比較
→ 候選小系統
→ 知識書
→ 最小規格
→ 最小實測
→ 判定
→ 登錄／修正／廢止
```

因此「小」只代表規模小，不代表可以省略研究、知識建立或驗證程序。

## 為什麼需要列表

當小系統增加後，單靠檔案名稱無法可靠回答：

- 現在有哪些小系統？
- 哪些可以使用？
- 哪些仍待驗證？
- 哪些與目前工作有關？
- 哪些存在依賴或衝突？
- 哪些可能應升格為正式系統／方案？

因此需要集中式「小系統列表」作為統御索引，而不是把小系統全部塞進正式方案架構。

## 邊界

小系統 ≠ 正式方案。

小系統 ≠ 待辦事項。

小系統 ≠ 單一知識。

小系統 ≠ 一個檔案。

小系統可以由知識、規格、驗證記錄與列表索引共同構成。

## 驗證狀態

目前尚未因文件建立而視為成立；必須經實際使用案例驗證。
