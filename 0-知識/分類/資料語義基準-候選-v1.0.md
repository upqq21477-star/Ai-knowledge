# 資料語義基準－候選 v1.0

狀態：【DISTILL-CANDIDATE / MEDIUM】
性質：P0.5-04 候選蒸餾文件
注意：本文件尚未成為 CURRENT Canonical Source。

## 一、定位
本文件整理 Ai-knowledge 目前跨方案可共用的資料語義邊界。
目的不是建立資料庫 Schema，也不是建立 Knowledge Graph，而是避免不同方案對同一概念使用不同含義。

## 二、核心語義集合
目前候選集合：Knowledge、Memory、Current State、Source、Evidence、Claim、Decision、Observation。
這是目前最小共同語義集合候選，不是固定且完整的資料宇宙。

## 三、核心邊界
Knowledge ≠ Memory：Knowledge 著重可重用理解；Memory 著重後續工作需要保留的背景與歷史。
Knowledge ≠ Current State：目前採用方案 A 首先是 Current State / Decision，不是通用 Knowledge。
Source ≠ Evidence：Source 說明內容來源；Evidence 是可支持、限制或反駁主張的判斷依據。
Evidence ≠ Claim：Claim 是被判斷的命題；Evidence 是判斷 Claim 的依據。
Claim ≠ Knowledge：Claim 可以尚未確認、受限制或被反駁；經理解、比較、驗證並具有可重用價值後才可能形成 Knowledge。
Observation ≠ Knowledge：一次測試結果首先是 Observation，經驗證與抽象後才可能形成 Knowledge。
Decision ≠ 永久規則：Decision 受到當時目標、時間、條件與限制影響。
Current State ≠ 單一 status 欄位：至少考慮時間、範圍、適用條件、目前採用內容與必要歷史脈絡。

## 四、內容與承載形式分離
Document / File / Note 是承載形式，不是資料語義類型。同一 Markdown 可以同時包含 Knowledge、Claim、Evidence、Decision、Observation、Current State 與歷史脈絡。
因此不建立「一種資料類型＝一種檔案格式」。

## 五、管理維度與資料語義分離
Classification 與 State 是管理維度，不應直接視為資料內容類型。
P0.5 Asset Governance State：CURRENT / REVIEW / DEPRECATED / RETIRED / HISTORICAL / UNKNOWN。
此 Asset State 與 Current State 語義不同，不得混合。

## 六、資料語義與能力層分離
System / Plan / Capability / Tool / Application 屬能力／組織層次，不與 Knowledge、Memory、Source 等同一層。
可存在 Knowledge → 支撐 → System、System → 提供能力 → Plan 等關係，但不因此建立關係引擎。

## 七、最小關係模型
Source → 提供內容／Observation；Observation → 形成 Claim；Evidence → 支持／限制／反駁 Claim；Claim → 經理解與驗證 → Knowledge；Decision 保存特定條件下的選擇；Memory 保存後續工作需要的背景與歷史。
這些是語義關係，不代表必須建立圖資料庫。

## 八、目前不建立
不建立完整 Metadata Schema、固定 Database Schema、Knowledge Graph、Vector Database、自動資料類型判定、複雜資料物件 ID 系統、全自動資料轉換或中央 Relationship Engine。

## 九、既有驗證
原「資料層級與分類」已以不同用途文件完成第一輪實際驗證，支持：文件承載形式 ≠ 內容語義 ≠ 管理狀態 ≠ 記憶用途。
該驗證只證明模型在既有 Ai-knowledge 文件中的可操作性，不證明適用所有知識庫。

## 十、待驗證
1. 既有文件是否能用同一語義集合描述。
2. 混合內容文件是否能同時保存多種語義。
3. Claim / Evidence / Source 是否能實際區分。
4. Decision / Current State / Knowledge 是否能避免誤判。
5. Memory 是否能保留背景而不被誤當 Knowledge。
6. 八種集合是否在真實案例中出現缺口。
7. 三方案是否能使用相同語義而不產生衝突。
