# 資料分類語義基準-候選 v1.0

狀態：【DISTILL-CANDIDATE / MEDIUM】
本文件不是 CURRENT Canonical Source。

## 一、定位
本候選文件蒸餾「知識分類」「分類維度」「分類原理」「分類與目錄」的共同有效語義。

必須分開：
- 通用分類概念
- Ai-knowledge 的目前工程應用

## 二、分類目的
分類的目的，是降低資料探索、理解、搜尋、維護與重用成本。

分類至少需要區分：
- 分類依據
- 分類對象
- 分類結果
- 使用目的

## 三、分類維度
可從不同角度描述資料，例如：
- 功能
- 資料性質
- 領域
- 物件
- 狀態
- 適用範圍

多個維度可以同時存在，但不應全部變成同一棵目錄樹。

## 四、分類判定
只有在實際需要降低搜尋、理解、維護、驗證或使用成本時，才建立新的分類。

不得因：
- 主題出現很多次
- 工具提供標籤／屬性能力
- 單一文件存在
而預先建立分類。

## 五、分類與目錄
分類是邏輯概念；目錄是實體實作方式之一。

目錄應只承擔主要、穩定、需要用於探索的分類。

Ai-knowledge 目前的 0-知識 採功能導向第二層分類，最多兩層是目前工程成本控制規則，不是通用知識庫定律。

## 六、跨功能文件
一份文件若具有多個功能，原則上依主要使用目的歸類。

其他關係透過文件內容、引用或必要的結構化機制表達，而不是強迫建立多份目錄副本。

## 七、Ai-knowledge 的應用邊界
目前 0-知識 的第二層功能分類是專案架構決策。

具體資料夾名稱、舊 0-知識/知識 過渡結構、現有文件分類對照，屬專案應用／管理脈絡，不應被宣稱為通用分類定律。

## 八、驗證
仍需以真實工作驗證：
- 新文件分類穩定性
- 跨功能文件處理成本
- 兩層目錄探索成本
- 搜尋成功率
- 新分類建立判斷一致性
- 現有分類是否仍合理
- 歷史過渡結構是否仍有未吸收價值

## 九、禁止事項
本候選不授權：
- Merge / Delete / Rename 原始文件
- 第三層目錄
- 分類資料庫
- 自動分類 Engine
- CURRENT Promotion

只有自然案例與後續驗證足夠時，才可重新判定其狀態。
