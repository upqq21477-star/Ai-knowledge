【外部稽核完成／實際驗證待進行】

## 核心結論

不同概念不應全部視為同一條資料階梯。

```text
內容／語義
├─ 資料（Data）
├─ 資訊（Information）
└─ 知識（Knowledge）

形成與支撐關係
├─ 來源（Source）
└─ 證據（Evidence）

承載形式
└─ 文件／檔案／筆記（Document / File / Note）

工作結果
├─ 觀察（Observation）
├─ 決策（Decision）
└─ 經驗／教訓（Experience / Lesson）

管理屬性
├─ 分類（Classification）
├─ 狀態（State）
└─ 記憶用途（Memory Role）
```

這是一個關係模型，不是一條「資料→資訊→知識→智慧」的固定階梯。

## 資料、資訊與知識

資料是可被記錄或處理的事實、觀測值、符號或原始內容。

資訊是經整理、組織或賦予意義後，可供理解或使用的內容。

知識依 Ai-knowledge 的定義，是經過理解、整理或驗證後，能在明確情境與適用條件下支持後續理解、判斷、決策或行動的可重用內容。

資料或資訊可以成為知識，但不是所有資料或資訊都會成為知識。

## 不採用硬性 DIKW 階梯

```text
資料 → 資訊 → 知識 → 智慧
```

可以作為理解工具，但不作為目錄或資料庫的硬性架構。記憶、來源、證據、文件與決策也不屬於同一語義階層。

## 來源與證據

來源回答「這項內容從哪裡來？」；證據回答「為什麼某項主張可以被支持、檢驗或接受？」。

```text
來源 ≠ 證據 ≠ 知識
```

但可以形成：

```text
來源 → 提供內容／觀察 → 形成證據 → 支持或限制主張 → 形成／修正知識
```

## 文件不是資料層級

文件是內容的承載或組織形式。一份 Markdown 文件可以同時包含資料、資訊、知識、來源描述、證據、決策紀錄與歷史資訊。

因此不能因為內容存在於 `.md` 文件，就直接判定它屬於某種資料性質。

## 記憶不是知識同義詞

記憶主要解決連續性：後續處理是否需要知道過去發生過什麼、目前背景是什麼？

記憶可能包含知識，也可能包含偏好、專案歷史、尚未整理的背景、當前狀態與過去決策。

```text
記憶 ≠ 知識
```

## 決策不是知識同義詞

決策是特定情境下做出的選擇。某專案目前採用方案 A，首先是決策與目前狀態，不是通用知識。

若整理成「在條件 X 下，方案 A 相較於方案 B 可以降低成本 Y」，並具有形成依據與可重用價值，才可能成為知識。

```text
決策 → 可能產生經驗／教訓 → 可能整理成知識
```

## 狀態不是資料類型

「待確認」「已確認」「過時」「歷史」「目前採用」是管理狀態，不是內容語義種類。

```text
候選 → 已確認 → 被修正 → 被取代
```

不應以 `已確認/`、`待確認/`、`歷史/` 作為主要分類樹。

## 分類不是資料性質

分類是對內容進行組織與描述的管理行為或結構。同一份內容可以同時具有不同分類維度：

```text
功能：搜尋
領域：AI 知識管理
物件：知識系統
狀態：已確認
適用範圍：Ai-knowledge
```

## Ai-knowledge 的最小模型

目前只保留概念上的最小關係：

```text
內容
＋ 適用情境／條件
＋ 形成依據
＋ 來源／證據關係
＋ 可重用目的
＋ 目前狀態
＋ 必要的分類資訊
```

不因此建立複雜資料庫。

## 與 `0-知識` 的關係

`0-知識` 保存建立與管理 AI 知識系統所需的基礎原理，目前以功能導向作為主要目錄分類維度：

```text
0-知識/
├─ 管理/
├─ 分類/
├─ 搜尋/
├─ 證據/
├─ 比較/
├─ 更新/
├─ 系統/
└─ 上下文/
```

這是目錄設計，不代表管理、分類、搜尋等是資料語義層級。

## 實際判斷順序

1. 這是什麼內容？
2. 它描述的是事實、資訊、可重用理解、決策、經驗，還是其他內容？
3. 它從哪裡來？
4. 哪些內容可以作為證據？
5. 是否形成可重用知識？
6. 目前處於什麼狀態？
7. 需要什麼分類或管理方式？
8. 最後才決定承載位置。

## 待實際驗證

用既有 Ai-knowledge 文件測試：基礎原理、長期記憶、專案決策、外部來源、證據內容、混合內容文件、已取代方案。

驗證重點是是否更容易判斷「這是什麼」「為什麼存在」「目前是否可用」「應該如何被重用」。
