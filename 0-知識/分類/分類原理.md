# 分類原理

狀態：**【建立中】**

## 一、目的

分類的目的不是把所有資料分門別類，而是讓資料能以穩定、可理解、可重複使用的方式被管理、探索與搜尋。

分類應直接降低以下成本：

- 找不到資料的成本
- 判斷資料歸屬的成本
- AI 理解資料結構的成本
- 後續維護與擴充的成本

## 二、分類的基本原則

分類必須先確定「分類依據」，再決定「分類結果」。

不能因為某個文件名稱看起來像某一類，就直接建立同名資料夾並將資料放入其中。

分類至少要區分：

- 分類依據
- 分類對象
- 分類結果
- 分類的使用目的

## 三、分類與功能

本知識庫的 `0-知識` 用於保存建立系統所需的基礎原理。

因此 `0-知識` 第二層資料夾採「功能導向」分類，而不是把所有知識視為同一類資料。

例如：

```text
0-知識/
├─ 管理/
├─ 分類/
├─ 搜尋/
└─ ...
```

這些資料夾表示「這些原理主要支援什麼功能」，不是表示資料本身的主題。

## 四、最小分類原則

分類只建立實際需要的層級。

目前固定為兩層：

```text
0-知識/
└─ 功能分類/
   └─ 原理文件.md
```

不建立第三層資料夾。

如果某一功能需要更多細分，優先增加文件，而不是增加資料夾層級。

## 五、分類不等於資料夾

分類是邏輯概念，資料夾只是實作分類的一種方式。

並非所有分類維度都應建立成資料夾。

例如資料的「狀態」「時間」「適用範圍」未來可能需要被判定或記錄，但不代表必須建立對應資料夾。

## 六、目前分類系統的核心方向

```text
0-知識
↓
按照系統功能所需的基礎原理分類
↓
功能資料夾
↓
原理文件
```

後續新增分類時，必須先確認：

1. 是否代表一個實際需要支援的功能。
2. 是否存在可獨立描述的基礎原理。
3. 是否能降低未來建立或使用系統的成本。
4. 是否可以用現有分類處理。

如果只是因為某個主題出現很多次，不應直接建立新分類。
