## 核心結論

不同概念不應全部視為同一條資料階梯。

```text
內容／語義
├─ 資料（Data）
├─ 資訊（Information）
└─ 知識（Knowledge）

形成與支撐關係
├─ 來源（Source）
└─ 證據（Evidence）

承載形式
└─ 文件／檔案／筆記（Document / File / Note）

工作結果
├─ 觀察（Observation）
├─ 決策（Decision）
└─ 經驗／教訓（Experience / Lesson）

管理屬性
├─ 分類（Classification）
├─ 狀態（State）
└─ 記憶用途（Memory Role）
```

這是一個關係模型，不是一條「資料→資訊→知識→智慧」的固定階梯。

## 資料、資訊與知識

資料是可被記錄或處理的事實、觀測值、符號或原始內容。

資訊是經整理、組織或賦予意義後，可供理解或使用的內容。

知識依 Ai-knowledge 的定義，是經過理解、整理或驗證後，能在明確情境與適用條件下支持後續理解、判斷、決策或行動的可重用內容。

資料或資訊可以成為知識，但不是所有資料或資訊都會成為知識。

## 不採用硬性 DIKW 階梯

```text
資料 → 資訊 → 知識 → 智慧
```

可以作為理解工具，但不作為目錄或資料庫的硬性架構。記憶、來源、證據、文件與決策也不屬於同一語義階層。

## 來源與證據

來源回答「這項內容從哪裡來？」；證據回答「為什麼某項主張可以被支持、檢驗或接受？」。

```text
來源 ≠ 證據 ≠ 知識
```

但可以形成：

```text
來源 → 提供內容／觀察 → 形成證據 → 支持或限制主張 → 形成／修正知識
```

## 文件不是資料層級

文件是內容的承載或組織形式。一份 Markdown 文件可以同時包含資料、資訊、知識、來源描述、證據、決策紀錄與歷史資訊。

因此不能因為內容存在於 `.md` 文件，就直接判定它屬於某種資料性質。

## 記憶不是知識同義詞

記憶主要解決連續性：後續處理是否需要知道過去發生過什麼、目前背景是什麼？

記憶可能包含知識，也可能包含偏好、專案歷史、尚未整理的背景、當前狀態與過去決策。

```text
記憶 ≠ 知識
```

## 決策不是知識同義詞

決策是特定情境下做出的選擇。某專案目前採用方案 A，首先是決策與目前狀態，不是通用知識。

若整理成「在條件 X 下，方案 A 相較於方案 B 可以降低成本 Y」，並具有形成依據與可重用價值，才可能成為知識。

```text
決策 → 可能產生經驗／教訓 → 可能整理成知識
```

## 狀態不是資料類型

「待確認」「已確認」「過時」「歷史」「目前採用」是管理狀態，不是內容語義種類。

```text
候選 → 已確認 → 被修正 → 被取代
```

不應以 `已確認/`、`待確認/`、`歷史/` 作為主要分類樹。

## 分類不是資料性質

分類是對內容進行組織與描述的管理行為或結構。同一份內容可以同時具有不同分類維度：

```text
功能：搜尋
領域：AI 知識管理
物件：知識系統
狀態：已確認
適用範圍：Ai-knowledge
```

## Ai-knowledge 的最小模型

目前只保留概念上的最小關係：

```text
內容
＋ 適用情境／條件
＋ 形成依據
＋ 來源／證據關係
＋ 可重用目的
＋ 目前狀態
＋ 必要的分類資訊
```

不因此建立複雜資料庫。

## 與 `0-知識` 的關係

`0-知識` 保存建立與管理 AI 知識系統所需的基礎原理，目前以功能導向作為主要目錄分類維度：

```text
0-知識/
├─ 管理/
├─ 分類/
├─ 搜尋/
├─ 證據/
├─ 比較/
├─ 更新/
├─ 系統/
└─ 上下文/
```

這是目錄設計，不代表管理、分類、搜尋等是資料語義層級。

## 實際判斷順序

1. 這是什麼內容？
2. 它描述的是事實、資訊、可重用理解、決策、經驗，還是其他內容？
3. 它從哪裡來？
4. 哪些內容可以作為證據？
5. 是否形成可重用知識？
6. 目前處於什麼狀態？
7. 需要什麼分類或管理方式？
8. 最後才決定承載位置。

## 第一輪實際驗證：2026-09-16

使用目前 repository 中不同用途的文件進行分類／分層判斷：

| 測試對象 | 判斷結果 | 原因 |
|---|---|---|
| `0-知識/分類/資料層級與分類.md` | 知識 | 提供可重用的分類與資料層級原理 |
| `目前狀態.md` | 記憶／目前狀態承載文件 | 主要作用是跨工作階段恢復目前狀態，不等同於通用知識 |
| `2-方案/AI知識管理方案.md` | 方案 | 將多個系統組合為特定工作方法 |
| `1-系統/資料分類與組織系統.md` | 系統 | 描述可重複執行的分類與組織能力 |
| `歷史方案與不採用方向.md` | 歷史／決策背景 | 保存過去選擇與不採用方向，不能直接當作目前規則 |
| 外部模型發布資訊 | 來源／資訊 | 可作為更新判斷的來源，但尚未因此自動成為本 repository 的知識 |

驗證結果支持以下區分：

```text
文件承載形式
≠
內容語義
≠
管理狀態
≠
記憶用途
```

因此目前模型可以處理混合內容文件，不需要為每種語義建立獨立文件副檔名或資料庫層級。

## 實際驗證得到的限制

本輪驗證只證明模型在既有 Ai-knowledge 文件中具有可操作性，不證明它適用所有知識庫。

同時，本輪尚未完整測試：

- 大量異質資料。
- 同一文件同時包含大量互相衝突的內容。
- 複雜外部資料集。
- 自動化分類。
- 大規模團隊協作。

這些情境若日後產生實際成本，再進入新的驗證與更新。

## 待持續驗證

後續以真實新增文件、移動文件、歷史文件與混合內容文件持續測試：

1. 能否穩定區分內容語義與管理屬性。
2. 能否避免把狀態、記憶用途或承載形式誤當成分類層級。
3. 功能導向的 `0-知識` 目錄是否仍能降低定位與維護成本。
4. 是否有新的資料維度產生足以支持獨立分類的實際需求。
