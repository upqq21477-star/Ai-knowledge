# 重大變更與遷移安全原理

狀態：【已建立；外部研究形成；待實際案例驗證】
日期：2026-09-17

## 一、用途

處理知識庫、軟體、系統、資料結構或流程發生重大變更時，如何在新舊狀態之間安全遷移，而不是把「建立新版本」誤認為「更新完成」。

本知識不規定所有更新都必須採用同一種遷移方式；依變更破壞性、依賴數量、可回復性與驗證成本選擇策略。

## 二、核心區分

重大更新至少區分：

1. 內容變更：主張、規則、資料或文件內容改變。
2. 結構變更：欄位、格式、目錄、接口、資料模型改變。
3. 行為變更：輸入、流程、輸出或判斷結果改變。
4. 相容性變更：舊使用者、舊資料、舊引用或舊接口是否仍可工作。
5. 遷移變更：需要把既有使用對象從舊狀態帶到新狀態。

重大變更的風險通常來自「相容性與依賴」而不只是變更本身。

## 三、重大變更基本生命週期

```text
變更提出
↓
建立新舊基線
↓
辨識破壞性變更
↓
盤點依賴與使用者
↓
設計遷移策略
↓
建立遷移前驗證條件
↓
小範圍／乾跑／測試
↓
分階段切換或一次切換
↓
驗證新狀態
↓
保留可回復路徑
↓
確認穩定後退役舊狀態
```

不是所有專案都需要完整的雙版本並行；但越高破壞性、越高依賴、越難回復的變更，越需要分階段驗證與回復方案。

## 四、版本策略

### 1. 非破壞性變更

若新增內容不破壞既有輸入、引用與行為，可直接加入目前版本或次版本。

### 2. 破壞性變更

若刪除、重命名、改變必填條件、改變核心語義或改變既有接口行為，使舊使用者可能失效，應明確標記為 breaking change，並提供遷移條件。

### 3. 不確定變更

證據不足時，不應直接宣稱相容或安全；先進入待確認狀態。

## 五、相容性檢查

至少檢查：

- 舊資料能否被新版本讀取。
- 舊引用是否仍能解析。
- 舊接口是否仍可使用。
- 新版本輸出是否仍滿足下游條件。
- 舊版與新版能否在過渡期共存。
- 變更後是否出現語義漂移而非單純格式差異。

必要時分為向後相容（Backward Compatibility）與向前相容（Forward Compatibility）。

## 六、遷移策略

可依風險選擇：

- 原地更新：適合低風險、可直接驗證的變更。
- 先建立新版本再切換：適合需要比較新舊結果的變更。
- 雙軌並行：適合舊版仍需服務且切換不能一次完成的變更。
- 分階段／漸進式切換：先讓小範圍使用，再擴大。
- 乾跑（Dry Run）：先模擬遷移，確認資料、依賴與工具行為。
- 回復（Rollback）：若驗證失敗，回到已知可用狀態。
- 不可逆遷移：只有確認回復不必要或另有備份／補救方案後才採用。

## 七、回復條件

回復不是「出錯再想辦法」，而應在施工前定義：

- 什麼條件視為失敗。
- 哪些結果必須停止擴大切換。
- 回復到哪一個已知狀態。
- 回復後如何確認資料與引用沒有進一步損壞。

## 八、驗證層級

重大變更至少需要區分：

1. 語法／結構驗證：新內容可讀取、格式有效。
2. 功能驗證：原有必要功能仍可運作。
3. 相容性驗證：既有依賴仍可運作。
4. 一致性驗證：新舊資料、索引、引用與狀態一致。
5. 實際使用驗證：真實任務中沒有出現預期外問題。

只有完成適用的驗證層級，才能決定舊狀態是否退役。

## 九、外部方法比較得到的共同原則

GitHub 的遷移文件要求先界定遷移範圍，並建議對每個 repository 進行 dry run，再安排遷移前與遷移後步驟。GitHub API 的版本策略則把 breaking change 與相容性、遷移與測試直接連結。Microsoft Azure Well-Architected Framework 強調小型增量更新、嚴格測試、漸進式暴露、向前／向後相容，以及為失敗部署準備補救或回復方案。

這些方法共同支持：

```text
重大變更 ≠ 直接覆蓋
重大變更 = 新舊基線 + 依賴盤點 + 遷移策略 + 驗證 + 回復條件 + 退役舊狀態
```

## 十、適用邊界

本知識不要求：

- 所有小修改都建立雙版本。
- 所有工作都做完整 dry run。
- 所有更新都必須藍綠部署。
- 所有舊版本永久並行。

應依破壞性、影響範圍、依賴、錯誤成本、回復難度與驗證成本決定遷移強度。

## 十一、與本知識庫的直接關係

當知識庫進行整體格式、目錄、分類、狀態模型或核心規則的大型重製時，本知識用於補足：

- 新舊格式共存與切換判斷。
- 依賴與引用遷移。
- 舊資料退役條件。
- 大型更新的乾跑與實際切換。
- 回復與失敗處理。
- 更新後的實際使用驗證。

本知識不能取代「知識更新」、「更新影響分析」、「知識整合」或「方案管理」；它提供的是重大變更時的遷移與安全施工原理。
