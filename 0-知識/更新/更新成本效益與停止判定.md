# 更新成本效益與停止判定

## 狀態
【建立中；已完成外部方法比對；待更新方案實測】

## 一、目的

判斷一項更新是否值得現在執行，以及影響範圍擴大時，何時應停止分析或延後更新。

核心不是追求「所有資料永遠一致」，而是在一致性收益、錯誤風險與更新成本之間取得合理平衡。

## 二、成本效益模型

```text
更新價值
≈
降低錯誤風險
＋維持一致性的收益
＋未來重工成本的避免

更新成本
≈
影響分析
＋修改
＋重新驗證
＋上下文／閱讀成本
＋後續連鎖更新
```

若更新價值明顯低於成本，可以暫不更新。

軟體變更影響研究普遍把 changeability、change amount、change proneness、instability 等因素與維護成本／努力估算聯繫起來，但研究也指出目前沒有一個普遍精確的單一量化方法。citeturn1search0turn1search11

因此本知識採「估算」而非「精確成本公式」。

## 三、更新效率閾值

本方案使用概念性閾值：

```text
預期更新收益 > 預期更新成本
→ 值得更新

預期更新收益 ≈ 預期更新成本
→ 視風險、時效與未來使用頻率決定

預期更新收益 < 預期更新成本
→ 暫不更新
```

這不是固定數字，也不是永遠拒絕大範圍更新。

高風險資料、近期大量使用的資料、會直接影響錯誤決策的資料，應提高更新收益估計。

低風險、低使用率、很少被引用的資料，可以接受延後一致化。

## 四、成本估算的最小因素

第一版只需要估算：

1. 受影響項目數量。
2. 每個項目的修改難度。
3. 重新驗證成本。
4. 是否會觸發下一層影響。
5. 使用頻率與錯誤風險。
6. 是否存在低成本替代方案。

不要一開始建立複雜金額模型。

## 五、影響範圍過大時的處理

```text
發現變更
↓
分析影響範圍
↓
估算完整更新成本
↓
估算不更新的風險／未來成本
↓
比較
├─ 更新收益高 → 執行
├─ 接近 → 視風險與時效
└─ 更新成本高且收益低 → 暫不更新
```

「不更新」必須留下理由，而不是默默忽略。

至少記錄：

- 哪個變更未更新。
- 受影響範圍。
- 預估成本。
- 延後原因。
- 何種條件出現後重新評估。

## 六、避免無限計算

成本分析本身也不能無限消耗。

當：

- 已有足夠資訊判斷更新／不更新。
- 新增估算資料不會改變決策。
- 估算成本已經明顯高於可期待收益。

就停止成本分析。

只有當決策接近閾值時，才值得投入更多估算工作。

## 七、更新優先級

若不能一次更新全部內容，優先：

1. 直接影響核心規則的資料。
2. 會影響其他系統輸出的資料。
3. 高頻使用資料。
4. 高錯誤成本資料。
5. 其他低風險資料。

這只是風險導向的優先處理，不是永久排名。

## 八、與研究方案的關係

搜尋研究方案的停止判斷處理「要不要繼續研究」。

本文件處理「發現知識變更後，要不要繼續更新整個受影響範圍」。

兩者共同原則是：

> 當新增工作已無法合理改變決策或降低足夠風險時，停止。
