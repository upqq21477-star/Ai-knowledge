# 新舊系統獨立運行原理

版本：v1.0  
狀態：【初版建立；待三方案實際建立後驗證】

## 一、目的

新系統應能在不依賴舊系統的前提下獨立運行。

這不是要求新舊系統永遠互不相容，而是要求新系統具有清楚、可驗證的自身閉環。

## 二、基本模型

```text
舊系統
├─ 舊知識
├─ 舊資料
├─ 舊方案
└─ 舊流程

新系統
├─ 新知識
├─ 新資料
├─ 新方案
└─ 新流程
```

新系統的核心功能不能以「舊系統剛好存在」作為必要前提。

## 三、獨立運行的最低條件

新方案至少應能：

1. 找到自身必要資料。
2. 理解自身資料的語義與狀態。
3. 使用自身需要的系統能力。
4. 執行主要工作流程。
5. 產生可保存的結果。
6. 對結果進行基本驗證。
7. 在失敗時指出缺口，而不是默默依賴舊系統補足。

## 四、允許共享

獨立運行不等於重複建造所有能力。

成熟後可以共享：

- 穩定的共同資料語義。
- 已驗證的通用知識。
- 明確定義的系統介面。
- 可重用的工具或軟體能力。

但共享必須透過明確介面，而不能形成隱性依賴。

## 五、獨立性驗證

可採用「隔離測試」：

```text
移除舊系統依賴
↓
只提供新系統自身資料與必要共同契約
↓
執行主要任務
↓
記錄缺失
↓
判斷真正依賴與偶然依賴
```

若測試失敗，應區分：

- 新系統本身缺能力。
- 共同資料契約不足。
- 新系統錯誤引用舊系統。
- 實際上應共享某項已驗證能力。

不能看到失敗就直接把整個舊系統重新接回來。

## 六、與融合蒸餾的關係

新系統獨立運行後，融合蒸餾可以分析三個新方案之間的重複能力。

因此：

> 先證明可以獨立，再證明哪些部分值得共享。

這可以避免一開始就把所有新系統綁在一起。

## 七、核心原則

> 獨立運行是驗證模組完整性的手段；共享能力是驗證完成後的最佳化手段。
