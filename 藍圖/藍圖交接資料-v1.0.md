## 三、目前藍圖狀態

目前藍圖的定位：

【未來規劃／長期架構】

不是：

【目前全部已實體化】

因此以下項目即使在藍圖中被描述，也不能視為已建立：

- Capability Registry
- System Graph Engine
- 自動化 Orchestrator
- Model Update 自動流程
- 大型 Agent Runtime
- Vector DB
- Event Bus
- Scheduler

只有實際工作出現重複瓶頸，並經過 Observation、研究、測試與驗證，才可以進入正式工程。

## 五、藍圖更新運作方式

參考正式「工程運作與持續改進方案」及「交接資料」的運作方式，藍圖也採：

`變更發生`
→ `變更原因`
→ `影響範圍`
→ `更新藍圖文件`
→ `更新待辦／進度`
→ `建立交接紀錄`
→ `驗證入口與引用`
→ `保留 Git 歷史`

但藍圖更新不等於正式工程採用。

藍圖中的候選內容仍須經正式工程的 Proposal → Impact Analysis → Research → Evaluation → Decision → Approval → Implementation → Regression → Evidence 流程，才可進入 CURRENT 工程。

## 六、每次藍圖重大更新必須交接的內容

至少記錄：

1. 更新日期。
2. 更新原因。
3. 哪些藍圖文件變更。
4. 變更的是方向、架構、Mapping、待辦或進度。
5. 是否影響目前正式工程。
6. 是否新增／移除候選項目。
7. 是否產生新的狀態衝突。
8. 下一步。
9. 驗證方式。
10. Git Commit 作為變更證據。

## 七、狀態判定

藍圖文件的狀態與正式工程狀態分開管理：

- CURRENT：目前有效的藍圖版本。
- REVIEW：正在確認。
- DRAFT：草案。
- SUPERSEDED：被新版藍圖取代。
- HISTORICAL：保留歷史決策／演化證據。

注意：

`藍圖 CURRENT` ≠ `正式工程 CURRENT`

本資料夾中的 CURRENT，只表示「目前採用的藍圖版本」，不表示其中所有功能已實體化。
