# 五對話並行施工規格

版本：v1.0
日期：2026-09-19
狀態：【規劃建立中（代）】
定位：本文件定義五個獨立對話如何在同一治理架構下並行執行任務。
權威：本文件只規範並行施工方式，不取代控制平面、唯一工作池、目前工程基線或問題清單。

## 一、核心目的

將大型工作拆成彼此具有明確邊界的獨立任務，使五個對話可以同時工作。

五個對話是執行席位，不是五套系統，也不是五個治理者。

共同使用：
- 同一控制平面。
- 同一目前權威。
- 同一唯一工作池。
- 同一問題清單。
- 同一驗收規則。

不得因並行施工建立第二個工作池、第二個控制平面、第二個目前狀態真相或第二套驗收制度。

## 二、任務基本契約

每個任務必須具備以下欄位：

| 欄位 | 必填 | 定義 |
|---|---|---|
| 任務編號 | 是 | 唯一識別 |
| 工作範圍 | 是 | 本任務可以處理的內容 |
| 禁止範圍 | 是 | 本任務不得處理的內容 |
| 允許操作 | 是 | 本任務可以進行的操作 |
| 輸出 | 是 | 任務必須產生的結果 |
| 驗證 | 是 | 判定輸出有效的方法 |
| 停止條件 | 是 | 必須暫停而不能繼續的情況 |
| 異常條件 | 是 | 發現治理問題時的判定 |
| 終止條件 | 是 | 任務正式結束的條件 |
| 完成狀態 | 是 | 任務目前生命週期狀態 |

任務不得只有「負責某類資料」這種模糊描述。

## 三、獨立性原則

每個任務必須可以在自己的工作範圍內獨立完成。

任務之間：
- 可以讀取共同資料。
- 可以發現其他任務的問題。
- 可以引用已公開的其他任務結果。
- 可以回報依賴與衝突。

但不得：
- 接管其他任務。
- 修改其他任務負責的內容。
- 改變其他任務的工作範圍。
- 替其他任務宣布完成。
- 因發現問題而自行擴大範圍。
- 以自己的判定覆寫共同權威。

核心規則：

**讀取可以廣，寫入必須窄。**

## 四、任務邊界

每個任務建立時，必須同時指定：
- 可讀取範圍。
- 可修改範圍。
- 禁止修改範圍。
- 可建立的輸出。
- 不得建立的治理資料。

同一檔案或同一責任鏈在同一時間原則上只能由一個任務持有修改權。

如果兩個任務都需要修改同一資料：
- 不得同時修改。
- 先建立衝突或依賴。
- 重新切分任務。
- 或由其中一個任務取得明確修改權。

## 五、任務生命週期

標準狀態：

待開始
→ 進行中
→ 已完成
→ 終止

例外路徑：

進行中
→ 停止
→ 等待條件
→ 重新分派或恢復

進行中
→ 異常
→ 問題清單
→ 等待處理

「停止」不等於完成。
「異常」不等於失敗。
「終止」才表示任務生命週期正式結束。

## 六、停止規則

以下任一情況成立時，任務應停止擴張：

- 權威無法判定。
- 必要資料缺失。
- 工作範圍不足以安全判定。
- 繼續操作將越出禁止範圍。
- 發現共同架構規則不足。
- 發現其他任務正在持有必要修改範圍。
- 驗證條件不足。
- 繼續操作需要自行猜測。

停止後：
- 保留已完成產出。
- 說明停止位置。
- 說明停止原因。
- 說明需要的外部條件。
- 不自行突破邊界。

## 七、異常規則

異常是任務執行過程發現的治理問題，例如：
- 多個目前入口。
- 多個目前版本。
- 控制平面與內容衝突。
- 舊入口仍被引用。
- 其他任務邊界重疊。
- 模擬驗收被誤標為實際驗收。
- 同一責任出現兩個不同判定。

發現異常後，原任務只負責：
發現 → 記錄 → 回報。

除非任務本身的工作範圍明確包含該問題，否則不得自行修正。

## 八、輸出規則

每個任務的輸出必須能被另一個沒有參與施工的對話理解。

至少包括：
- 任務編號。
- 工作範圍。
- 實際處理內容。
- 修改或新增內容。
- 依據。
- 證據。
- 驗證結果。
- 發現問題。
- 未完成事項。
- 最終狀態。

不能只回報「完成」。

## 九、停止回報

固定格式：

【停止回報】

任務編號：

目前狀態：停止

已完成：

停止位置：

停止原因：

發現問題：

是否涉及其他任務：

需要外部條件：

目前產出：

未完成內容：

禁止自行處理：

後續等待：

## 十、異常回報

固定格式：

【異常回報】

任務編號：

異常類型：

發生位置：

發現內容：

影響範圍：

是否影響本任務繼續：

是否越出本任務範圍：

已建立問題：

暫時處理：

禁止自行處理：

建議後續：

## 十一、終止回報

任務只有符合以下條件才能終止：

- 工作範圍已完成。
- 禁止範圍未越界。
- 輸出已完成。
- 驗證已完成。
- 未解問題已登記。
- 沒有必要的後續操作。

固定格式：

【終止回報】

任務編號：

最終狀態：已完成／終止

工作範圍：

實際完成：

禁止範圍檢查：未越界

最終輸出：

驗證結果：

模擬驗收：通過（代）／未通過

發現問題：

未處理事項：

產出位置：

任務結論：

本任務已達終止條件，停止後續操作。

## 十二、五席初始分流

第一批建議使用以下五個方向：

一號：
全庫入口與目前權威盤點。

二號：
六層功能責任與資料分類映射。

三號：
控制平面、狀態、依賴與索引關係檢查。

四號：
新舊資料、重複、衝突、歷史與退場判定。

五號：
獨立驗證與交叉檢查。

席位不是永久職務。

第一批任務完成後，席位釋放，再由唯一工作池重新分派下一批任務。

## 十三、五號驗證席

在需要高可靠度的批次中，至少保留一個獨立驗證席。

驗證席不得直接把自己的判定改成施工結果。

主要檢查：
- 是否符合任務契約。
- 是否越界。
- 是否產生第二真相。
- 是否與共同權威衝突。
- 是否有引用斷裂。
- 是否把規劃當正式。
- 是否把模擬當實際證據。
- 是否留下沒有退場路徑的暫存資料。

## 十四、任務結果回收

任務完成後，結果進入共同回收流程：

任務輸出
→ 結果登記
→ 邊界檢查
→ 引用檢查
→ 權威檢查
→ 狀態檢查
→ 模擬回歸
→ 問題回收
→ 任務終止

任務結果在完成共同驗證前，不因單一對話宣稱而自動成為全庫正式真相。

## 十五、任務重新分派

以下情況可以重新分派：
- 任務正常終止。
- 任務停止且等待條件已解除。
- 任務原邊界不再適用。
- 任務被拆分。
- 任務發現自己不具備必要權限或能力。

重新分派時必須建立新的任務編號或明確的續作編號，不覆寫原任務歷史。

## 十六、並行停止條件

整批並行施工應停止擴張，如果出現：
- 多個任務修改同一目前真相。
- 任務邊界大量重疊。
- 五個任務開始互相等待。
- 任務結果互相矛盾且無法判定權威。
- 任務開始建立第二工作池。
- 任務開始建立第二控制平面。
- 任務開始自行修改共同治理規則。
- 驗證證據不足卻準備切換正式狀態。
- 大量結果依賴未解決的核心架構問題。

遇到上述情況，回到問題流程或研究流程，不以增加對話數量解決治理問題。

## 十七、模擬驗收

在尚未有實際運作證據前，本機制全部標記「（代）」。

至少模擬以下情境：

一、五個新對話完全沒有歷史記憶，只取得自己的任務卡，能否正確開始。

二、任務讀到其他責任範圍的問題，能否只回報而不接管。

三、任務遇到權威衝突，能否停止而不是猜測。

四、任務完成後，能否輸出完整終止回報。

五、任務停止後，能否保留狀態並等待重新分派。

六、兩個任務需要同一檔案時，能否阻止同時修改。

七、五個結果回收後，能否發現互相矛盾。

八、模擬驗收結果不會被誤標為實際運作證據。

## 十八、非目標

本機制不負責：
- 建立新的架構層。
- 建立新的控制平面。
- 建立新的工作池。
- 建立新的問題清單。
- 取代目前工程基線。
- 自行決定全庫正式內容。
- 以並行數量取代必要的驗證。
