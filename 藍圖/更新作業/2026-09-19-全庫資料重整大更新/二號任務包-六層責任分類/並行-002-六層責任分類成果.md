## 1. 任務輸出定位

本文件為二號任務的分類施工成果，不代表全庫遷移完成，也不改變控制平面、CURRENT 或其他席位成果。

分類維度：
1. 功能責任：Knowledge / System / Project / Solution Capability / Assistance Capability / Agent Capability
2. 資料類型：Definition / Spec / Evidence / Research / Work / State / History / Reference / Registry / Index / Governance 等
3. 範圍：Central / Project / Historical / External Research 等
4. 狀態：以來源文件現有狀態為準；尚未實際運作驗證者保留「（代）」
5. 權威性：是否可作為 Runtime / Current Source of Truth；不得因分類結果自行提升權威

## 2. 六層判定規則

- 六層是功能責任，不是實體資料夾。
- 路徑、檔名、Skill 標籤均不能單獨決定功能責任。
- 橫向治理資料（State、Evidence、Dependency、Impact、Change、Authority、Registry、Index、CURRENT、Handoff、Blueprint、Governance Rule、Governance Spec、Problem Record 等）不強塞入六層。
- 無法安全判定時標記「待判定（代）」；不得創造第七層。
- 「規劃中／建立中」不得直接轉成正式完成。
- 模擬驗收通過仍保留「（代）」直到實際運作驗證。

2. 交接測試是 Handoff Evidence；「測試交接能力」與「提供交接能力」是兩個不同責任。
3. 方案二／三的方案級驗證文件可以保留 Solution Capability 作為對象範圍，但資料本體是 Verification Evidence，不得把 SIMULATION-PASSED 等同 FIELD 完成。
4. 方案四共同能力影響分析是在做 Solution Capability 內部的候選能力判斷；候選能力沒有因此升格為獨立 System。
5. 待辦與問題紀錄是橫向治理資料；它們可以指向六層資產，但自身不因此成為某一層。
6. 歷史快照不得覆蓋 CURRENT Authority；版本新舊與 Authority 關係屬 Lifecycle／Authority 治理。
