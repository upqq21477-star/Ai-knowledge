## 1. 修正原因

第二輪獨立回查發現，v1.0 將「檔案索引中的歷史版本紀錄」誤判為「目前索引 metadata drift」。

檔案索引實際同時保存歷史變更紀錄；其中 v1.1 / v1.3 等舊版本出現在歷史區，不足以證明目前入口指向錯誤版本。

因此：
- P3-001「Index Version Drift」撤銷。
- 不建立索引問題。
- 正式文件本身目前為 Registry v1.2、Query v1.4，與其目前規格狀態一致。

## 2. 已確認的控制平面基準

- CURRENT Baseline 是唯一目前工程游標 Authority。
- 待辦清單是唯一 Workpool。
- Skill Definition 是 Skill Source of Truth。
- Registry 是 Derived View，不取代 Source。
- Query 是 Progressive Retrieval，不是第二 Source。
- Version 不等於 State。
- DEPENDS_ON 不等於 AFFECTS。
- 無證據的 Impact 保持 UNKNOWN。
- Simulation 不升格 FIELD。
- SOURCE / DERIVED / INFERRED / UNKNOWN 必須分開。
- Registry 遺失或 Drift 時，可由 Source 重建。
- 不建立第二控制平面或第二 CURRENT。

## 4. 仍存在的狀態治理對照缺口

狀態與可變資料管理規格另要求：

「先判斷實體類型，再套用適合的狀態配置。」

例如知識、系統、能力、專案、任務、工作流程、代理執行具有不同狀態語義。

因此可確認：
- Skill Registry 的 Skill State mapping 有正式規格。
- 但「一般 Entity Registry 的 State 欄位」與「全 Entity Type 的 type-specific state configuration」之間，目前沒有本任務足夠證據證明已完成全面落地映射。

這不是 Skill Registry 缺失，而是跨 Entity Type 的狀態契約對照仍屬 UNKNOWN。

問題：
P3-001（修正版）｜Cross-Entity State Mapping（代）

處理：
保持 UNKNOWN；不自行新增 mapping。

## 5. Dependency / Impact

Registry v1.2：
- DEPENDS_ON = 直接執行／結構依賴。
- AFFECTS = 有 Change / Evidence 支持的影響關係。
- 不得由 Dependency 自動推導 Impact。

Query v1.4：
- Q5 預設查直接 Dependency。
- Q8 查 Impact 時必須取得 Reason / Evidence / Confidence / Verification。
- 沒有 Evidence 時回 UNKNOWN。

CURRENT Baseline Dependency Map v0：
- 只記錄已確認直接依賴。
- 未知依賴保持 UNKNOWN。

判定：（代）一致。

## 6. Evidence / Acceptance

Registry 與 Query 均明確：
Simulation ≠ FIELD。

CURRENT Baseline 也明確指出：

因此：
- 規格／Simulation 可證明契約成立。
- 不得把 Simulation Acceptance 宣告成 Natural FIELD。
- 真實成本、Stop Depth、Drift、Recovery、Candidate 正確性等仍維持自然工作 Evidence。

判定：（代）一致。

CURRENT Baseline 另明確規定：
不得由其他文件另行宣告新的工程 CURRENT。

判定：（代）一致。

## 8. Index 對照重新判定

檔案索引包含：
- 目前文件導航紀錄。
- 歷史變更紀錄。
- 待檢索項目。

其中出現 Registry v1.1 / Query v1.3 等歷史版本，並不等於目前入口指向舊版本。

因此：
INDEX DRIFT = 未證實。
不登記為問題。

這裡採「證據不足即 UNKNOWN / 不立案」，而非從歷史版本文字推導缺陷。
