目前可直接定位的 General Entity 承載系統為：

`1-系統/共同對象與關係目錄系統-v1.0.md`

該文件明確將自身定位為跨方案共用的薄型 Object Catalog / Relationship Registry，負責：
- 對象 Identity / Kind / Name / Alias / Location 定位
- Relationship 的 Source / Type / Target
- Version / State 的定位入口
- 提供其他系統查詢共同身份與關係

但同一文件也明確表示：
- 目前只定義語義；
- 尚未凍結完整 JSON / YAML Schema；
- 系統實作仍為「進行中」；
- 最小實作驗收與實戰驗證尚待執行。

因此，此文件可以確認「General Entity Source/責任邊界的候選正式承載位置」，但不能視為已存在的 Registry 資料集。

因此，本輪可把先前「找不到 General Entity Registry dataset」從單純搜尋結果，提升為有正式施工文件支持的結論。

### 3. 檔案索引不是 General Entity Registry

`檔案索引.md` 的用途是：
「近期檔案新增、實質更動、位置變更與隔日檢索驗證。」

它保存的是 Path / 用途／本次變更 / 預計隔日檢索 / 狀態等資訊。

目前沒有證據顯示它承擔：
- General Entity Identity
- Entity Type
- Entity State Configuration
- Relationship records
- Control Plane Source Pointer 的正式 Entity Registry 資料責任

因此不能把「檔案索引」升格解讀為 General Entity Registry。

### 4. CURRENT Baseline 也不是 General Entity Registry

`2-方案/完善/CURRENT Baseline-v1.0.md` 的責任是「目前工程狀態、下一施工游標與最小恢復資訊的唯一 CURRENT Authority」。

它不是一般 Entity Catalog，也沒有被證明保存全庫 Entity Identity / Relationship records。

因此：
CURRENT Baseline = 工程目前狀態權威
≠ General Entity Registry
≠ Control Plane Registry Source

### 5. Query 的目前證據邊界

Control Plane Query v1.4 的最小結果契約已固定為：

EntityID / Scope / Authority / Depth / Result / Unknowns / Fallback / SourcePointer。

但本輪沒有找到足以證明「General Entity → 共同對象目錄實際資料 → Control Plane Query」已經形成可執行資料流的 Registry sample / Query result。

目前已被明確證明的實際資料流仍是 Skill：

Skill Definition
→ Derived Registry View
→ Control Plane Query
→ Runtime
→ 回讀 Skill Definition

General Entity 尚未取得同等強度的實作證據。
