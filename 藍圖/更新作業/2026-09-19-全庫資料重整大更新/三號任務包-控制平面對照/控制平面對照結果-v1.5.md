# 並行－003｜控制平面對照結果（第六輪 Type 語義分層回查）

版本：v1.5
日期：2026-09-20
任務：並行－003
驗證性質：失憶後獨立模擬執行
整體驗收標記：（代）

## 1. 本輪目的

針對 P3-002，追查是否存在更上游的 Entity Type 定義，以判斷前一輪所稱「taxonomy conflict」究竟是直接衝突，還是不同層級的分類。

## 2. 新證據

找到以下正式規格：

《AI Control Plane 與整體改版藍圖 v1.1》
明確將 Control Plane 核心管理對象列為：
Entity / State / Dependency / Impact / Change / Evidence / Provenance / Authority / Lifecycle / Capability / Trace / Drift / Recovery。

同時資產層使用：
Rules → Knowledge / Memory → System → Plan → Software / Tool → Application。

《AI 知識系統六層架構資產分類與遷移規格 v1.2》
將功能責任分成：
知識、系統、專案、方案能力、協助能力、代理能力。
並另列控制資料：
實體、目前狀態、範圍、依賴、變更、歷史、證據、來源、追蹤。

《Skill Architecture v1.1》
又明確區分：
Agent / Workflow / Skill / Mode / Skill Family / Provider / Tool / Knowledge / System / Model。
這表示「Type」在目前架構中確實存在多個不同語義層。

## 3. 修正前一輪判定

因此不能直接把：
Registry 的 General Entity Type 清單
與
State Governance 的 State-bearing Entity Type 清單

視為同一層 taxonomy。

前一輪「兩套 Type taxonomy 直接衝突」的表述過強。

本輪撤回「直接衝突」判定。

但仍存在可驗證的缺口：

目前沒有找到一份正式規格，逐項說明：

General Registry Entity Type
→ 是否為 State-bearing Entity
→ 若是，套用哪一組 State Configuration
→ 若否，是否只有 Lifecycle / Version / Evidence / Authority 等欄位
→ Query 如何依 Type 判斷適用狀態欄位。

因此 P3-002 不再命名為 Conflict，而修正為：

P3-002（代）｜Entity Type → State Configuration Mapping Coverage

## 4. 與 P3-001 的關係

P3-001：
是否已存在所有 State-bearing Entity Type 的實際 Registry / Query 落地資料。

P3-002：
General Entity Type 與 State-bearing Entity Type 之間的正式 mapping 是否完整。

P3-002 仍是 P3-001 的前置判定條件之一，但不是「規格互相矛盾」。

## 5. 已確認與未確認

已確認：
- Control Plane 有 General Entity 概念。
- Registry 有 General Entity Type 欄位。
- State Governance 有 type-specific State Configuration。
- Skill 有獨立 State / Acceptance / Lifecycle / Version Contract。
- Agent / Workflow / Skill 等責任邊界已有正式規格。
- Project / Plan / Application 等概念在資產與專案規格中存在。

尚未確認：
- General Registry Type → State-bearing Type 的完整 mapping table。
- Project / Task / Workflow / Agent Execution 是否全部已有 Registry Query 對應。
- 每一種 General Type 是否應有 State、Lifecycle、Version、Acceptance 中的哪些欄位。
- 是否已有實際資料集證明上述 mapping 已落地。

## 6. 本輪停止條件

因此仍不得宣稱：
- 全部 Entity Type 的 State Mapping 已完成。
- Registry 已完整涵蓋所有 State-bearing Entity。
- Query 已能對所有 State-bearing Entity 正確選擇狀態配置。

以上保持 UNKNOWN（代）。

## 7. 回歸結果

1. 發現過強判定後主動撤回 → PASS（代）
2. 不把不同語義層 Type 強行合併 → PASS（代）
3. 不把 Plan / Project / Application 自動視為同一 Entity Type → PASS（代）
4. 不把 Skill / Capability 自動視為同一 Entity Type → PASS（代）
5. 不把 Runtime / Agent Execution 自動視為同一 Entity Type → PASS（代）
6. 未找到 mapping 就保持 UNKNOWN → PASS（代）
7. 不建立第二套 mapping → PASS（代）
8. 不建立第二 Control Plane → PASS（代）
