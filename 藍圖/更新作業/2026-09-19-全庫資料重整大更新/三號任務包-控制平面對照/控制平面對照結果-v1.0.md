## 2. 控制平面檢查基準
- Source of Truth 高於 Registry / Cache / Graph。
- CURRENT Baseline 是唯一目前工程狀態 Authority。
- 待辦清單是唯一 Workpool。
- Registry 是 Derived View，不取代 Source。
- Query 取得最小必要資料，足夠即 STOP。
- State 不得混合不同 Entity Type 的狀態語義。
- Version 不是 State。
- Dependency 只記錄可證明關係；未知保持 UNKNOWN。
- Impact 不得由 Dependency 自動推導。
- Simulation 不得升格 FIELD。
- Provenance 必須區分 SOURCE / DERIVED / INFERRED / UNKNOWN。
- Index 不得覆寫 Source。
- Derived Registry / Index 必須可由 Source 重建。

### 3.4 State / Acceptance / Lifecycle

判定：（代）一致。

### 3.6 Dependency / Impact

### 3.7 Evidence / Acceptance

### 3.8 Provenance

判定：（代）一致。

判定：REGISTRY MATERIALIZATION = UNKNOWN（代）。
不得把「規格存在」當成「完整 Registry 實體已存在」。

## 4. 問題

### P3-001｜Index Version Drift（代）
證據：檔案索引記載 Registry v1.1 / Query v1.3，而正式文件為 v1.2 / v1.4。
影響：查詢若直接依舊索引，可能得到過期 metadata。
處理：本任務不自行改共同索引真相。

### P3-002｜Entity State Mapping 未完全證明（代）
證據：Registry 有一般 Entity State 欄位；狀態治理要求 Entity Type-specific state configuration。
目前無足夠資料證明完整 mapping。
處理：保持 UNKNOWN，不補值。

### P3-003｜Registry 實體化程度 UNKNOWN（代）
證據：可確認規格與 Derived View 契約，但本次未證明完整獨立 Registry data store。
處理：不把規格存在視為實體資料已完整存在。
