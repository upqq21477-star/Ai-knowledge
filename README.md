# Ai-knowledge

這是一套以 Markdown + GitHub 為核心的個人 AI 工程知識庫。

## AI／工具接手入口

一般工作依現行入口鏈恢復必要 Context；若使用者要求「交接／開始交接／進行交接／交給下一個 AI」等交接意圖，優先進入 Handoff Skill。

交接任務入口：
1. `1-系統/交接 Skill.md`
2. `交接資料/目前施工交接包-2026-09-19-v1.0.md`
3. `1-系統/Agent Skill.md`
4. `藍圖/工程施工總控與收尾計畫-v1.0.md`
5. `1-系統/問題清單.md`
6. 再依交接包指定的 CURRENT State 與下一施工游標載入必要文件。

舊交接文件與舊快照只作歷史／背景參考，不得覆蓋目前交接包。
若只提供 GitHub 首頁，AI 必須先讀 README，再依上述入口恢復 CURRENT；不得直接依舊文件猜測狀態。

## Agent 啟動規則

本 repository 現在採用「Agent as Top-Level Skill」運作方式。

任何 AI／工具第一次接手時，必須先依上述現行入口鏈恢復必要工作狀態，並讀取：

`1-系統/Agent Skill.md`

讀取後**必須立即啟動 Agent Skill**，不等待使用者另外輸入「啟動」。

啟動後，除非使用者明確要求停止或停用，必須持續保持 `AGENT_STATE = ACTIVE`。後續所有任務都必須先經 Agent Skill 進行：

`Task Understanding → Context → Skill Selection → Execute → Verify → Replan if needed`

完成單次任務後，只停止該任務，不停止 Agent。

如果發生上下文重置、重新接手、或無法確認 Agent State，必須重新讀取 `1-系統/Agent Skill.md` 並重新啟動，再繼續工作。

這裡的「Agent Active」是對話／工作流程狀態，不代表存在背景常駐程序。AI 不得假設目前環境具有未提供的 Agent Runtime、API、資料庫或常駐服務。

**啟動後的核心要求：**
- 不直接跳過 Agent 判斷。
- 不預載整個 repository。
- 只載入當前任務必要 Context。
- 依 Responsibility 選擇 Skill。
- 執行後必須驗證。
- 失敗才重新規劃，不得無目的循環。
- 不把 Provider、Tool、Mode 自動新增為 Skill。
- 不把模擬結果寫成實戰驗收。
- Repository 修改仍必須遵守 `規則.md` 與 `檔案索引.md`。

## 檔案變更紀錄：必須執行

任何 AI、工具或其他自動化流程對 repository 進行檔案操作時，只要發生以下任一情況，都必須同步更新根目錄的 `檔案索引.md`：

- 新建檔案。
- 檔案內容有實質更動。
- 檔案移動位置或重新分類。
- 刪除檔案，尤其是原本存在且可能仍被引用的檔案。

「資料夾內的檔案」與「根目錄檔案」一律同樣處理，不得只記錄根目錄。

### 新建／實質更動

在當日日期下記錄：

- 完整目前路徑。
- 檔案用途或本次主要內容。
- 預計隔日檢索日期。
- 狀態先標記為 `待檢索`。

### 位置變更

除了目前路徑，必須記錄：

`原位置 → 新位置`

並說明變更原因。位置變更紀錄不能因為 Git 已保存歷史就直接刪除。

### 隔日消除規則

隔日必須重新檢索前一天的紀錄：

```text
找到檔案
↓
確認目前路徑正確
↓
確認可透過正常搜尋方式找到
↓
移除該筆「近期變更」紀錄

找不到
↓
保留紀錄
↓
標記「未找到／待處理」
↓
分析是檔案不存在、位置問題、名稱問題或搜尋／索引問題
```

如果檔案在隔日之前又再次發生實質更動或位置變更，必須重新對齊紀錄，不得沿用舊的驗證結果。

## 重要界線

`檔案索引.md` 是近期變更的檢索驗證工具，不是永久檔案目錄，也不是知識圖譜、資料庫或大型搜尋系統。

低維護成本仍然優先；只有實際使用證明目前機制不足，才增加更複雜的管理機制。

## 目前狀態文件維護界線

`目前狀態.md` 只保存專案／架構高階總覽，以及仍會影響整體判斷的穩定狀態資訊。

`2-方案/完善/目前工程狀態快照-006.md` 承擔目前工程執行位置與新 AI 最小恢復入口。

不要把測試過程、完整歷史、每次修改細節持續追加到 `目前狀態.md`。測試結果與歷史細節應放入既有專門文件；只有會影響整體接手與架構判斷的結論才回寫 `目前狀態.md`。
