# Ai-knowledge

這是一套以 Markdown + GitHub 為核心的個人 AI 工程知識庫。

## AI／工具接手入口

開始工作前，依以下順序讀取：

1. `說明.md`：整體目的與架構。
2. `目前狀態.md`：目前做到哪裡、正在處理什麼。
3. `規則.md`：正式操作規則。
4. `待辦清單.md`：目前工作主線與下一步。
5. `檔案索引.md`：近期檔案新增、實質更動、位置變更與隔日檢索驗證。
6. 之後依任務讀取相關的 `0-知識/`、`1-系統/`、`2-方案/` 等內容。

`交接資料.md` 屬於歷史決策、架構轉折與背景資料，不作為目前狀態的第一入口。

## 檔案變更紀錄：必須執行

任何 AI、工具或其他自動化流程對 repository 進行檔案操作時，只要發生以下任一情況，都必須同步更新根目錄的 `檔案索引.md`：

- 新建檔案。
- 檔案內容有實質更動。
- 檔案移動位置或重新分類。
- 刪除檔案，尤其是原本存在且可能仍被引用的檔案。

「資料夾內的檔案」與「根目錄檔案」一律同樣處理，不得只記錄根目錄。

### 新建／實質更動

在當日日期下記錄：

- 完整目前路徑。
- 檔案用途或本次主要內容。
- 預計隔日檢索日期。
- 狀態先標記為 `待檢索`。

### 位置變更

除了目前路徑，必須記錄：

`原位置 → 新位置`

並說明變更原因。位置變更紀錄不能因為 Git 已保存歷史就直接刪除。

### 隔日消除規則

隔日必須重新檢索前一天的紀錄：

```text
找到檔案
↓
確認目前路徑正確
↓
確認可透過正常搜尋方式找到
↓
移除該筆「近期變更」紀錄

找不到
↓
保留紀錄
↓
標記「未找到／待處理」
↓
分析是檔案不存在、位置問題、名稱問題或搜尋／索引問題
```

位置變更只有在隔日確認「新位置存在且可正常搜尋找到」後，才可以消除位置變更紀錄。

如果檔案在隔日之前又再次發生實質更動或位置變更，必須重新對齊紀錄，不得沿用舊的驗證結果。

## 重要界線

`檔案索引.md` 是近期變更的檢索驗證工具，不是永久檔案目錄，也不是知識圖譜、資料庫或大型搜尋系統。

它的目的只有一個：

> **確保 AI／工具對 repository 的檔案新增、修改、移動與刪除，不會在沒有留下可追蹤紀錄的情況下發生。**

低維護成本仍然優先；只有實際使用證明目前機制不足，才增加更複雜的管理機制。

## 目前狀態文件維護界線

`目前狀態.md` 只保存目前仍會影響接手、判斷與下一步工作的狀態資訊。

不要把測試過程、完整歷史、每次修改細節持續追加到 `目前狀態.md`。測試結果與歷史細節應放入 `更新紀錄/` 或既有專門文件；只有會影響「現在怎麼接手／現在做什麼」的結論才回寫 `目前狀態.md`。
