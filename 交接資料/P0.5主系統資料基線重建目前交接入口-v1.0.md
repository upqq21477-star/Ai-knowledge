## 五、目前已確立的工程邊界

### 1. State ≠ Version ≠ Git Commit ≠ Path

不能：

- 用檔名 v1.1 判定 CURRENT。
- 用 Git 最新 Commit 判定 CURRENT。
- 用資料夾位置判定 System。
- 用文件存在判定能力已成立。

### 2. Mapping ≠ Canonical

Mapping 只是 Derived View。

若 Mapping 與正式來源衝突：

```
先修 Canonical Source
→ 再修 Mapping
```

### 3. Capability ≠ System

Capability 是跨方案比較、測試、替換的功能單位。

不能因 Capability 存在就建立一個 System。

### 4. Knowledge ≠ System

Knowledge 說明知道什麼。

System 組織知識、規則、資料與操作方式。

### 5. Plan ≠ System

Plan 可以使用多個 System。

System 可以被多個 Plan 重用。

### 6. 文件存在 ≠ System 成立

至少需要：

```
Problem
→ Goal
→ Input
→ Knowledge / Data
→ Rules
→ Process
→ Output
→ Verification
→ Boundary
→ Real Use Evidence
```

### 7. Duplicate Candidate ≠ Duplicate Confirmed

看到相似內容只能建立候選，不可直接 Merge。

### 8. Evolution ≠ Redundant

新版本補充舊版本，不代表舊版本必須刪除。

### 9. 不人工製造 FIELD

FIELD 必須由真實工作觸發。
