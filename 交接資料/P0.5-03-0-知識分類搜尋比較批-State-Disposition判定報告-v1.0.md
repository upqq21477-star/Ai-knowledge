### 4.2 語義關係

前三個文件主要處理「如何分類」：

`分類原理`
→ 分類的基本原則與最小分類思想

`分類維度`
→ 分類可以從哪些維度描述

`分類與目錄`
→ 分類概念如何與實際目錄結構分離

後兩個文件主要處理「分類什麼」及資料語義：

`核心資料類型與邊界`
→ Knowledge、Memory、Current State、Source、Evidence、Claim、Decision、Observation 等核心語義物件的邊界

`資料層級與分類`
→ Data / Information / Knowledge 與 Source / Evidence / Document / Observation / Decision 等概念的關係，並明確不採用固定 DIKW 階梯作為硬性架構。

因此目前不能把五份文件視為單純重複。

### 4.3 特別風險

「核心資料類型與邊界」與「資料層級與分類」具有較高語義接近度，是後續 Canonical Mapping 的重點。

目前仍不能直接合併，原因是兩者處理的問題不同：
- 前者偏「目前系統需要固定哪些核心語義及其邊界」。
- 後者偏「不同資料概念如何形成關係模型，以及為何不採用固定資料階梯」。

後續若確認其中一份已完整吸收另一份，才進入 P0.5-04 蒸餾／重建判定。

### 5.2 搜尋知識目前形成完整工作鏈

本批不是 12 個彼此獨立的「搜尋技巧」，而是已經形成相對清楚的研究鏈：

`問題理解與研究問題定義`
→ `資訊需求建立`
→ `查詢策略建立`
→ `搜尋原理`
→ `搜尋拆分／搜尋擴展`
→ `候選資料整理與篩選`
→ `資訊適用性與情境匹配`
→ `研究結果採用判斷`
→ `研究結果整合與綜合`
→ `研究過程與決策軌跡記錄`

而 `資料探索` 橫向支援對資料空間的理解。

這表示目前最大的問題不是明顯內容重複，而是「未來入口如何讓 AI 知道先讀哪一份」。

### 5.3 高關聯群組

以下群組需要後續 Mapping，但目前不直接合併：

- 問題理解 ↔ 資訊需求
- 搜尋原理 ↔ 查詢策略
- 搜尋拆分 ↔ 搜尋擴展
- 資料探索 ↔ 搜尋原理
- 候選資料整理 ↔ 研究結果採用
- 資訊適用性 ↔ 證據／可信度知識
- 研究結果採用 ↔ 研究結果整合
- 研究過程與決策軌跡 ↔ 證據追溯／決策紀錄

這些是工作流程上的相鄰責任，不足以證明應合併成一份文件。

### 5.4 關鍵邊界

本批確認一個重要邊界：

`搜尋` 不負責證明資料正確。

搜尋負責定位候選資料；後續的來源、證據、可信度、適用性與採用判斷才處理「能不能相信／能不能用」。

這與前一批 `0-知識/證據` 的結構相容，沒有發現直接衝突。

### 6.1 文件

- 知識衝突判定.md → REVIEW / KEEP

### 6.2 責任邊界

兩者不是重複：

`知識比較原理`
→ 先判定兩份內容的實質關係。

`知識衝突判定`
→ 在比較結果顯示可能互斥後，進一步判斷是否真正衝突。

核心邊界：

`內容不同 ≠ 衝突`

且：

`發現衝突 ≠ 已知道哪一方正確`

前者是比較問題，後者是衝突判定／後續裁決問題。

因此目前保留兩份文件。
