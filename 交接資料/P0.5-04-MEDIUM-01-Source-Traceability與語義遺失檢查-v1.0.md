## 三、來源一：資料層級與分類

候選文件已保留：

1. 不採用硬性 DIKW 階梯，而採關係模型。
2. Data / Information / Knowledge 的語義區分。
3. Source ≠ Evidence ≠ Knowledge。
4. Document / File / Note 是承載形式，不是資料語義層級。
5. Memory ≠ Knowledge。
6. Decision ≠ Knowledge。
7. State ≠ Data Type。
8. Classification ≠ Data Property。
9. 內容、適用條件、形成依據、來源／證據、重用目的、狀態、分類之最小關係思想。
10. 文件承載形式、內容語義、管理狀態、記憶用途必須分離。
11. 原文件已完成第一輪實際驗證，以及其驗證限制。
12. 不因語義模型直接建立複雜資料庫。

判定：核心語義均已吸收；沒有發現會改變原結論的遺失。

## 四、來源二：核心資料類型與邊界

候選文件已保留：

1. 八種目前跨方案共同語義候選：
   Knowledge / Memory / Current State / Source / Evidence / Claim / Decision / Observation。
2. 各類型核心邊界。
3. Claim 與 Evidence、Source、Knowledge 的分離。
4. Observation 不等於 Knowledge。
5. Decision 不等於永久規則。
6. Current State 不等於單一 status 欄位，需考慮時間、範圍、條件、採用內容與必要歷史脈絡。
7. Capability / System / Plan / Tool / Application 與資料語義分層。
8. 最小轉換／關係模型。
9. 資料類型不等於檔案格式。
10. 不建立完整 Metadata Schema、Database、Knowledge Graph、Vector Database、自動類型判定、複雜 ID 或全自動轉換。
11. 必須以實際案例決定是否增加或修改資料類型。

判定：核心語義均已吸收；沒有發現會改變原結論的遺失。

## 五、蒸餾時的合理壓縮

以下內容在候選文件中被壓縮，而非遺失：

- 原文件的逐段說明文字。
- 第一份文件較完整的 Data / Information / Knowledge 解釋。
- 原文件個別範例與較長的推導文字。
- 第二份文件的「成立判定」完整問題描述。
- 原始文件對未測試情境的詳細文字。

這些內容目前仍可由原始文件追溯，因此壓縮不構成語義遺失。

## 六、重要語義保護檢查

### 1. Current State 與 Asset Governance State

候選文件明確保留兩者不同：

- Current State：描述特定時間、範圍、條件下的目前實況。
- P0.5 Asset Governance State：CURRENT / REVIEW / DEPRECATED / RETIRED / HISTORICAL / UNKNOWN。

判定：未發生 State vocabulary 混合。

### 2. 八種語義是否被錯誤固定化

候選文件明確稱其為「目前最小共同語義集合候選」，並保留未來案例可增加／修改的可能。

判定：未把八種類型宣稱為固定宇宙。

### 3. Claim 是否被錯誤物件化

候選文件保留 Claim 為語義物件，但沒有要求 Claim Database 或獨立 Claim File。

判定：通過。

### 4. 語義關係是否被錯誤升格為工程實作

候選文件明確禁止直接建立 Knowledge Graph、Relationship Engine、Database 等。

判定：通過。

### 5. 實際驗證成熟度是否被誇大

候選文件只保留「資料層級與分類」已有第一輪實際驗證，並明確保留其他案例仍待驗證。

判定：未把文件級蒸餾誤寫成實際能力驗證。
