## 三、關鍵判定

### 1. 正式 Namespace 不等於 CURRENT

20/20 文件都位於目前正式 0-知識 Namespace，但本批沒有任何文件僅因路徑而被判定為 P0.5 CURRENT。文件自身普遍標示待實際資料驗證、待實際任務驗證、待持續實測、建立中或待三方案實際建立後驗證。因此本批統一採 P0.5 State = REVIEW。

這不是否定內容，而是避免把「正式知識文件」與「已驗證、目前可直接作為工作依據」混為一談。

### 2. REVIEW 不代表應移出 0-知識

目前沒有證據支持把這批文件移入歷史或廢棄區。它們都有實質內容，並形成分類、管理、搜尋、比較、更新的原理鏈。因此目前 Disposition = KEEP，而不是 ARCHIVE、RETIRE 或 DELETE。

### 3. 沒有足夠證據進行 DISTILL / MERGE / SPLIT

這 20 份主要是原理文件，不是明顯的舊格式混合資料。目前沒有足夠證據要求 DISTILL、MERGE、SPLIT 或 DELETE，因此不為了「整理」而強行改寫。

### 4. 語義接近不等於重複

目前特別注意：分類原理／分類維度／分類與目錄；資料狀態與生命週期原理／資料狀態模型；搜尋原理／資料探索／搜尋拆分／搜尋擴展／資訊需求建立／查詢策略建立；知識比較原理／知識衝突判定；知識更新原理／目前狀態判定／版本與演化邊界。

目前證據顯示它們主要是互補責任，而不是完全重複，因此暫不 MERGE。

## 四、Canonical Source 判定限制

本批使用「候選正式知識來源」，沒有無條件宣稱所有文件都是全域 Canonical Source。Canonical Source 是某項語義的正式權威來源，不是所有正式目錄文件自動成為權威。

本批確認了文件的正式知識層身份與主要責任，但完整跨文件 Canonical Mapping 尚未完成。因此 Canonical Mapping = PARTIAL / REVIEW。

## 五、與 G2 Recall Boundary 的實際銜接

G2-08 已建立 CURRENT、RELEVANT EVIDENCE、HISTORY、RESEARCH、DEPRECATED / RETIRED、UNKNOWN / REVIEW 六個 Recall Boundary。本批將這套邏輯實際套入 0-知識：文件位於正式 Knowledge Namespace，不等於文件內容已達 CURRENT 使用狀態。

## 六、本批不修改文件本體

P0.5-03 的責任是判定資料，不是邊判定邊重寫資料。如果現在直接修改 20 份文件內部狀態，會混淆原始文件內部狀態、P0.5 外部判定與未來實際驗證結果。因此本批判定先保存在 Derived Audit。
