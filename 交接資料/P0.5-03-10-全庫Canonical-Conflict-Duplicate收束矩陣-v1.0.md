## 一、目的
本文件承接 P0.5-03 前序盤點，將目前已確認的跨目錄、跨版本高重疊知識資產整理成可交接的 Canonical / Conflict / Duplicate 判定矩陣。
本輪原則：不因檔名相似直接視為 Duplicate；不因版本較新直接視為 Canonical；不因內容部分重疊直接合併；KEEP 不等於 CURRENT；Mapping 是 Derived View，不取代原始知識文件；尚無充分證據時保留 REVIEW；不執行刪除、合併、改名或內容重製。

## 二、判定語義
| 類型 | 定義 |
|---|---|
| Canonical Candidate | 在目前證據下，較適合作為共同原理或主要語義來源，但尚未取得 CURRENT 授權 |
| Evolution | 同一核心問題的後續版本、修訂或深化 |
| Complementary | 責任或抽象層不同，可並存 |
| Duplicate Candidate | 實質語義、責任、輸出高度相同，若保留兩份會形成主要維護歧義 |
| Conflict | 對同一語義主張存在無法同時成立的差異，需要進一步決策 |
| Historical | 保留作為演化、否決或設計歷史證據 |
| REVIEW | 尚不足以進行最終處置 |

### 4. 分類

- 分類原理：分類判定。
- 分類與目錄：實體目錄落地。
- 核心資料類型與邊界：語義資料類型。

知識分類的責任較像管理層總結，因此目前不宣告 Duplicate、不宣告已被完全吸收，暫列 MEDIUM REVIEW。後續應與上述分類鏈做全文逐條對照。

### 5. System Catalog / Identity
目前判定：系統目錄與系統登錄原理 ≠ 系統穩定識別與引用原理。
前者負責管理、查找、登錄；後者負責穩定識別與引用。
判定：Complementary。優先級：LOW。不進行合併。

## 四、目前 Conflict 判定
本輪尚未發現足以宣告直接 Conflict 的核心知識對。
資料狀態群存在狀態集合與語義粒度不同：管理版包含草稿、待確認、已採用、歷史、廢棄；更新版包含待確認、已確認、建立中、歷史、已失效、已否決。
這目前較適合標記為 Semantic Divergence／模型粒度差異，而不是直接 Conflict。後續必須在三方案實際運作案例中判定哪些維度屬於共同 State、哪些其實屬於文件工作狀態、內容確認狀態或採用狀態。

## 五、目前 Duplicate 判定
本輪沒有任何資產達到可立即刪除／合併的證據門檻。
原因：多數高重疊文件存在不同責任層；版本差異可能保存重要演化資訊；尚缺三方案完整實際運作證據；檔案內容仍可能被後續 Canonical 蒸餾吸收。
因此本輪結論是：Duplicate Candidate ≠ Duplicate Confirmed；KEEP ≠ CURRENT；Evolution ≠ Redundant。
