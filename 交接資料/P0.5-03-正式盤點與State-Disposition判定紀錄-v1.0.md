## 三、正式判定欄位

每項資產至少需要：

| 欄位 | 判定 |
|---|---|
| Asset ID | 沿用 G1 暫時 ID，未正式註冊前不創造新的永久 ID |
| Source Path | Repository 原始路徑 |
| Identity | 它實際代表什麼 |
| Type | Knowledge / System / Solution / Evidence / Research / Test / Handoff / State / Template / History 等 |
| Version | Filename / Internal Version 分開記錄 |
| State | CURRENT / REVIEW / DEPRECATED / RETIRED / HISTORICAL / UNKNOWN |
| Canonical Source | 是否為該語義權威來源 |
| Current Counterpart | 是否有目前正式對應 |
| Conflict | 是否存在語意／狀態／版本衝突 |
| Duplicate | 是否為重複內容 |
| Valid Content | 是否仍有有效資訊 |
| Distillation Needed | 是否需要蒸餾 |
| Disposition | KEEP / UPDATE / DISTILL / MERGE / SPLIT / ARCHIVE / RETIRE / DELETE |
| Evidence | 判定依據 |
| Notes | 例外與限制 |

## 四、判定安全規則

1. 不因檔名較新直接判定 CURRENT。
2. 不因 Git Commit 較新直接判定 CURRENT。
3. 不因位於目前目錄直接判定 CURRENT。
4. 不因存在相似文件直接判定 Duplicate。
5. 不因版本不同直接判定 Conflict。
6. 不因舊文件已被部分取代就丟棄其中仍有效的內容。
7. UNKNOWN 不得被強制轉成 RETIRED 或 DELETE。
8. REVIEW 不得在未完成證據判定前進入一般 CURRENT Context。
9. Migration 不得早於 State / Disposition 判定。
10. 若證據不足，保留不確定性。

## 八、P0.5-03 與 P0.5-04 的分界

目前只完成「判定」。

若某資產被判定：

- DISTILL
- UPDATE
- MERGE
- SPLIT

才進入下一階段：

**P0.5-04 蒸餾與重製。**

不得在 P0.5-03 中順手改寫大量文件。

這樣可以避免：

> 判定尚未完成 → 邊判邊改 → 最後無法知道原始證據與處置理由。

## 十一、停止條件

遇到下列情況，不自行判定：

- 兩個候選 Canonical Source 無法區分
- 新舊規格 Scope 不明
- 同一內容存在不同責任但無法確認是否應 Split
- 研究內容可能已進入正式規格但沒有 Adoption Evidence
- 文件內部狀態與 CURRENT Authority 衝突
- 不知道是否仍有保存價值

處理：

**UNKNOWN / REVIEW + Evidence**

而不是猜測。
