## 二、全文比較結論

兩份文件高度同源。

共同核心包括：

- Trigger 是正常流程之外的第二層啟動保險。
- Trigger 命中不等於立即啟動。
- 必須先確認目標 System 的處理狀態。
- 已處理／執行中不得二次啟動。
- 必須防止 Re-entrancy。
- 必須防止 Trigger Loop。
- Multiple Match 不應直接全部啟動。
- 狀態不明時不得擴大啟動。
- Trigger 不應成為中央執行引擎。
- Trigger Registry 不保存完整業務邏輯。
- 必須透過自然工作案例驗證。

因此：

**不是兩套不同原理。**

## 三、無版本文件的實質新增

無版本文件不是單純複製 v1.0，而是對 v1.0 進行了內容深化。

主要新增：

### 1. 啟動保險的必要性說明

補充上下文遺漏、流程轉換、系統索引失效、判斷疏漏等實際漏啟動原因。

### 2. 冪等性（Idempotency）

明確把重複事件／重試問題獨立提出，並加入：

`Event ID + Trigger ID + System ID + 處理／啟動狀態`

作為最小去重判斷資訊。

### 3. 狀態模型細化

v1.0 只有「目前處理狀態」概念。

無版本文件進一步列出：

- 未啟動
- 啟動中
- 執行中
- 已處理／已完成
- 暫停／失效
- 狀態不明

並明確指出：

> 啟動保險只需要最小必要狀態，不應接管目標系統完整執行狀態。

### 4. 外部方法比較深化

無版本文件增加 Kubernetes Controller、事件至少一次傳遞／冪等性，以及 Backstage Catalog 的方法對照。

這些內容仍然是設計參考，不代表本 Repository 必須建立對應大型系統。

### 5. 禁止事項具體化

無版本文件增加：

- 不把 Trigger Registry 變成第一啟動源。
- 不因多重匹配全部啟動。
- 不以系統名稱或文件路徑取代 System ID。
- 不建立複雜規則引擎作為第一版前提。

因此無版本文件確實包含 v1.0 沒有的有效增量。
