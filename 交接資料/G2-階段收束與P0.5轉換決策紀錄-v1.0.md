## 五、與主系統資料基線重建規範的關係

基線重建規範本身沒有定義 G2-09。

它定義的是完整 P0.5 執行流程：

1. 規則確認
2. Repository 盤點
3. Inventory
4. Canonical Source 對照
5. CURRENT 候選確認
6. 蒸餾／重製
7. 舊資料分類
8. 移入歷史／備份
9. 建立 CURRENT Baseline
10. Recall / Context 驗證
11. Git Commit 固化

這是一條 P0.5 工程流程，不是一串 G2-01～G2-N 任務編號。

因此：

> G2 負責完成跨資料、State、Version、Canonical Source、Research Traceability 與 Recall Boundary 的基線辨識與審計。

而：

> P0.5 後續負責依既有規範實際完成資料判定、蒸餾、Migration、Baseline 建立與驗證。

兩者不可混為同一個編號系統。
