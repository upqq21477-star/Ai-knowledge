# P0.5-03 0-知識跨批次 Canonical / Conflict / Duplicate Review 第一輪

日期：2026-09-18
階段：P0.5-03

## 一、目的

本輪不執行刪除、合併或重製，只確認高重疊資產的語義關係，縮小後續 P0.5-04 的實際處理範圍。

## 二、主要判定

### 1. 變更影響分析

管理/變更影響分析最小原則 與 更新/變更影響分析與影響範圍 並非單純重複。

管理版偏共同最小語義：Identity、Relationship、Dependency、Usage、Version、Compatibility、Validation、Lifecycle、Data、History，以及 Impact Analysis 與 Change Decision 的分離。

更新版偏操作化流程：建立變更集、逐層追蹤影響、停止條件、輸出影響範圍。

暫定關係：
管理版＝共同原理候選
更新版＝更新場景應用／延伸候選

兩者 KEEP，不直接合併。

### 2. 資料狀態

管理/資料狀態與生命週期原理 與 更新/資料狀態模型 高度重疊，但目前仍可辨識為治理語義與更新模型兩個候選層次。

管理版：狀態、版本、時間分離，最小生命週期與治理責任。

更新版：更細的狀態模型，增加建立中、已確認、已失效、已否決，並處理 AI 輸出、搜尋與狀態轉換。

兩者狀態集合並不完全一致，因此不能現在宣告其中一個取代另一個。

P0.5-04 候選：高。

### 3. 觸發條件管理與啟動保險

v1.0 與無版本檔案具有高度相同核心模型：
Trigger 命中不等於立即啟動、確認處理狀態、防二次啟動、Re-entrancy、Trigger Loop、Multiple Match。

差異：
v1.0：待實際案例驗證。
無版本：已完成外部比對，待自然工作案例驗證。

暫定判定：
v1.0 → 演化／修訂 → 無版本候選。

目前不刪除 v1.0。P0.5-04 候選：高。

### 4. 知識分類與分類原理鏈

管理/知識分類 與 分類/分類原理、分類維度、分類與目錄、核心資料類型與邊界、資料層級與分類，不是簡單重複。

目前較合理的結構是：
分類維度＝描述角度
分類原理＝分類判定
分類與目錄＝實體目錄落地
核心資料類型與邊界＝語義資料類型
資料層級與分類＝資料、資訊、知識、來源、證據、文件、觀察、決策等關係

知識分類可能是管理層總結或較早版本，需後續確認是否已被分類原理鏈吸收。

P0.5-04 候選：中。

### 5. System Catalog 與 System Identity

系統目錄與系統登錄原理 與 系統穩定識別與引用原理 為不同責任。

前者回答如何管理、查找系統；後者回答如何穩定識別與引用系統。

屬互補，不合併。

## 三、暫定 Canonical Mapping

| 主題 | 共同原理候選 | 應用／延伸候選 |
|---|---|---|
| 變更影響 | 管理/變更影響分析最小原則 | 更新/變更影響分析與影響範圍 |
| 資料狀態 | 管理/資料狀態與生命週期原理 | 更新/資料狀態模型 |
| 觸發保險 | 無版本觸發保險原理 | v1.0 演化候選 |
| 分類 | 分類原理／分類維度 | 分類與目錄、核心資料類型、資料層級 |
| System Identity | 系統穩定識別與引用原理 | 系統目錄與系統登錄 |

以上都是 Mapping 候選，不代表已取得 CURRENT 授權。
