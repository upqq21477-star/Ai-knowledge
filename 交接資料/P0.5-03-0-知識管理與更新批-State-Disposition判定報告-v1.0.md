## 三、狀態判定規則

本批「0-知識/管理」與「0-知識/更新」是知識原理層，不因位於正式知識 Namespace 就直接判定為 CURRENT。

P0.5 State 採：
- REVIEW：內容具有實質知識價值，但尚未完成與整體 CURRENT Canonical Source 的最終關係判定。
- HISTORICAL：已有明確被後續版本／決策取代的證據。
- RETIRED：明確停止採用。
- UNKNOWN：證據不足以安全判定。
- CURRENT：已能確認其內容本身就是目前正式依據。

本批原則：沒有充分證據時，不升格 CURRENT，也不直接移出。

### 管理層重要發現

1. 多數文件內部仍明確標示「待實際驗證／候選／建立中」。這是 REVIEW 的直接證據，不能因文件已建立而升格 CURRENT。
2. 「觸發條件管理與啟動保險原理-v1.0.md」與「觸發條件管理與啟動保險原理.md」存在高度語義重疊，而且後者內容更接近自然工作驗證版本；但目前只足以標記「疑似演化／重疊候選」，不足以在本階段直接刪除或合併。
3. 「系統目錄與系統登錄原理」與「系統穩定識別與引用原理」高度相關，但前者描述 Catalog/Registry 整體，後者描述身份語義，屬可能上下層關係，不應直接視為重複。
4. 「共同資料契約」「共同資料最小描述」「共同關係模型」形成共同資料治理候選鏈，目前沒有證據需要拆成實體系統。
5. 「記憶定義與邊界」明確為建立中，不可當作完成的正式記憶規範。
