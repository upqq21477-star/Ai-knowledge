快照-005不是單獨宣稱自己是 CURRENT。

其形成依據包括：

1. 快照-003 已建立四方案模擬／回歸完成的狀態。
2. 快照-004 記錄第一次入口漂移問題解決與 8/8 回歸。
3. 後續問題處理發現第二次規則／版本漂移。
4. 快照-005 記錄第二次問題完成與 8/8 回歸。
5. README、說明、目前狀態、規則、待辦及交接-v2.9 均將工程游標指向快照-005。

因此目前沒有證據支持快照-001～004與快照-005並列為 CURRENT。

## 四、歷史快照的使用邊界

快照-001～004仍可用於：

- 還原當時工程狀態。
- 查找問題發現與修復原因。
- 驗證 CURRENT 為何從舊狀態演化而來。
- 作為工程決策與回歸證據。

但不應用於：

- 判斷目前工程游標。
- 覆蓋快照-005。
- 直接推導目前待辦。
- 直接建立新的正式功能。
