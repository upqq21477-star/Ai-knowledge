## 二、真正被後續版本吸收的問題

1. 三方案／四方案邊界逐步固定。
2. 「文件完成 ≠ 方案驗證 ≠ 實戰驗證」逐步固定。
3. 交接資料不再承擔完整歷史，而成為狀態恢復入口。
4. Git、工作檔案、待辦、交接的責任逐步分離。
5. FIELD 不人工製造，改為自然觸發。
6. CURRENT 工程游標固定為單一快照。
7. 無記憶交接入口漂移透過問題解決與回歸修正。

## 三、目前不能從歷史交接推導的內容

歷史交接不能直接證明目前所有能力都已 FIELD 驗證。

目前仍應以快照-005判定：
- 四方案模擬／回歸完成。
- FIELD 待自然觸發。
- 不重做四方案總驗收。
- 不建立第五方案。
- 不建立第二套 CURRENT 工程入口。

## 四、結論

v2.0～v2.8 已由後續版本承接，不能再作為 CURRENT 入口；v2.9 是目前交接背景與重大決策入口。

本文件只負責交接版本演化，不負責定義目前工程游標。
