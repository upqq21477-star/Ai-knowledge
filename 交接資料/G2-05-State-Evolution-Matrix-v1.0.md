## 一、核心判定
CURRENT 不是由單一文件憑空產生，而是由連續工程證據逐步形成。
但「形成 CURRENT 的歷史證據」與「CURRENT 本身」不是同一件事。

目前可建立的主鏈為：

`早期設計／規則` → `方案建立` → `完善／施工` → `模擬驗收` → `模擬回歸` → `無記憶交接回歸` → `快照-005 CURRENT` → `正常工程運作`

FIELD 尚未進入這條完成鏈，因為目前仍是 FIELD-PENDING。

目前明確包括：

- 快照-001～004

它們仍具有 Evidence Value。

## 七、不能直接 Archive 的內容
以下類型不能僅因過時就直接移除：

- 形成目前規則的歷史決策。
- 證明某次驗收曾經發生的文件。
- 說明為何 CURRENT 從舊狀態演化到新狀態的文件。
- 仍被 CURRENT 文件引用且尚未建立替代證據的文件。

因此 Archive 前仍需要逐項檢查 Reference Dependency。

## 八、G2-05 的重要結果
目前已經可以把 Repository 分成三個不同概念：

`CURRENT`：現在應該直接讀取的工程狀態。
`CURRENT SUPPORT`：幫助理解目前狀態，但不自行決定工程游標。
`HISTORY / EVIDENCE`：解釋目前狀態如何形成，不能反過來取代 CURRENT。

這比單純把舊資料全部搬進 Archive 更安全。

## 九、目前尚未解決的問題

這屬於 Reference Dependency / Retrieval Hygiene，不是 State Authority 問題。
